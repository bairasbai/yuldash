Задача не готова, пока здесь не зелено. Только реальные прогоны с выводом: не смог запустить —

## 1. Что изменилось

Возьми зафиксированную базу пакета. Для пакета поверх другой ветки это его исходный коммит. Отдели свои изменения от уже существовавших правок и укажи полный CI отдельной строкой.

```bash
git status --short
git diff --name-only "$package_base"                     # package_base — коммит базы пакета
git ls-files --others --exclude-standard                   # новые файлы
```

Разложи файлы по частям — запускай только нужные:

| Часть | Признак |
|---|---|
| Android | `android/**` |
| Бэкенд | `backend/**` |
| PWA | `webapp/**` |
| Лендинг | `web/**` |
| Проверка цепочек приёмки | `tools/audit_traceability/**` — `python -B tools/audit_traceability/run_tests.py`; это тесты инструмента |
| Только инструкции и документы (`AGENTS.md`, `CLAUDE.md`, Markdown в `docs/` и `.claude/`) | сборка не нужна: проверь diff, ссылки и лимит ядра 22 КБ; затем шаги 3–4. Изменённые скрипты/хуки проверяй по их назначению |

## 2. Проверки (как в `.github/workflows/ci.yml`)

**Android** — PowerShell:
```powershell
Set-Location "$(git rev-parse --show-toplevel)\android"
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"     # local.properties не нужен и не копируется
.\gradlew.bat :app:assembleDebug --no-daemon
.\gradlew.bat :app:compileDebugAndroidTestKotlin --no-daemon
.\gradlew.bat :app:testDebugUnitTest --no-daemon --tests "*GuardTest" --tests "<тесты затронутых экранов>"
```
- `*GuardTest` — ~30 сторожей правил, читают исходники и идут быстро: двуязычие (`Text`, `text =`,
  `contentDescription`, `Icon`/`Image`, `Toast`), шкалы `Canon*`, свой цвет `Color(0x…)` (`ColorSourceGuardTest`),
  храповик `padding(N.dp)` (`SpacingRatchetGuardTest`), контраст, тон «ты», тач-цели, деньги, приватность. Полный набор (3 600+ тестов Robolectric, долго,
  с порогом покрытия) гоняет CI; локально — сторожа и тесты затронутых экранов.
- `compileDebugAndroidTestKotlin` — инструментальные тесты (`androidTest`) не собирают ни `assembleDebug`,
  ни unit-прогон; CI компилирует их в `android-build` (с 13.10.2026), локально — чтобы не ждать CI.
- Трогал зависимости, правила R8/ProGuard, сериализацию или рефлексию — ещё
  `.\gradlew.bat :app:assembleRelease -Pyuldash.unsignedRelease --no-daemon` (как CI: проверка R8).
- Если Android Studio или другой процесс держит файлы сборки, согласуй освобождение ресурса по `docs/locks.md` и повтори полный обязательный прогон.
- Тестам нужна Java 21 (MapKit собран под неё; `jbr` Android Studio — 21).
- Видимое на экране — эмулятор обязательно (⭐ п.7 `AGENTS.md`; агент `yuldash-qa-verify`, стенд — `docs/qa.md`,
  «Локальный стенд»): открывается, «Назад» работает, есть загрузка / пусто / ошибка, светлая и тёмная тема ×
  русский и башкирский. Эмулятора нет — так и напиши в отчёте.

**Бэкенд** — из `backend/`:
```bash
ruff check app/ --select F
python -m pytest tests/ -q --maxfail=25
```
- Долго — сначала тесты затронутых модулей, потом весь набор. Весь набор в CI идёт с порогом
  покрытия: `--cov=app --cov-fail-under=85`.
- Трогал `alembic/` — `alembic heads` должен показать ровно одну голову.

**PWA** — `npm ci --prefix webapp` (если нет `webapp/node_modules`, в worktree его нет), затем
`npm run check --prefix webapp` и `npm run build --prefix webapp`.
**Лендинг** — `npm ci --prefix web` (если нет `node_modules`), затем `npm run lint --prefix web`
и `npm run build --prefix web`. В CI то же самое — джоба `web-build` (с 13.10.2026).

## 3. Правила проекта (не проверяются компилятором)

- Для нетривиального исправления или обслуживания проверь применимые критерии `docs/agent-workflow.md`: правки относятся к задаче, проверка отличает ошибочное поведение от правильного, ускорение подтверждено сопоставимыми замерами. Не добавляй ритуалы для мелкой обратимой правки; обязательные проверки выше сохраняются.

- При закрытии любого режима прочитай `/audit-traceability` и `docs/audit-traceability/README.md`.
  Укажи `--mode rideshare|taxi|courier` по задаче; для общей приёмки всех режимов — `--all`.
  Передай отдельно сверенный полный SHA базы и сохрани настоящий код выхода. У каждого режима свой
  обязательный состав; успех другого режима его не закрывает. Первоначальные манифесты ожидаемо возвращают 1:
  цепочки текущей версии ещё не связаны. Это не отменяет реальные тесты шага 2; зелёные self-tests
  инструмента не принимают приложение. Новому режиму сначала нужен явный состав. Статусы — только в `docs/audit-blocks.md`.
- Новые надписи — `appText(ru, ba)`; черновой башкирский — в `docs/tasks.md`, «Переводы на проверку».
- Новый экран — `enum Screen` (в `MainActivity.kt`) + ветка в `YuldashApp.kt` или `AppNav*.kt`
  (раздел «Навигация разрезана» в `docs/architecture.md`) + строка в `docs/architecture.md`.
- Второй мозг: решение → `docs/decisions.md`, грабли → `docs/lessons.md`, прогресс → `docs/tasks.md`.
- Меняли `.claude/hooks/` — `node .claude/hooks/yuldash-secrets-guard.test.mjs` зелёный.
- По спискам из шага 1 проверь, что правки пакета не затрагивают `mobile/`, файлы с ключами, реальные `.env` и сгенерированный `BuildConfig.java`. Проверяй только имена защищённых файлов. `git ls-files --others --exclude-standard` перечисляет неигнорируемые файлы.
- Проверяй разрешённые изменённые и новые исходники сканером `detect-secrets`. В отчёте укажи область проверки и результат без значений секретов.

## 4. Независимая приёмка (⭐ п.8 `AGENTS.md`)

- **Когда:** новый экран или функция, деньги, безопасность и личные данные, прод-база, правила агентов.
  Мелкую правку (текст, отступ, одна строка) — не гоняй: дорого и медленно.
- **Кто:** свежий агент сильнейшей модели — у Claude субагент `model: "opus"` (Opus 5.5), у Codex `gpt-6.1-sol`.
  Не автор плана и без его рассуждений — иначе это «проверил сам себя».
- **Бриф** (цель + ограничения + критерий, не пошаговый план): задача Александра дословно; что изменено
  (разница от базы пакета и новые файлы); вывод проверок шагов 2–3. Для правок только документации приложи результаты проверок из шага 1. Проверить против задачи,
  ⭐ «Готово» и §3, §4, §4.5, §8, §11 `AGENTS.md`; по умолчанию «не принято», пока реальные прогоны и чтение кода
  не докажут обратное. Вернуть: «принято / не принято» + находки P0/P1/P2 с `файл:строка` и как чинить.
- **Цикл:** находки → чинишь → приёмка заново, снова свежим агентом. Не сошлось за 2 круга — скажи Александру.
- **План до кода:** для списка «ждёт «да»» (§8) и новых подсистем независимый проверяющий сначала сверяет план. Итоговый результат принимает свежий агент по правилам выше.
