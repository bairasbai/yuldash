# Проверяемая приёмка попутки

Прочитай `docs/audit-rules.md` и [инструкцию](../../../docs/audit-traceability/README.md).
Текущие статусы — только `docs/audit-blocks.md`, пункт `W1-E2E-20261018`; состав —
`docs/audit-traceability/rideshare-scope.md`. Исторический PASS не принимает свежий коммит.

Из корня **своего** чекаута запускай:

```powershell
python -B tools/audit_traceability/check.py --baseline-ref <полный-SHA-отдельно-проверенной-базы>
```

База — неизменяемый локальный Git-коммит с `docs/audit-traceability/rideshare.json`,
сверенный принимающим отдельно от изменяемого JSON. Не выбирай новую базу для обхода сокращённых требований.
Кандидатные доказательства: `--manifest test-results/<своя-папка>/manifest.json`; JSON-отчёт: `--json`.
Пути артефактов — от корня чекаута. Код 0: формальные условия выполнены; 1: приёмка заблокирована;
2: неверный ввод/окружение. Возвращай реальный код, не скрывай его последующей печатью или `|| true`.

Первоначальный манифест честно возвращает 1: семь требований перенесены, реальные цепочки текущей версии
ещё не связаны. Это не доказательство поломки функций. Два телефона, внешние сервисы, проверка BA носителем
и согласованный выпуск остаются отдельными условиями. `accepted_with_skips` не равно полной приёмке.

Инструмент не запускает команды из JSON и не доказывает подлинность журнала/личности. Свежий принимающий
сверяет первичные журналы, реальные команды/коды завершения, окружение, происхождение сборки и охват зависимостей.
Не дописывай PASS и не меняй target старых протоколов ради зелёного результата. Итог и остатки запиши вручную
в существующий пункт реестра. Отчёт Александру: что подтверждено, что блокирует, какой следующий сценарий.

При изменении инструмента: `python -B tools/audit_traceability/run_tests.py`.
Это self-tests (проверки инструмента), не тесты попутки. Допуски ОС и остальные команды — в README выше.
