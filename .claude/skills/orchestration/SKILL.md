# Оркестрация: несколько агентов одновременно

**Зачем:** ускорить — пустить агентов параллельно.
**Главная опасность — конфликты.** Весь UI Юлдаша в одном файле `MainActivity.kt`. Если два агента правят его разом, последний затирает правки первого (уже ловили вживую: файл «уехал» на 350 строк за минуту, сборка краснеет, эмулятор уходит в ANR).

## 🥇 Золотое правило
**Один файл — один агент в один момент.** Параллелить можно только то, что НЕ пересекается по файлам и общим ресурсам (эмулятор, сборка).

> Это правило продублировано в §11 «Стоп-правила» файла `CLAUDE.md` — там оно всегда в контексте, даже если этот скилл не загружен.

## A. Зоны ответственности (lanes)
Делим проект на непересекающиеся зоны. Один агент = одна зона → их файлы не пересекаются → конфликтов нет.

| Зона | Файлы | Можно параллельно? |
|---|---|---|
| 🎨 **UI** | `android/.../MainActivity.kt` | да, но **только ОДИН UI-агент** |
| 🔌 Backend | `backend/` | да |
| 🖼 Ресурсы | `android/.../res/`, иконки, ассеты | да |
| 🧠 Мозг | `docs/` | да, но **один писатель на файл** |
| ⚙️ Конфиг/сборка | `*.gradle.kts`, `AndroidManifest.xml`, `local.properties` | **ни с кем** (влияет на всех) |

→ UI-зону держит **один** агент. Backend / ресурсы / доки можно вести параллельно с UI — это разные файлы.

## B. Общие ресурсы — строго по очереди
- **Эмулятор один.** `install` / `launch` / `screencap` / `uiautomator` / тапы делает **только UI-агент**. Два агента на одном эмуляторе = ANR и мусорные касания.
- **Сборка одна.** `gradlew assembleDebug` пишет в общий `app/build/` → две сборки разом ломают друг друга. Собирает один агент за раз.
- **Android Studio тоже участник очереди.** Открытая Студия на той же папке держит файлы сборки: прогон тестов падает с `FileSystemException: файл занят другим процессом`. Либо закрыть Студию, либо собирать с `-x bundleDebugClassesToRuntimeJar`.

## C. Правильная изоляция — git worktree
По-настоящему без конфликтов — когда у каждого агента своя копия репозитория (worktree): правки не пересекаются, в конце сводим (merge).
- **Предусловие:** проект — git-репозиторий. ✓ Сделано: ветка `main`, первый коммит, `.gitignore` без секретов (`local.properties`, `*.jks`, backend `.env`/`.db`/`.venv`) и без QA-артефактов. Worktree-изоляция доступна.
- Внутри одной сессии Claude Code: запускай субагентов с изоляцией `worktree` (инструменты Agent / Workflow). Каждый получает свою копию, лид сводит результат. Это **родной механизм Claude Code — предпочитай его «двум окнам вручную».**
- **Осторожно с деплой-скриптами.** `backend/deploy-backend.bat` копирует файлы из основного чекаута `C:\Users\Bayra\Yuldash\backend`, а НЕ из worktree. Работая в worktree, сначала слей ветку в основной чекаут — иначе выкатишь старый код.

## D. Если worktree пока нет (две сессии руками) — протокол «замок»
Минимум, чтобы не затирать:
1. В `docs/tasks.md` завести раздел **«🔒 Замки»**.
2. Перед работой агент пишет строку-замок: `🔒 MainActivity.kt — занят, <кто>, <время>`.
3. Другой агент видит замок → этот файл НЕ трогает, берёт свободную зону.
4. Закончил → снимает замок + пишет в «Ревью».
5. **Перед стартом всегда:** перечитать `tasks.md` (свежие замки) и перегрепнуть свой файл — если номера строк «уезжают», кто-то пишет параллельно, остановись.

## E. Роли
- **Лид (оркестратор):** режет задачу на непересекающиеся куски, раздаёт зоны, следит за замками, в конце сводит и собирает **один раз**. Сам в большой файл не лезет, пока заняты воркеры.
- **Воркеры:** строго своя зона, за границы не выходят, эмулятор не трогают без права, отчитываются лиду.

## F. Долгий план (чтобы параллелить стало легко)
`MainActivity.kt` слишком большой для параллели. Постепенно резать на файлы (`ui/screens/…`, `data/…`, `maps/…`) — тогда разные экраны = разные файлы = разные агенты без конфликтов. Резать по одному экрану за раз, не ломая сборку (см. §6 в `CLAUDE.md`).

## ⚡ Быстрый старт для Александра
Хочешь параллельно — давай каждой сессии **одну зону одной строкой**:
- Сессия 1: «только `MainActivity.kt` (UI), эмулятор твой».
- Сессия 2: «только `backend/`, эмулятор не трогай».
- Сессия 3: «только `docs/` и иконки».

Если зоны пересекаются хоть в одном файле — не запускай разом, делай по очереди.

## G. ruflo (MCP-оркестрация) — ВЫКЛЮЧЕН, и это правильно
- MCP-сервер `ruflo` (`mcp__ruflo__*`) — тяжёлый фреймворк координации/консенсуса/общей памяти между агентами.
- **Отключён 2026-08-03** при уборке: за 30 дней ни одного обращения. Понадобится — включается обратно через `/mcp enable ruflo`.
- **По умолчанию — НАТИВНЫЕ инструменты Claude Code:** `Agent` (сабагент, поддерживает `isolation: "worktree"`) и `Workflow` (детерминированный фан-аут). Они реально правят файлы и собирают. ruflo — слой поверх; для обычной работы по Юлдашу не нужен.
- **ruflo НЕ отменяет золотое правило.** Рой из 10 агентов в одном `MainActivity.kt` всё равно затирает сам себя. Топология роя не меняет физику: один файл — один писатель.

## H. Как реально ускорить разработку (приоритет сверху вниз)
1. **Резать `MainActivity.kt` на модули** (`ui/screens/…`, `ui/components/…`) — это РАЗБЛОКИРУЕТ весь параллелизм (разные экраны → разные файлы → разные агенты). Один экран за раз, сборка зелёная после каждого. Это главный рычаг — всё остальное вторично.
2. Пока файл цельный — параллелить только непересекающиеся зоны (UI ↔ `backend/` ↔ `docs/` ↔ `res/`), каждую своему сабагенту с `isolation: "worktree"`.
3. Лид сводит (merge) и собирает/тестит **один раз** в конце — сборка и эмулятор общие, их нельзя делить.
4. Тяжёлый ресёрч/аудит (не правка файлов) — в фоновые сабагенты, чтобы основной контекст был чистым.
