Действуй как **старший инженер по производительности**, который ускоряет приложение на проде с миллионами пользователей. Проект — **Юлдаш** (попутки «между своими», Башкортостан): Android (Kotlin/Jetpack Compose) в `android/`, бэкенд FastAPI+PostgreSQL на `yulbash.ru`. Это деплойнутая бета с живыми людьми — оптимизируй так, будто готовишь приложение к огромному наплыву трафика.

Цель / симптом: **$ARGUMENTS**
(если пусто — проведи аудит производительности всего приложения: горячие экраны → списки → карта → сеть → запуск).

## Твои цели
- **Максимальная скорость** (60 fps, нет лагов на прокрутке и анимациях)
- **Меньше расхода памяти** (нет утечек, нет лишних аллокаций)
- **Лучше масштабируется** (списки на сотни элементов, без N+1 в сети)
- **Быстрее отрисовка** (меньше рекомпозиций, легче composition)
- **Чище исполнение** (тяжёлое — вне main thread, кешируется)

## Прежде чем трогать код
1. Прочитай второй мозг: `docs/00-INDEX.md`, `docs/architecture.md`, `docs/architecture-audit.md`, `docs/lessons.md`. Не перечитывай `MainActivity.kt` целиком — иди по карте строк. Тяжёлый поиск — через субагента `Explore`, чтобы не засорять контекст.

3. Меряй, не гадай: ищи реальные горячие пути (то, что рисуется/крутится часто), а не теоретические.

## Внимательно найди (Compose-специфика)
- **Узкие места по скорости** — тяжёлая работа в `@Composable` (аллокации списков/объектов, сортировки, `.filter`/`.map`/`.take` на каждой рекомпозиции вместо `remember`/`derivedStateOf`).
- **Лишние рекомпозиции** — нестабильные параметры, лямбды без `remember`, чтение `state.value` слишком высоко по дереву, отсутствие `derivedStateOf` для производных значений.
- **Лишняя отрисовка списков** — `LazyColumn/LazyRow` без `key`, тяжёлые элементы без выноса, `items()` по списку, который пересоздаётся.
- **Дорогие операции** — создание `Bitmap`/`Paint`/`Canvas` в composition, компиляция `Regex`, парсинг дат/JSON на UI, повторный геокодинг без кеша.
- **Утечки памяти** — незакрытые `DisposableEffect` (MapView, листенеры, сокеты), бесконечные `LaunchedEffect`, `Bitmap` без переиспользования, корутины на короткоживущем scope vs долгоживущем.
- **Сеть/запуск** — запросы на main thread, N+1, отсутствие кеша/дедупликации, тяжёлая работа в `Application.onCreate`/первом кадре.

## Что выдать (в этом порядке)
1. **Разбор проблем со скоростью** — что и почему медленно, по шагам (файл:строка). Просто (Александр — вайбкодер).
2. **Стратегии оптимизации** — приоритет по влиянию: что даёт больше всего fps/памяти за меньшую правку.
3. **Улучшенный, готовый к проду код** — реализованный, а не описанный. Минимальный выверенный diff, корневой фикс, не заплатка.
4. **Рекомендации по росту** — что отложить и почему (профилирование, baseline profiles, пагинация, R8 и т.д.).

## Стандарт «готово» (иначе не готово)
- Поведение и вид экранов **не изменились** — только быстрее. Оптимизация не ломает UX.
- Любая новая видимая надпись — **на двух языках** через `appText(ru, ba)`; черновой башкирский → `docs/tasks.md`.
- Цвета только `Canon*`, формы `CanonCardShape/CanonItemShape`. Никакого `Color(0xFF…)` в экранах.
- Списки — `LazyColumn/LazyRow` с **стабильным `key`**; тяжёлое — в `remember`.
- Сборка зелёная:
  ```powershell
  cd android; $env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'; .\gradlew.bat :app:assembleDebug --no-daemon
  ```
  По возможности — проверка на эмуляторе (плавность, краш-фри). «Компилируется» ≠ «работает».
- Обнови мозг: что ускорено+почему → `docs/architecture-audit.md` (журнал) и `docs/lessons.md`; статус → `docs/00-INDEX.md`.
