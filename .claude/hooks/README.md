# Хуки Юлдаша (`.claude/hooks/`)

Хук — маленькая программа, которую Claude Code запускает сам: до команды агента (PreToolUse) или после
правки файла (PostToolUse). Подключены в `.claude/settings.json`. Работают только у Claude Code; у Codex
их нет — для него правила те же, но держатся на тексте `AGENTS.md`.

| Хук | Когда | Что делает |
|---|---|---|
| `yuldash-post-edit.mjs` | после правки файла | подсказывает: мёртвые импорты в `backend/app/` (ruff `--select F`, как CI), `Color(0x…)` и одноязычный `Text("…")` в новых строках экранов. Ничего не правит сам |
| `yuldash-secrets-guard.mjs` | до команды Bash / PowerShell | не даёт команде прочитать, скопировать, упаковать, сослаться, удалить или перезаписать файлы с ключами |
| `yuldash-secrets-guard.test.mjs` | вручную / в `/gotovo` | таблица «запретить / пропустить» для сторожа: `node .claude/hooks/yuldash-secrets-guard.test.mjs` |

Файлы с ключами: `local.properties` (ключ MapKit, Sentry DSN и др.), `google-services.json`,
`keystore.properties`, `*.jks`, `*.keystore`, сгенерированный `BuildConfig.java` (в нём ключ карты).

## Известные ограничения

**Сторож ключей — сетка от случайностей, а не стена.** Он читает текст команды и ищет в нём опасные
сочетания. Способов прочитать файл бесконечно много, поэтому всё предусмотреть по тексту нельзя — это
показали четыре круга независимой приёмки 13.10.2026: каждый находил новые обходы.

Что ловит (каждый случай — в таблице тестов):
- чтение, копирование, упаковку, ссылки, удаление и перезапись файла по имени или маске (`local*`, `*.properties`);
- PowerShell (`Get-Content`, `Copy-Item`, `Remove-Item`, блоки `if {…}`, `$c = …`), `bash -c` / `powershell -Command`;
- рекурсивный поиск и копирование папок, где лежат ключи; поиск в папке сборки;
- `rg` с `-u` / `--no-ignore` / `-g` по ключевым маскам; `git grep --untracked`, `git show`, `git add -f`, `git clean -x`;
- список файлов или имя файла, переданные по `|` в читателя; имя в переменной; перенаправления `<` и `>`.

Чего не ловит (примеры, не полный список): склейку имени из частей (`"local." + "properties"`), чтение
через самописный скрипт без имени файла в команде, хитрые переменные окружения, программы, которые сами
обходят папки.

**Где настоящая граница:**
1. Запрет `Read(//**/…)` в `.claude/settings.json` — инструменты Read/Grep и распознаваемые команды не видят файлы.
2. Классификатор Claude Code и подтверждения — подозрительную команду он останавливает или спрашивает.
3. **Главное — держать ключи вне досягаемости агента:** не в папке проекта и не в рабочих копиях, а в одном
   месте вне репозитория (переменная окружения или `~/.gradle/gradle.properties`) с запретом чтения этого пути.
   Тогда этот класс утечек исчезает целиком. Это отдельная задача (см. `docs/decisions.md`).

**Ложные тревоги.** Сторож осторожен и иногда запрещает безобидное (например, `grep -r` по корню проекта
или путь с `..`). Обход простой: искать инструментом Grep или `rg`, писать путь без `..`. Нашёл ложную тревогу
в обычной работе — добавь случай в таблицу тестов и поправь сторожа.
