## Следующий независимый прогон

Использовать отдельную QA-ветку, без PR для запуска и без продакшена. Пиновать фактически
запущенный продукт и тестовый стенд раздельно. Сначала подготовить синтетический API через loopback
и проверить, что Android/PWA не обращаются к боевым сервисам, а платёжная форма не создаёт реальных платежей.
Затем на API 34 и в браузере провести один общий заказ: пассажир начинает оплату, получает потерю ответа,
перезапускает приложение и открывает тот же чек; водитель видит согласованные итоги в браузере.
В отдельном варианте банк подтверждает отмену после открытия чека. Другую попытку нельзя считать
отменённой по старому статусу. Зафиксировать ID заказа, сумму, количество созданных счетов, шаги,
скриншоты и проверенный SHA. PostgreSQL и два физических телефона остаются отдельными воротами.
