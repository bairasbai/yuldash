# Проверяемая приёмка всех режимов

Общие правила действуют для попутки, такси и доставки; у каждого режима свой полный обязательный состав.
Инструмент связывает требование → исходный материал → реализацию → выполненную проверку → независимую
приёмку, сверяет связи и SHA256 (контрольные суммы). Текущие статусы — только в [реестре](../audit-blocks.md).
Успех одного режима не принимает другой; зелёные self-tests проверяют инструмент, а не приложение.

| Режим CLI | Аудит | Обязательные группы | Исходный состав |
|---|---|---|---|
| rideshare | W1-E2E-20261018 | 7 прежних, без изменения смысла | [Попутка](rideshare-scope.md) |
| taxi | TAXI-E2E-20261023 | 10, все подусловия обязательны | [Такси](taxi-scope.md) |
| courier | COURIER-E2E-20261023 | 10, все подусловия обязательны | [Доставка](courier-scope.md) |

Доставка включает отправителя, попутного перевозчика, профессионального курьера и получателя.
Старые B03/B04, PATH и QA-ID сохраняются в картах требований; новые машинные ID их не заменяют.
Общие правила применяются и к будущим режимам: сначала отдельный полный состав/профиль и его проверка.
Неизвестный `--mode` отклоняется, молчаливого выбора попутки для него нет.

## Запуск из корня проекта

Python 3.10+ и локальный Git с `--no-lazy-fetch` (без догрузки из сети), без установки библиотек.
Полный SHA **отдельно проверенного коммита** с исходными составами передаётся извне, не из кандидата.
После интеграции первоначального состава в main:

```powershell
$traceBase = git rev-parse main
python -B tools/audit_traceability/check.py --all --baseline-ref $traceBase
$traceExit = $LASTEXITCODE
if ($traceExit -ne 0) { exit $traceExit }
```

Принимающий отдельно сверяет SHA с утверждённым составом. Если база уже утверждалась раньше,
передай её полный SHA, а не автоматически свежий main. Команда без `--mode` сохраняет прежнее поведение
попутки; в новых заданиях указывай режим явно:

```powershell
python -B tools/audit_traceability/check.py --mode taxi --baseline-ref $traceBase
python -B tools/audit_traceability/check.py --mode courier --baseline-ref $traceBase
python -B tools/audit_traceability/check.py --mode rideshare --baseline-ref $traceBase
```

Каждая команда независима: при выполнении нескольких сохраняй код каждой, а не только последней.
Состав базы всегда читается из Git по фиксированному `docs/audit-traceability/<режим>.json`, а не из рабочей
копии/кандидата. В ветке внедрения общий исходный состав впервые доступен в коммите
`88d8f0bb9ed39596b360da5633cfeadb60c6e2b9`. Отсутствующий состав в выбранной базе — ошибка 2 без обхода.

Добавь `--json` для автоматики. Коды выхода:

| Код | Значение |
|---|---|
| 0 | Формальные условия выполнены; `accepted=false` означает согласованные необязательные пропуски |
| 1 | Приёмка заблокирована: неполная цепочка, неверные связи/хеши, другой коммит, изменённый состав/реализация |
| 2 | Неверный ввод/команда, недоступный локальный Git, отсутствующий/некорректный кандидат или база |

`--all` сохраняет отчёт и код **всех трёх** режимов. Любой 2 даёт общий 2; иначе любой 1 даёт общий 1.
Общий 0 возможен только при трёх нулях; `accepted=true` — только если все приняты без пропусков.
**Первоначальные манифесты должны дать 1:** это требования без выдуманных реализаций/прогонов/приёмок.
Ноль полных цепочек не означает ноль работающих функций; это отсутствие привязанных доказательств в этом формате.
Старые PASS не переназначаются текущему HEAD. Не скрывай отказ через `|| true`, `exit 0`,
`continue-on-error` или последнюю успешную печать отчёта.

## Кандидатные доказательства

Один режим:

```powershell
python -B tools/audit_traceability/check.py --mode taxi --manifest test-results/release/taxi.json --baseline-ref $traceBase
```

Все режимы — отдельная папка с **rideshare.json, taxi.json, courier.json**:

```powershell
python -B tools/audit_traceability/check.py --all --manifest-dir test-results/release --baseline-ref $traceBase
```

Отсутствующий файл пакета даёт 2 для этого режима, даже если штатный манифест существует.
Небезопасный путь отклоняется до чтения; смешивать `--all` с одиночным `--manifest` или
`--manifest-dir` с одиночным `--mode` нельзя. Папка кандидатов не меняет фиксированные пути Git-базы.

## Обновление доказательств

1. Найди режим и его существующие B02/B03/B04/PATH в реестре; сохрани постоянные ID и все обязательные
   подусловия. Число групп не доказывает полноту. Вспомогательные проверки не уменьшают основной состав.
2. Зафиксируй проверяемый код коммитом своей ветки. Полный SHA одинаков в `audit.target_commit`,
   реализациях, тестах и приёмке; он равен HEAD. Рабочие заявленные реализации совпадают с его деревом.
3. Выполни реальные проверки `/gotovo`; сохрани первичные журналы с командами, кодами завершения,
   временем, окружением и происхождением сборки. API не заменяет Android; эмулятор — физические устройства.
4. Свяжи требования/реализации/тесты/приёмку в кандидате. Пути артефактов — **от корня чекаута**,
   независимо от папки JSON; SHA256 — по фактическим байтам. Поля — [SCHEMA.md](../../tools/audit_traceability/vendor/SCHEMA.md)
   и [схема](../../tools/audit_traceability/vendor/schema/manifest.schema.json).
5. Свежий независимый принимающий проверяет исходные журналы, реальные команды/коды завершения,
   окружение, происхождение сборки, полноту зависимостей и независимость проверки. Разные ID людей/агентов
   сами по себе её не доказывают. Неизвестное остаётся непринятым. Общее доказательство связывается явно
   и принимается по применимости, а не автоматически переносится между режимами.
6. Проверь кандидатов с отдельно сверенной Git-базой и сохрани настоящие коды. После реальной приёмки
   вручную обнови существующий пункт единого реестра. Новый HEAD не принимается старым отчётом автоматически.

Исторические материалы не переписывай и SHA старых журналов не меняй. Совпадение отдельных файлов позволяет
изучить прежний результат, но не создаёт новый выполненный прогон. Ключи, реальные входы, телефоны и точные
координаты в доказательства/git не добавляются. Согласованный выпуск — отдельное разрешённое действие.
Правила оценок и денег различаются: повтор оценки такси обновляет запись; второй голос доставки запрещён,
при неизвестном результате сначала читается сервер. Нельзя переносить поведение одного режима в другой.

## Защита и граница доверия

- Git-база неизменяема, её полный SHA сверяет принимающий отдельно. Проверяются ID, тексты, обязательность,
  приоритеты и принадлежность; базовые семь требований попутки не изменены.
- До чтения запрещаются выход из корня, ключи/BuildConfig.java, mobile, .git, symlink и NTFS junction.
- Заявленные реализации — обычные tracked-файлы HEAD. Байты сравниваются с самим Git-объектом, даже при
  `assume-unchanged`; только для UTF-8 текста допускается разница LF/CRLF. SHA256 артефакта всегда точный.
  Исходный файл реализации ограничен 8 МиБ; APK подтверждается отдельным артефактом исполнения/происхождения.
- Команды и URL из JSON не исполняются. Сеть, выкладка и автоматическая смена статусов отсутствуют.

**Проверены декларации и байты, а не подлинность журнала/личности.** Поддельный журнал с пересчитанным
хешем и незаявленные зависимости выявляет независимая проверка. Не меняй файлы параллельно с проверкой:
сначала зафиксируй область/владельца по `docs/locks.md`.

## Проверка самого инструмента

```powershell
python -B tools/audit_traceability/run_tests.py
```

Исходные тесты и новые CLI-контракты трёх режимов используют синтетические данные с уборкой.
На Windows без права symlink два исходных теста и один проектный дают SKIP; реальная NTFS junction
проверяется отдельно. На Linux выполняются symlink-тесты, Windows junction там явно пропускается.
CI настроен на Linux и Windows; фактический удалённый прогон подтверждай отдельно. Его зелёный итог не принимает режимы.
Происхождение неизменного ядра — [UPSTREAM.md](../../tools/audit_traceability/UPSTREAM.md).
Claude Code: `/audit-traceability` и `/gotovo`; Codex — `AGENTS.md` §13. Инструкции действуют в чекауте,
где есть эти файлы; в основную рабочую папку попадают после разрешённого переноса в main.
