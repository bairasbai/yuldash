# Проверяемая приёмка попутки

Инструмент связывает требование → исходный материал → реализацию → выполненную проверку →
независимую приёмку. Он сверяет связи и SHA256 (контрольные суммы файлов), выявляет пропуски и
изменённые доказательства. Текущий статус продукта хранится только в [реестре](../audit-blocks.md).

## Запуск из корня проекта

Python 3.10+ и локальный Git с `--no-lazy-fetch` (без догрузки объектов из сети), без установки библиотек.
Полный SHA **отдельно проверенного коммита**
с исходным составом требований передаётся явно; не получай его из изменяемого манифеста.
После интеграции в main пример для текущего исходного состава:

```powershell
$traceBase = git rev-parse main
python -B tools/audit_traceability/check.py --baseline-ref $traceBase
$traceExit = $LASTEXITCODE
if ($traceExit -ne 0) { exit $traceExit }
```

Перед приёмкой принимающий отдельно сверяет выбранный полный SHA с утверждённым исходным составом.
Если есть ранее утверждённая база, передай именно её SHA, а не автоматически новый main.
В ветке первого внедрения main ещё не содержит этот файл: возьми полный SHA коммита этой ветки,
впервые добавившего `docs/audit-traceability/rideshare.json` (см. `git log --diff-filter=A -- docs/audit-traceability/rideshare.json`).
Отсутствие файла в выбранной базе — ошибка, автоматического обхода нет.

Для автоматизации добавь `--json`. Коды выхода:

| Код | Значение |
|---|---|
| 0 | Формальные условия выполнены; `accepted=false` отдельно означает согласованные необязательные пропуски |
| 1 | Приёмка заблокирована: нет полной цепочки, неверные связи/хеши, другой коммит, подмена состава или реализации |
| 2 | Команда/ввод/локальный Git недоступны или некорректны |

**Первоначальный манифест должен дать код 1.** В нём перенесены семь критериев, без выдуманных
реализаций/прогонов/приёмок. Ноль полных цепочек не означает ноль работающих функций.
Его target — база `a1394d58`; после изменения HEAD дополнительно виден другой коммит.
Исторические локальные PASS прежней ветки остаются историческими; к текущему main они здесь не привязаны.
Не превращай ожидаемый отказ в успех через `|| true`, `exit 0`, `continue-on-error` или печать отчёта последней командой.

## Обновление доказательств

1. Найди пункт `W1-E2E-20261018` в реестре и нужное требование [фиксированного состава](rideshare-scope.md).
   Сохрани ID и смысл; вспомогательные проверки не уменьшают семь обязательных требований.
2. Зафиксируй проверяемый код коммитом в своей ветке. Все `target_commit`/`commit` цепочки должны
   содержать этот полный SHA; рабочая реализация должна совпадать с HEAD. Команды из JSON не запускаются.
3. Выполни реальные проверки по `/gotovo`; сохрани первичные журналы с командами, кодами завершения,
   временем, окружением и привязкой сборки к коммиту. UI/телефон/провайдер подтверждаются своим видом доказательств.
   Серверный тест не заменяет Android; эмулятор не заменяет два телефона.
4. В отдельном кандидатном манифесте свяжи `requirements` с `implementations`, `tests` и `acceptances`.
   Артефакты имеют относительные POSIX-пути **от корня чекаута**, а не от папки JSON, и точные SHA256 байтов.
   Используй `--manifest test-results/<своя-папка>/manifest.json`; исходный состав оболочка всегда берёт
   из `docs/audit-traceability/rideshare.json` доверенного Git-коммита. Схема —
   [SCHEMA.md](../../tools/audit_traceability/vendor/SCHEMA.md), поля —
   [manifest.schema.json](../../tools/audit_traceability/vendor/schema/manifest.schema.json).
5. Свежий независимый принимающий открывает исходные журналы и проверяет реальный запуск, команду,
   код завершения, окружение, происхождение сборки, полный охват зависимостей и независимость проверки.
   Роли с разными ID сами по себе не доказывают независимость людей/агентов. Неизвестное остаётся непринятым.
6. Запусти оболочку с отдельно сверенной базой, передай её код выхода без подмены. После реальной приёмки
   вручную обнови соответствующий пункт единого реестра. Новый коммит требует сверки: сохранённый отчёт не принимает его автоматически.

Исторические материалы не переписывай и не меняй в них SHA на текущий. Совпадение отдельных файлов
позволяет принимающему изучить прежний результат, но не создаёт новый выполненный прогон в этой строгой схеме.
Результаты вне чекаута сначала сохраняются в допустимой папке доказательств без секретов; ключи,
реальные входы, телефоны и точные координаты в доказательства и git не добавляются.

## Что защищено и где граница

- База читается из неизменяемого Git-объекта по полному SHA и фиксированному пути. Подмена рабочего JSON не меняет базу.
- Все семь W1-критериев остаются `must`; ядро также сохраняет тексты, приоритеты, категории и принадлежность к функции.
- До чтения артефактов проверяются пути: нет выхода из корня, ключей, `mobile/`, `.git/`, symlink или NTFS junction.
- Для заявленных реализаций проверяются обычные tracked-файлы и отсутствие изменений против HEAD.
  Сравнение идёт с самим Git-объектом, даже если файл скрыт от `git diff` флагом `assume-unchanged`.
  Для UTF-8 текста допускается только разница LF/CRLF; SHA256 доказательства всегда сверяется с фактическими байтами.
  Исходный файл реализации ограничен 8 МиБ; сборка APK подтверждается отдельным артефактом исполнения/происхождения.
- Команды/ссылки из манифеста не выполняются и не открываются. Сети, выкладки и смены статусов инструмент не делает.

**Это проверка деклараций и байтов.** Поддельный журнал с пересчитанной суммой, выдуманная личность и
пропущенная зависимость требуют независимой проверки. `gate_passed=true` не выдаёт внешнего свидетельства
подлинности. Доверенный SHA базы выбирает принимающий вне изменяемого документа. Не запускай проверку
параллельно с изменением этих файлов; сначала зафиксируй область и владельца по `docs/locks.md`.

## Проверка самого инструмента

```powershell
python -B tools/audit_traceability/run_tests.py
```

Исходные тесты ядра и проектные тесты оболочки работают на синтетических данных с автоматической уборкой.
На Windows без права symlink два исходных теста и один проектный показываются как SKIP; реальная NTFS junction
проверяется отдельно. На Linux выполняются тесты symlink; Windows junction там явно пропускается.
Отдельный CI проверяет инструмент на Linux и Windows. Зелёный CI этих тестов **не означает приёмку попутки**.
Происхождение и неизменность ядра — [UPSTREAM.md](../../tools/audit_traceability/UPSTREAM.md).
Claude Code: `/audit-traceability`, также подключено к `/gotovo`; Codex читает общую ссылку в `AGENTS.md` §13.
Инструкции доступны в том чекауте/ветке, где есть эти файлы; другой чекаут получит их после переноса изменений.
