Аудит `TAXI-E2E-20261023`. Это требования, а не второй реестр статусов.
Текущие статусы остаются в [едином реестре](../audit-blocks.md), B03/B04 и соответствующих PATH.
Состав выделен из действующих материалов по поручению Александра 23.10.2026;
исторические QA/PATH/денежные ID сохраняются и не становятся новыми PASS.
Каждое подусловие ниже обязательно; число пунктов само по себе не доказывает полноту.

## TAXI-E2E-01 — Непрерывная поездка

Обязательное требование (`must`, `P1`): Пассажир и водитель проходят общую навигацию: адреса → актуальная цена → заказ → поиск → принятие → прибытие → посадка → завершение. Обе пары Android/PWA. Сохраняются маршрут, остановки, предзаказ и согласование нового адреса.

Источники при выделении состава: `docs/audit-blocks.md:55–56; docs/audit-role-journeys.md:41; docs/audit-main-recheck.md:18–19`. Прежние ID: **PATH-04/05, QA-B03-001/002, DELTA01/08**. Номера строк относятся к моменту составления; ищи также по ID и смыслу.

## TAXI-E2E-02 — Допуск и линия

Обязательное требование (`must`, `P1`): Заявка водителя → решение → документы/готовность → линия. Pending/rejected/verified, первая ошибка загрузки, поздние ответы и замена фото дают верный результат. Тяжёлая обработка изображений измерена.

Источники при выделении состава: `docs/audit-blocks.md:56,1105–1114`. Прежние ID: **PATH-05, DESIGN-044…049**. Номера строк относятся к моменту составления; ищи также по ID и смыслу.

## TAXI-E2E-03 — Отмена и переназначение

Обязательное требование (`must`, `P1`): Отмена обеих сторон, отсутствие машины, ожидание, отказ водителя и переназначение имеют верные конечные состояния. Повтор заказа сначала прекращает прежнюю очередь; неудачная отмена оставляет её видимой.

Источники при выделении состава: `docs/audit-blocks.md:104; docs/audit-role-journeys.md:41; docs/audit-live-services-recheck.md:26–39`. Прежние ID: **B03, PATH-04/05**. Номера строк относятся к моменту составления; ищи также по ID и смыслу.

## TAXI-E2E-04 — Расчёт без дублей

## TAXI-E2E-05 — Сеть и перезапуск

Обязательное требование (`must`, `P1`): Потеря сети/ответа, ручной повтор, перезагрузка и смерть процесса восстанавливают тот же заказ, стадию и точки. Ошибка чтения заказов не открывает новую форму; поздний геокодер не заменяет ручную точку.

Обязательное требование (`must`, `P0`): Два устройства пассажира создают один активный заказ; таксист не принимает два заказа. Совмещение с доставкой сохраняет существующую несимметричную политику, а не придуманную общую блокировку.

## TAXI-E2E-08 — Итог и следующая поездка

Обязательное требование (`must`, `P1`): Обе стороны через настоящую навигацию достигают своего итога, чека, оценки и следующего заказа. Ошибка или неготовый чек не выдумывают сумму. Оценка восстанавливается; повтор такси обновляет существующую запись, не запрещается по правилам доставки.
