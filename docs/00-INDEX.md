## 🔒 СТАТУС (2026-08-08) — аудит безопасности: закрыт угон доступа администратора

> Сквозной проход по всему коду (352 маршрута бэкенда, приложение, PWA, сборка, CI).
> **Критичная дыра:** селфи в заявке курьера принималось любой ссылкой, а экран модерации
> грузит приватные фото с ключом входа администратора в заголовке — то есть любой
> зарегистрированный человек забирал полный доступ владельца в три шага, просто дождавшись,
> когда Александр откроет очередь заявок. Закрыто **двумя стенами**: проверкой на сервере
> (как у водителя и таксиста) и запретом на клиенте отдавать ключ куда-либо, кроме нашего хоста.
>
> Ещё шесть находок: платный ключ геокодера зашивался в каждый APK (в коде не использовался —
> потому и не замечали); роль администратора выдавалась по последним 10 цифрам номера без кода
> страны; счётчик попыток кода входа обнулялся запросом нового кода; проверка документов
> спрашивала диск вместо хранилища и сломалась бы в день переезда в облако; неотправленные
> сообщения чата лежали на телефоне открытым текстом; исключение вебхука Telegram из лимитера
> стояло на несуществующем пути (и тест это повторял, оставаясь зелёным). Плюс подпись
> `integrity` для внешнего скрипта на публичной странице живой поездки.
>
> **Второй и третий проходы** шли по следу первой находки («проверку поставили не на все однотипные
> поля») и нашли ещё девять мест: модерация чата не видела расшифровку голосового (в такси и
> доставке номер достаточно было продиктовать), то же в заявке (расшифровка + имя близкого),
> имя получателя посылки и курьерского заказа в открытой ленте, комментарий расписания
> водителя (отдаётся вообще без входа, модерации не было ни строчки), витрина водителя
> открывалась по id ЛЮБОГО пользователя (перебор всей базы), секретная ссылка живой поездки
> уезжала в Sentry в адресе запроса, приём телеметрии без входа жил на общем лимите, витрина купонов публиковалась без единой проверки текста (по решению Александра включён СТРОГИЙ режим: правка видимого текста у одобренного бизнеса возвращает карточку на модерацию, помеченный купон в витрину не выпускается), поиск адреса не обрезал строку и клал её в ключ кеша.
>
> **Проверено:** бэкенд **2509 тестов зелёные** (+24 новых, по одному на находку),
> `assembleDebug` **BUILD SUCCESSFUL**, тесты приложения зелёные. Миграций нет, деплой обычный.
> **🔴 Александру:** сменить ключ Яндекс.Геокодера — старый лежал в розданных APK
> ([tasks.md](tasks.md), первый раздел). Разбор — [audit-security-2026-08-08.md](audit-security-2026-08-08.md).

### Карта и поездки (production-ready ядро):
- **Маршрут** — Яндекс DrivingRouter по дорогам, основной зелёный + до 2 объездных серым (`routesCount=3`); фоллбэк прямая при квоте/ошибке; камера фитит весь путь; ключ MapKit в `local.properties` (НЕ в git).
- **Live-стрелка попутчика** — нав-стрелка, едет по дороге, **плавно** (chaser 60fps, сглаживание адаптивно по плотности подачи + зуму), нос по `bearing`. WS `/ws/trip/{booking_id}/location` (реле; направленные ключи `-bid*2`/`-bid*2-1` → без self-эхо; перепроверка токена/статуса раз в 15 сообщений). Foreground `TripLocationService` шлёт GPS ~раз в 7с. **Приватность:** точное гео только в активной поездке. **Проверено код-тестом 2 WS-клиентов** (без 2 телефонов) — нашёл+починил баг self-эхо.
- **ETA** — общее «≈ … в пути» + **живой остаток** «≈ … осталось» (от позиции по маршруту, уменьшается).
- **Демо-симуляция** — кнопка «▶ Симуляция» (ТОЛЬКО `BuildConfig.DEBUG`): фейк-попутчик едет по дорожному маршруту, постоянная скорость по длине; посмотреть live-стрелку без 2 телефонов. В релизе кнопки нет.
- **Статус-вотчер активной поездки** — поллинг `/bookings/{id}/role` раз в **~12с** (на паузе в фоне, `repeatOnLifecycle`) → пассажир видит **live-баннер** «Водитель выехал / подъезжает» (бэк хранит `Booking.driver_phase`).
- **Авто-обновление пинов** — раз в **~25с** (пауза в фоне) **+ WS-пуш** `/ws/map`: при новой поездке/заявке/брони/отмене сервер шлёт «refresh» → клиент мгновенно перетягивает `/rides/near`+`/requests/near` (дебаунс 1.5с). Новые появляются сами, исполненные/уехавшие исчезают.
- **Фильтры «Ближайшие»** (чипы) — 6: Только женщины / Детское кресло / С животным / Багаж / Кондиционер / **Некурящий**. Те же в «Фильтры по умолчанию».

## Проект в двух словах

**Юлдаш** — приложение попуток «между своими» (Башкортостан: Баймаҡ, Сибай, Уфа). Двуязычное (русский + башкирский). Android — Kotlin + Jetpack Compose.

- **Рабочий код:** `android/` ← тут работаем.
- **Бэкенд:** FastAPI (`backend/`) на PostgreSQL, **развёрнут**: API `https://yulbash.ru` (см. [server.md](server.md)).
- **Лендинг скачивания:** `web/` (Next.js статик-экспорт), **LIVE на `https://yulbash.ru/`** (nginx: статика + fallback на API). Деплой/nginx — [server.md](server.md) «🚀 Деплой». Остатки (APK, реквизиты, METRIKA, проверка башкирского) — [tasks.md](tasks.md).
- **Приложение ПОДКЛЮЧЕНО к серверу:** вход (SMS→JWT→автологин), поездки, заявки, бронь, SOS, доверенные контакты, чат, активная поездка (share/статус), **рейтинги** (отзывы после поездки), **проверка водителя** (фото прав/авто→модерация), **премиум-предпочтения поездки** (животные/кресло/только женщины/багаж/кондиционер/курение), лента карты (`/feed`), ближайшие по маршруту+гео (`/rides/near`) — всё реально на сервере. Слой `data/ApiClient.kt`. Базовый URL — `BuildConfig.YULDASH_API_BASE_URL` (debug→`10.0.2.2:8000`, release→`yulbash.ru`). SMS — код готов (нужен буквенный отправитель sms.ru).
- **Не трогать:** `mobile/` (старый Flutter, заброшен).
