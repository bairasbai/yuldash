## Зависание помощника и числовые состояния TCP — 28.10.2026

- Перед и после каждого ожидания технического помощника сохраняй название этапа.
  Чтение ответа, `locator.count()` и закрытие контекста могут оставить ошибку только
  в памяти. Ограничивай ожидания; даже неудачное закрытие браузера должно позволить
  сохранить FAILED и передать ROOT точные зарегистрированные процессы для уборки.
  Истечение `Promise.race` не отменяет исходную операцию: меняющее данные действие
  не повторять автоматически, использовать таймаут самого вызова и проверять результат.
- После JSON-сериализации состояние TCP может быть числом: `Listen` = `2`.
  Сравнение только со строкой `Listen` пропускает слушающие порты. Проверяй оба
  представления и отдельно сохраняй клиентские сокеты; PID сверяй вместе с временем
  создания и командой. Старые доказательства не переписывай — дополняй новой явно
  датированной проверкой. Не выдавай нынешнее состояние за снимок прошлого времени.

## Растущая история тестового аккаунта — 28.10.2026

- Локальный тестовый аккаунт накапливает поездки. Если пункт или форма не найдены,
  сначала установи достижимость обычной прокруткой без нажатия и без изменения данных.
  Увеличивай ограничение только у нужного перехода; не ослабляй проверку владельца,
  единственной карточки, маршрута, цены и действия. Новый полный прогон получает новую

  бюджет max_price, у оценки stars. Ошибка диагностического запроса до UI не доказывает
  ошибку приложения. Пустые свои тестовые данные закрывай обычным UI, часы не сдвигай.

Замечание к старой версии могло быть уже исправлено; номер этапа сам по себе этого не доказывает. Сначала проверь существование пути и прямых ссылок в текущем кандидате. Конкретный блокировавший процесс не установлен. Для сверки брать завершённые строки нужного временного окна через shared reader; хешировать замороженный extract, а не меняющийся оригинал. После падения сохранить старый журнал, отдельно зарегистрировать перезапуск/новый журнал и новый RunID; не смешивать сброшенные счётчики разных proxy-процессов.

- Возобновление локального стенда: перед каждым новым UI-run и после него сохранять фактические timezone эмулятора, auto_time_zone и UTC относительно host. Для этого стенда браузер и ufaClock используют Asia/Yekaterinburg; после возобновления обнаружен GMT/auto_time_zone1, и новый synthetic ride получил время на5часов позже. Причина смены настройки не установлена. Исправлять только настройки часового пояса с записью прежних значений и финальным восстановлением; не менять UTC, depart_at или серверный30-минутный барьер. Разрыв source/binding/ownership и изменение времени — отдельные проверки; один proof не заменяет другие.

Использовать обычную ограниченную прокрутку к точному сообщению и один fresh in-bounds tap; не подменять его первой карточкой того же имени. ## История и холодный запуск: точность помощника — 25.10.2026

- Маршрут, цена, дата и статус принадлежат одной реальной карточке. В native XML связывай их
  по предкам узла и не переходи через scrollable-список; геометрическая близость и старое
  совпадение маршрута могут склеить две разные поездки. Перед единственным завершающим нажатием
  снова проверь текущий ID/active и используй координаты того же свежепроверенного элемента.
- Proxy GET200 означает полученный сетевой ответ, а не законченную клиентскую запись. Перед
  убийством процесса дождись фактического разобранного UI, затем независимо проверь собственную
  запись на диске. Не заменяй готовность задержкой. Если инструментальный тест перезапускает
  приложение, восстанови обычный вход/свою ссылку и свежее чтение до потери сети.
- `Outbox.count()==0` и `hasPending()==false` не доказывают пустую читаемую очередь: эти методы
  сворачивают ошибку чтения в0/false. Для такой проверки отдельно различай null и пустой список,
  не очищая очередь и не читая файлы ключей. Непроверенную очередь указывай открытым условием.
- Проверяя чистую функцию с подменёнными часами, сохраняй и `Date.now()`, и конструктор
  `new Date()`. Объект только с now ломает саму пробу; такие отказы не являются RED приложения
  или проверяемого условия. Для disabled-кнопок проверяй весь набор действий, включая класс
  Button без clickable; время сохранения проходит те же границы кадра, что маршрут/стадия.

## Windows: воспроизводимый локальный прогон — 24.10.2026

- Перед зависимым запуском проверяй `exit_code` предыдущего `exec_command`: ошибочный выход
  возвращается обычным результатом инструмента и сам не прерывает JS-обёртку. Неудачную
  подготовку нельзя скрывать постфактум; сохрани ошибку и повтори обязательный запуск с полными
  начальными проверками. Открытый пишущим процессом журнал читай с `FileShare.ReadWrite`,
  иначе `ReadAllText` может отказать, хотя `Get-Content` видит те же строки.
- В PowerShell маску файлов передавай `rg` через `-g '*.kt'` и путь к каталогу: встроенная маска в аргументе пути (`.../Home*.kt`) не раскрывается и даёт ошибку123. Не повторяй такой поиск с другими расширениями.
- После бронирования PWA может показать `/trip/<id>` со статусом pending; отмена неподтверждённой брони находится в «Поездки» → «Подробнее» → `/booking/<id>`. Проверяй точный ID перед действием и закрывай предложение установки через видимую кнопку «Позже»; не добавляй отсутствующую кнопку в тестовый DOM.
- Для каждого прогона используй собственные короткие `TEMP`/`TMP`, зарегистрированные в журнале задачи. Длинный путь ломал Java Pipe до тестов (`UnixDomainSockets.connect`, `Invalid argument: connect`); короткий путь восстановил Gradle. Не меняй глобальные настройки Windows. Свой TEMP также не даёт старой уборке pytest затронуть чужие временные базы.
- В PowerShell аргумент с точками и присваиванием передавай целиком в кавычках: `'-Pkotlin.compiler.execution.strategy=in-process'`. Вычисленный путь XML передавай отдельным аргументом после `--junitxml`; включай `$ErrorActionPreference='Stop'` в служебных сценариях.
- Сохраняй настоящий код дочернего процесса до печати хвоста журнала. Вывод обёртки — UTF-8: ошибка печати символа не должна превращать успешную проверку в отказ продукта.
- HTTPX-клиент изолированного loopback-стенда — с `trust_env=False`: на этой машине без этого `/health` возвращал пустой503 вне приложения, напрямую —200. Не путай это с отсутствием сети у приложения.
- Параметрам pytest с огромными значениями задавай короткие явные ID: Windows не принимает такой `PYTEST_CURRENT_TEST`. Сам большой вход и его проверки сохраняй.
- Тест списка должен гарантировать попадание собственных контрольных записей в выборку. Первая страница общей тестовой базы не доказывает исчезновение записи; не меняй ради теста пагинацию приложения.

## Пропущенное скрытие и потерянный ответ чата — 21.10.2026

Не подменяй этот сценарий старым WS-кадром после закрытого соединения: connection/session-ограждения его уже отбрасывают. Реальная проверка: сервер сохранил отправку, клиент не получил подтверждение, другой свой сеанс скрыл сообщение, исходный клиент получил историю без ещё неизвестного id и повторил тот же ключ. Проверяй одновременно отсутствие содержимого в ответе, снятие именно своей очереди/отрицательной строки, отсутствие повторной загрузки медиа и сохранность истории собеседника. Отдельно задержи исходный POST200 через наблюдаемую границу отсутствия: replay при этом вообще не вызывается.

Для фоновой очереди сначала покажи положительный id в истории, затем пропусти скрытие и верни content-free receipt при GET503: удаление одного отрицательного id недостаточно. Проверь неверный ключ/владельца/дробный id, другую неподтверждённую строку, возврат после POST, начавшегося в фоне, и новый голос после более ранней потери канала. Стабильный новый голос и пропущенное изменение во время старого POST — разные утверждения. Подписчиков браузерных событий в компонентном стенде храни множеством: два visibilitychange-обработчика не должны затирать друг друга.

Два «Повторить» в Android — разные действия. После принудительного GET503 сначала дождись устойчивой строки ошибки истории, затем заново найди нижнюю кнопку действия по свежей XML. Снимок до завершения GET не годится для координат: появившийся блок ошибки сдвигает кнопку. Само отсутствие второго POST не доказывает неверный тап: в этом проходе правильное accessibility-нажатие нижней кнопки сопровождалось новой ошибкой соединения до запроса. Различай выбор кнопки и отказ транспорта; подтверждай второй POST по тому же ключу и порядок в журнале: чужой DELETE(me) → успешный native GET → повтор POST. Внешний ASGI-отказ может не попасть во внутренний HTTP-журнал: не приписывай ему несуществующую запись wire, укажи управляемую границу и реальную ошибку на экране.

Классический UiAutomator-runner требует совместимые `android.test.RepetitiveTest`/`FlakyTest`, как старый помощник ввода. Проверяй не только `OK (1 test)`, но и отсутствие `Exception`/`FAILURES`: оборванный runner тоже может напечатать OK. Для jdb в Windows явно выбирай SocketAttach; вывод дочерней Java декодируй с защитой от ошибки кодировки, а отсоединение отладчика и снятие своего adb-forward выполняй в finally/atexit. Пустой XML после остановки VM отладчиком не доказывает поломку экрана.

Нельзя «лечить» этот HTTP-сбой ожиданием: у установленного OkHttp4.12 глубокая проверка HTTP/1 idle начинается после10с, поэтому короткий повтор и повтор спустя минуты не равны. RED эмулятора: EOF в `okhttp3...Http1ExchangeCodec`→`RealCall.execute`→`ApiClient.call`, не путать с отдельным системным `com.android.okhttp` чтений или ожидаемым отказом WS на стенде. Regression: полный503→server FIN без close-header→200мс→один явный same-key POST. Проверять новое соединение и число запросов, сохраняя запрет автоматического replay. Артефакт байткода включает SHA фактически используемого jar; это не предположение о другой версии библиотеки.

## Помощники локальной проверки чата — 21.10.2026

`browser_run_code_unsafe` принимает `filename` только внутри разрешённых корней инструмента: для этого компьютера — основной проект и его `.playwright-mcp/`; файл из `%TEMP%` будет отклонён до открытия страницы. До копирования одного помощника зарегистрируй владельца, точный путь, хэш и условие удаления вне этой копии. После проверки закрой только свои контексты, сверяй хэш и удали именно свой файл; не удаляй общие папки или браузер MCP.

Повторять разрешено чтение реестра, а не продуктовую операцию; окончательный код выхода проверяется по завершённой записи. После штатного завершения сервера/эмулятора дождись реального выхода и проверь PID/порты: фиксированные2–3секунды не доказывают уборку.

   Обход: `& $adb reverse tcp:8000 tcp:8000` и сборка с
   `$env:YULDASH_DEBUG_API_BASE_URL='http://localhost:8000'`. Незашифрованный HTTP в debug разрешён
   только для `10.0.2.2`, `localhost`, `127.0.0.1`, `::1`
   (`android/app/src/debug/res/xml/network_security_config.xml`) — любой другой адрес режется молча.
3. Стендовые машины такси «пропали» (`POST /instant/presence` → 200, а машин ноль) — антифрод отбросил
   «телепорт» быстрее 200 км/ч и заклинил. Перезапусти стендовый сервер; машина в скрипте должна
   кружить вокруг точки, а не ехать по прямой.
4. Карта: ключ MapKit лежит в одном месте — `android/local.properties` основной папки
   `C:\Users\Bayra\Yuldash`, копий не делаем (решение Александра: не мусорить). В worktree карта
   пустая — всё остальное проверяется там. Нужна именно карта — собери и проверь её из основной
   папки, когда твоя ветка туда влита, с `$env:YULDASH_DEBUG_API_BASE_URL='http://10.0.2.2:8000'`
   (иначе сборка возьмёт адрес сервера из `local.properties` основной папки — там может быть прод). Сам ключ агент не читает и не копирует (§11 `AGENTS.md`).

5. Потеря сети через `adb reverse --remove` не обрывает уже открытый HTTP keep-alive-туннель.
   Перед проверяемым нажатием дождись закрытия прежнего соединения (на стенде Uvicorn с его
   стандартным keep-alive5с — более5с) и сверь журнал настоящих запросов. Сам факт удаления
   перенаправления не доказывает отсутствие сети; незаметно успешный запрос нельзя записывать
   как offline-проверку.
6. Для настоящей загрузки фото на локальном стенде задай `MEDIA_BASE_URL` тем же локальным
   адресом, что `API_BASE` клиента. Файл, сохранённый локально с возвращённым адресом рабочего
   сайта, правильно отвергается проверкой своего сервера и отображается текстом; это ошибка
   настройки стенда, а не доказательство поломки клиентского отображения фото.
7. В PowerShell передавай `rg` каталог и `-g 'маска'`, а не путь с `*`: оболочка может
   не развернуть маску и поиск не прочитает нужные файлы.

## Клавиатура на экране с полем ввода (24.10.2026)

Экран с `imePadding()` / `WindowInsets.ime` включает `ResizeWindowForKeyboard()` — иначе на Android 15+ окно
сдвигается целиком поверх нашего отступа (двойной скачок, шапка под строкой состояния). Сторож —
`KeyboardResizeGuardTest`. Проверка на эмуляторе: касайся поля **у нижнего края** экрана — поле вверху окно не
сдвигает и поломку не покажет; проще всего поднять шрифт (`adb shell settings put system font_scale 1.3`, потом
вернуть `1.0`). Режим окна: `adb shell dumpsys window windows` → строка `sim={adjust=…}` у `MainActivity`
(`resize` — верно, `pan` — сдвигает). Заодно проверь, что кнопка формы достаётся прокруткой при открытой клавиатуре.

## Пути Windows и историческая приёмка — 28.10.2026

- Запрет `mobile` и `.git` проверяй без учёта регистра: `Mobile` на Windows ведёт
  в ту же папку. До чтения содержимого проверяй исходные и разрешённые абсолютные
  компоненты пути; запрет ключевых файлов сохраняется. Проверку запрета выполняй
  на строках и подставных объектах, защищённые файлы для теста не открывай.
- После `runpy` возвращённый словарь может отличаться от `function.__globals__`.
  Защита должна действовать в фактических функциях чтения и до Git blob lookup,
  а не только в копии словаря. Старые замороженные помощники не переписывай.
- `kind=acceptance` запрещён в `reviewed_artifact_ids` строгого проверяющего кода.
  Старый отчёт приёмки остаётся исторической справкой; нельзя ради прохождения
  сторожа переименовывать его в `source`. Если он необязателен для текущих связей,
  вынеси его в явные historical notes и создай новую версию пакета с пересчитанным
  составом. Старую версию и её ошибку сохрани. Обязательные доказательства не убирай.


## Проверка тестового окна с полем ввода — 29.10.2026

- Если Robolectric зацикливает измерение окна, сначала воспроизведи сбой в двух адресных тестах. Реальное окно приложения, исходные проверки и таймауты сохраняй; допустимый обход относится только к окну тестовой среды.
- Прямой вызов OnClick и продвижение кадров не доказывают создание окна: проверяй применение снимка состояния и обработку очереди Android по существующим примерам. После исправления сначала запусти падающие случаи, затем весь изменённый класс.
- Окончательные привязки исходников и полной проверки экрана формируй после зелёного изменённого класса, чтобы не выпускать несколько служебных версий из-за одной неисправной проверки. Не переименовывай прежние неудачные результаты в успешные.

- В установленном Compose у DpRect нет свойств width/height. Для проверок размеров используй right−left и bottom−top; перед компиляцией нового теста сверь API с уже собранным соседним тестом.
