## 🗺 Специфика Башкортостана — что закладываем в продукт

| Особенность | Что это значит для Юлдаша |
|---|---|
| **География**: Уфа ↔ Зауралье (Баймак, Сибай, Учалы, Белорецк) — 300–450 км, горные дороги через Урал | Поездка — событие дня, планируется заранее → нужны фильтр по дате, подписки на маршрут, регулярные рейсы |
| **Связь**: на трассах Зауралья реальные дыры покрытия (перевалы, лес) | Офлайн-устойчивость: ключевые данные поездки (код посадки, телефон, точка сбора) должны жить без сети; очередь отправки |
| **Зима до −35°**: остановка на трассе = угроза жизни | Зимняя безопасность: авто-чек «доехал?», маячок «я застрял», SOS-протокол трассы |
| **Главный сценарий села**: «в больницу в Уфу» (РКБ и др.), к детям, на рынок | Категория «в больницу» уже есть → усиливаем: подписка «кто едет в Уфу в четверг», обратная поездка |
| **Соседние центры притяжения**: Магнитогорск (для Баймака/Сибая ближе Уфы!), Оренбург, Миасс | Не ограничивать маршруты границей РБ; популярные направления включают соседние области |
| **Праздники**: Сабантуй (июнь), Ураза/Курбан-байрам, выпускные — пики поездок «в родное село» | Сезонные подсказки маршрутов, шаблон «еду на Сабантуй в …» |
| **Башкирский язык** — не перевод, а маркер «свой» | Топонимы на двух языках (Өфө/Уфа, Сибай, Баймаҡ), голосовая заявка понимает оба, тексты живые |
| **Сёла без адресов**: «у мечети», «у магазина», «у моста» | Точки сбора по ориентирам + сохранённые точки села (сообщество наполняет) |
| **Аудитория**: много 50+, вайбкод-простота, Telegram-центричность | Простой режим уже есть → добиваем: SMS/звонок-фолбэки, минимум шагов, крупно |
| **Оплата**: наличные и СБП-перевод «на доверии» | Не строить платёжный флоу поездки — фиксировать договорённость («500 ₽, наличными») в брони |

## 🌊 Волна 1 — «Дыры ядра» (без этого рост опасен) — 6 фич

Разрывы, которые бьют по доверию при первых же реальных пользователях.

### F1. Отмена и завершение поездки водителем ⭐ главный разрыв
- **Что**: `POST /rides/{id}/cancel` (владелец; каскад: все брони → cancelled, пассажирам push+уведомление, места/карта обновляются) и `POST /rides/{id}/complete` (все onboard/confirmed-брони → done). Кнопки в кабинете водителя.
- **Почему**: сейчас водитель со сломанной машиной НЕ МОЖЕТ снять поездку — она висит active, пассажиры ждут. Прямой удар по доверию.
- **РБ-угол**: зимой поломка = критично; быстрая отмена + пассажиры сразу видят «ближайшие альтернативы» (эндпоинт /rides/near уже есть).
- Ветка: `feat/ride-cancel-complete` · Зона: бэк+UI · Усилие: M

### F2. Подтверждение брони водителем (закрывает P1-9 аудита)
- **Что**: экран/секция «Заявки на мои поездки» у водителя (pending-брони) + кнопки «Подтвердить»/«Отклонить». API `confirm` на сервере уже есть; клиентский метод + UI.
- **Почему**: прямая бронь сейчас навсегда pending → телефон и точка встречи никогда не открываются.
- Ветка: `feat/driver-confirm-booking` · Зона: UI (+мелочь бэк: push пассажиру при confirm) · Усилие: M

### F3. Редактирование поездки и заявки
- **Что**: `PATCH /rides/{id}` (цена/время/места/комментарий — пока нет броней; с бронями — только цена вниз и комментарий + push пассажирам) и `PATCH /requests/{id}`. UI: «Изменить» в кабинете.
- **Почему**: опечатка в цене/времени сейчас неисправима (нельзя даже удалить).
- Ветка: `feat/edit-ride-request` · Зона: бэк+UI · Усилие: M

### F4. Фильтр по дате + «когда едем» в поиске
- **Что**: параметр `date`/`depart_from..depart_to` в `GET /rides` и `/rides/near`; чипы в UI: Сегодня / Завтра / Выходные / Дата.
- **Почему**: поездки в РБ планируют за 1–3 дня; лента «всё подряд» неюзабельна при росте.
- Ветка: `feat/date-filter` · Зона: бэк+UI · Усилие: S–M

### F5. Центр уведомлений с типами (заменяет плацебо-табы)
- **Что**: таблица `Notification` (user_id, type: booking/ride/system/message, title/body RU+BA-ключами, read_at) + записи при событиях (бронь создана/подтверждена/отменена, водитель выехал, поездка отменена, отклик пришёл, заявку приняли) + `GET /notifications` типизированный + пометка прочитанного. UI: реальные табы, непрочитанный бейдж, время.
- **Почему**: пропущенный push сейчас теряется навсегда; табы «Поездки/Система» — пустышки (аудит WP-8).
- **РБ-угол**: при дырах связи push часто не доходит — лента событий обязана быть источником истины.
- Ветка: `feat/notification-center` · Зона: бэк+UI · Усилие: L
- **Бонус внутри**: FCM переводим на data-payload (фикс аудита «тумблеры не работают в фоне») + deep-link по типу.

### F6. История поездок + отзыв отклика
- **Что**: `GET /driver/rides?status=all|done|cancelled` + вкладка «Архив» в кабинете (счётчики: рейсов сделано, пассажиров отвезено); `DELETE /responses/{id}` (водитель отзывает свой отклик, пока не принят).
- **Почему**: история = основа репутации и «стажа»; неотзываемый отклик — ловушка.
- Ветка: `feat/ride-history` · Зона: бэк+UI · Усилие: M

## 🌊 Волна 2 — «Доверие = продукт» (фишка «между своими») — 4 фичи

### F7. Текстовые отзывы о поездке + публичный профиль водителя ⭐ ядро доверия
- **Что**: `Rating.text` (опц., max 500) + модерация как у app-отзывов; экран «Профиль водителя» (открывается с карточки поездки): фото, стаж в Юлдаше, число поездок, средний рейтинг, последние отзывы, бейджи. `GET /drivers/{id}/public`.
- **Почему**: «садишься вслепую к цифре 4.8». Отзыв «довёз бабушку до подъезда» продаёт сильнее любого маркетинга.
- **РБ-угол**: в малых городах репутация = всё; отзывы на башкирском — сигнал «свой».
- Ветка: `feat/reviews-driver-profile` · Зона: бэк+UI · Усилие: L

### F8. Бейджи и «стаж своего»
- **Что**: вычисляемые бейджи в профиле/карточке: «Проверен» (есть), + «N поездок», «С нами с <месяц год>», «Отвечает быстро», «Земляк» (город совпадает). Без новых таблиц — агрегаты.
- Ветка: `feat/trust-badges` · Зона: бэк (агрегаты) + UI · Усилие: S–M

### F9. «Женщинам — водитель-женщина» доводка
- **Что**: у водителя пол в профиле (опц.), фильтр women_only показывает и водителей-женщин; бейдж. Чувствительная тема — только opt-in.
- Ветка: `feat/women-driver` · Зона: бэк+UI · Усилие: S

### F10. Фиксация договорённости об оплате в брони
- **Что**: поле «как платим» в брони (наличные / СБП-перевод / договоримся) + сумма — просто ЗАПИСЬ договорённости (не платёж!), видна обеим сторонам и в споре.
- **Почему**: 90% конфликтов попуток — «мы же договаривались о 400». Продукт-арбитр без движения денег (юр-модель не меняется).
- Ветка: `feat/payment-agreement` · Зона: бэк+UI · Усилие: S–M

## 🌊 Волна 3 — «Башкортостан-специфика» (то, чего нет у Яндекса/inDrive) — 5 фич

### F11. Офлайн-паспорт поездки ⭐ трасса без связи
- **Что**: при подтверждении брони клиент сохраняет локально (DataStore) «паспорт»: маршрут, время, водитель+телефон, код посадки, точка сбора, договорённость об оплате. Экран активной поездки поднимает его БЕЗ сети с плашкой «офлайн». Исходящие действия (сообщение, статус «сел») — в очередь с ретраем при появлении сети.
- **Почему**: перевал между Белорецком и Уфой — 100+ км без связи. Сейчас без сети пассажир не увидит даже номер водителя.
- Ветка: `feat/offline-trip-pass` · Зона: UI (+мелочь бэк) · Усилие: L

### F12. Зимний протокол безопасности
- **Что**: (1) авто-чек «доехал?»: через ETA+буфер после начала поездки, если статус не done — пуш обеим сторонам «всё в порядке?», нет ответа за 30 мин при активном шаринге → SMS доверенному; (2) кнопка «Я застрял / нужна помощь на трассе» в активной поездке — шлёт координаты доверенным и в ленту SOS-админа; (3) баннер «морозная ночь, проверь тепло/заряд» при поездке ночью зимой (по месяцу, без внешних API в v1).
- **РБ-угол**: это фича, о которой будут рассказывать. Прямое «между своими = заботимся».
- Ветка: `feat/winter-safety` · Зона: бэк+UI · Усилие: L

### F13. Подписка на маршрут («карауль поездку») ⭐ retention-двигатель
- **Что**: «Следить за маршрутом»: пара городов (+опц. дата/направление) → push+уведомление при появлении подходящей поездки/заявки. Таблица RouteWatch, проверка при создании Ride (хук в create_ride), анти-спам (1 пуш/маршрут/день, авто-протухание 14 дней).
- **Почему**: главный ответ на «поездок пока мало»: пользователь не уходит навсегда, а оставляет «сторожа» — и возвращается по пушу. Ключ к ретеншену ≥30%.
- **РБ-угол**: «Сообщи, когда кто-то поедет Сибай→Өфө в пятницу» — точный сценарий Зауралья.
- Ветка: `feat/route-watch` · Зона: бэк+UI · Усилие: M–L

### F14. Точки сбора по ориентирам села
- **Что**: справочник точек (город/село → «у мечети», «у Магнита», «автовокзал» + координаты), пополняется из реально выбранных pickup-точек; при создании поездки/заявки — выбор из подсказок вместо ручного тыка в карту. Названия RU+BA.
- **РБ-угол**: адресов в сёлах нет; «встретимся у мечети» — это и есть локальный язык навигации.
- Ветка: `feat/village-pickup-points` · Зона: бэк+UI · Усилие: M

### F15. Сезонные маршруты и праздники
- **Что**: серверный конфиг «событий» (Сабантуй по районам, Ураза/Курбан-байрам, 9 мая, выпускные): баннер на карте «Скоро Сабантуй в Баймаке — едешь? Опубликуй поездку», шаблон создания поездки с предзаполненным маршрутом, бейдж «на Сабантуй» на карточке.
- **Почему**: пики спроса = моменты взрывного роста установок; календарь делает Юлдаш «своим» культурно.
- Ветка: `feat/seasonal-events` · Зона: бэк-конфиг+UI · Усилие: M

## 🌊 Волна 4 — «Рост и удержание» — 4 фичи

### F16. Расшарить поездку наружу (viral loop)
- **Что**: «Поделиться» на карточке поездки → красивая ссылка yulbash.ru/r/{id} (веб-превью: маршрут/время/цена/имя + «Скачать Юлдаш»), шеринг в WhatsApp/Telegram-чаты сёл. Deep-link в приложение, если стоит.
- **Почему**: сейчас рост = сарафан в чатах WhatsApp — дать этому сарафану красивую машинку. Каждая поездка — рекламный носитель.
- Ветка: `feat/share-ride-link` · Зона: бэк (страница+OG) + web + UI · Усилие: M

### F17. «Постоянные маршруты» водителя (расписание)
- **Что**: у водителя видимый блок «езжу регулярно: Баймак→Уфа по пятницам» (из recurrence-серий + ручное) в профиле и поиске; пассажиры подписываются (связка с F13).
- Ветка: `feat/driver-schedule` · Зона: бэк+UI · Усилие: M

### F18. Экран «Мой Юлдаш» (личная статистика)
- **Что**: км проехано вместе, поездок, сэкономлено ₽ (vs такси-ориентир), CO₂, «звание» (Юлдаш/Аҡһаҡал дороги…). Шарится картинкой.
- **Почему**: эмоциональная привязка + бесплатный маркетинг скриншотами.
- Ветка: `feat/my-stats` · Зона: бэк-агрегаты+UI · Усилие: M

### F19. Приглашение водителей (со стороны спроса)
- **Что**: на пустой выдаче «Никто не едет? Позови знакомого водителя» → шеринг персональной ссылки; реферал уже есть — добавить водительский трек (бонус: бесплатный Boost за первого приглашённого водителя, который сделал рейс).
- Ветка: `feat/invite-drivers` · Зона: бэк+UI · Усилие: S–M

## 🌊 Волна 5 — «Монетизация+» (после роста аудитории) — 3 фичи

### F20. Кабинет рекламодателя-партнёра (обещан в ads-system.md)
- **Что**: партнёр видит свои объявления, показы/клики/CTR, срок; продление через СБП/ЮKassa. (Бэкенд-статистика уже есть — нужен UI-кабинет.)
- Ветка: `feat/advertiser-cabinet` · Зона: UI (+мелочь бэк) · Усилие: M

### F21. ЮKassa-автоподтверждение Boost (уйти от honor-system)
- **Что**: интеграция создана в аудит-ветке (create/fetch/webhook) — включить путь Boost через YooKassa при наличии ключей, поллинг статуса на клиенте (ON_RESUME), СБП-fallback остаётся.
- Ветка: `feat/boost-yookassa` · Зона: бэк+UI · Усилие: S–M

### F22. B2B «медцентр-партнёр» для больничных поездок
- **Что**: связка категории «в больницу» с партнёрами-медцентрами: карточка «приём + дорога»: клиника размещается → пациенты из районов видят «кто едет к этой клинике». Деликатно, без обещаний медуслуг.
- Ветка: `feat/medical-partner` · Зона: бэк+UI · Усилие: M–L

## 🎯 Рекомендуемый порядок реализации (мной, на ветках)

**Первая партия (готовлю сразу, бэкенд под тестами + UI с проверкой):**
1. **F1** отмена/завершение поездки — главный разрыв доверия
2. **F2** confirm водителем — разблокирует прямые брони (P1-9)
3. **F4** фильтр по дате — маленькая и сильная
4. **F13** подписка на маршрут — retention-двигатель

**Вторая партия (после твоей сборки первой):** F5 центр уведомлений, F7 отзывы+профиль, F3 редактирование, F6 история.
**Третья:** РБ-фишки F11/F12/F14, рост F16.

> Каждая фича: бэкенд с тестами (проверяю здесь) + UI (баланс+ревью, сборка твоя) + черновики
