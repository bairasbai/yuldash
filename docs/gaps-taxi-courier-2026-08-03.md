## 🟠 БАГИ — не пробелы, а поломки

### ✅ ПОЧИНЕНО в этой сессии: фото при вручении не сохранялось

`delivery_photo_url` был объявлен в модели, в схеме запроса и отдавался наружу — **и не
присваивался нигде** (`grep '\.delivery_photo_url\s*='` по `backend/` → пусто). Курьер снимал,
экран писал «Фото приложено ✓», сервер снимок выбрасывал. В споре «привёз битой» доказательства
не оказывалось.

Почему не поймали: единственный тест (`test_courier_gaps.py:191`) проверял только отклонение
**чужого** хоста и проходил бы при полностью отключённой записи. Добавлена проверка, что своё
фото **сохраняется**. Правка — `parcels.py`, ветка `delivered`, зеркало `pickup_photo_url`.

> **Урок (в `lessons.md`):** тест «плохое отвергается» без парного «хорошее сохраняется» — не тест.

### ⚠️ НЕ ТРОНУТО, нужно решение Александра: время выезда попутки уезжает на 5 часов

`CreateRideScreen.kt:365-368` шлёт `SimpleDateFormat("yyyy-MM-dd'T'HH:mm:ss")` **без `timeZone`** —
локальное настенное время уходит как наивный ISO, сервер кладёт его в `Ride.depart_at` как наивный
**UTC** и фильтрует лентой по `utcnow()` (`rides.py:231`). Поездка «на 10:00» висит в выдаче до
~17:00 по Уфе; «доехал?» в `BookingActiveTripScreen.kt:1831` (`parseIsoUtcMillis`) срабатывает
на 5 часов позже. Показ времени — нарезка строки (`MainActivity.kt:576`), поэтому **визуально
ошибки не видно**. Тот же баг в заявке пассажира (`AccessibilityScreens.kt:729-732`).

Такси-предзаказ сделан **правильно** (`InstantOrderScreen.kt:2003 isoFromMillis` → `OffsetDateTime`).
То есть в одном проекте два разных подхода к времени.

**Почему не чиню молча:** все существующие поездки в проде записаны по старому соглашению.
Починка клиента разведёт старые и новые записи — нужна миграция или разовый пересчёт
`depart_at` для будущих поездок. Это решение по данным, а не правка экрана.

### ⚠️ Двойное создание посылки / заказа курьера

У такси серверный гард есть (`instant.py:254-262`: row-lock + проверка активного заказа).
У доставки — нет: `parcels.py:366-441` и `courier.py:710-800` делают `session.add()` без дедупа
и без idempotency-key. Защита только клиентская (`ParcelsScreen.kt:1577 enabled = !working`).
Лаг сети + ретрай → две посылки.

## 🧱 Инфраструктурное

- **`create_all()` на каждом старте в проде** (`db.py:78-88`): на пустой БД схема родится мимо
  alembic, `alembic_version` останется пустым без `stamp`. Лечится отключением для прод-ENV.
- **Alembic — одна голова**, проверено полным обходом `down_revision`: `x_promo_taxi_ride`.
  Единственный merge (`merge_20260720.py`) сошёлся.
- **Версионирование API — заготовка**: роутеры висят и на корне, и на `/api/v1` (`main.py:110-112`),
  но версия одна и клиент ходит на корень. Первое ломающее изменение придётся катить форс-апдейтом.
- `versionCode=2` при `versionName="1.0.0"` — выровнять до публикации.
