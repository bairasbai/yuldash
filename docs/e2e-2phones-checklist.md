# 📱 E2E-чеклист на 2 телефона — 10 минут (Александр)

> Главный оставшийся гейт качества. Ядро (live-трекинг поездки + FCM-пуш) НИКОГДА не проверялось на реальных устройствах — только в коде/эмуляторе. Пройди по шагам с 2 телефонами → отметь галочки. Что не так — пиши агенту с шага.

## Подготовка
- [ ] 2 телефона (Android), на обоих установлен свежий APK (debug или release).
- [ ] Интернет на обоих.
- [ ] Телефон **A** и Телефон **B**. Дальше по ролям.

## 1. Вход (обе стороны)
- [ ] A: вошёл через Telegram (код из бота) → попал на карту.
- [ ] B: вошёл через Telegram (другой аккаунт) → попал на карту.
- ✅ PASS: оба на главном экране «Карта», без крашей.

## 2. Поездка: A публикует, B бронирует
- [ ] A: «Создать поездку» → маршрут (напр. Баймак→Сибай), время, места, цена → опубликовал.
- [ ] B: на карте/в «Ближайшие» видит поездку A → открывает → «Забронировать».
- [ ] A: получил **пуш** «Новая бронь» (даже если приложение свёрнуто) ← **проверка FCM #1**.
- ✅ PASS: бронь создалась, у B появилась «Моя поездка», A получил пуш.

## 3. Активная поездка — LIVE-трекинг (главное!)
- [ ] Оба открыли экран активной поездки.
- [ ] A (или пусть A реально едет/идёт с телефоном): **B видит стрелку A, которая ДВИЖЕТСЯ по дороге, плавно**.
- [ ] У B «≈ … осталось» (ETA) **уменьшается** по мере движения.
- [ ] A: в шторке уведомлений висит **«Юлдаш — поездка идёт / Показываем вашу позицию попутчику»** (foreground-сервис).
- ✅ PASS: стрелка едет плавно, ETA живой, уведомление висит. ← **это НИКОГДА не тестили на 2 устройствах, самый важный шаг.**

> Без второго живого телефона частично проверяется кнопкой «▶ Симуляция» (только в debug-сборке) — фейк-попутчик едет по маршруту. Но настоящий тест — 2 телефона.

## 4. Двуязычие уведомления (свежий фикс)
- [ ] B (или A): переключи язык на **башкирский** (профиль/настройки).
- [ ] Снова зайди в активную поездку → уведомление сервиса теперь **«Юлдаш — сәфәр бара / Урынығыҙҙы юлдашығыҙға күрһәтәбеҙ»**.
- ✅ PASS: уведомление сменило язык на башкирский (это чинили в этой сессии).

## 5. Чат
- [ ] A пишет сообщение → [ ] B получает (в диалоге + **пуш**, если свёрнуто) ← **проверка FCM #2**.
- [ ] B отвечает → A получает.
- ✅ PASS: сообщения ходят в обе стороны, пуш приходит.

## 6. Код посадки
- [ ] B видит свой код посадки; A видит тот же код (сверка «та самая машина»).
- ✅ PASS: коды совпадают.

## 7. SOS
- [ ] B: кнопка SOS → открывается экран экстренной связи, гео показывается, кнопки 112/поделиться работают (звонить не обязательно).
- ✅ PASS: SOS открывается, гео есть, не крашится.

## 8. Завершение
- [ ] Заверши поездку (сел/доехал/завершить).
- [ ] Уведомление foreground-сервиса **исчезло** (стрим гео остановился).
- ✅ PASS: поездка закрылась, уведомление ушло.

## Итог
- Всё зелёное → **ядро подтверждено на реальных устройствах**, можно к релизу/продвижению.
- Что-то красное → запиши шаг + что увидел (скрин/текст) → агент починит. Логи прода: `ssh root@85.239.52.55 "journalctl -u yuldash-api -f"`.

Самое критичное — **шаг 3 (live-стрелка) и шаги 2/5 (FCM-пуш)**: именно они не проверены end-to-end.
