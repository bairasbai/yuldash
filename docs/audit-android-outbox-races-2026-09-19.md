## Подтверждённые ошибки

1. Во время отправки сообщения 1 добавлялось сообщение 2. Ответ на сообщение 1 приводил к записи старого пустого остатка: сообщение 2 исчезало без отправки.
2. Во время первого HTTP-запроса очередь очищалась и заполнялась заново. Прежний flush продолжал отправлять свой старый остаток и затирал новую очередь.

Его не считаем новой найденной ошибкой. Доказательства — `C:\Users\Bayra\Yuldash\test-results\android-outbox-races-red-20260919.log/.xml`.

Тесты используют настоящий Outbox/ApiClient и MockWebServer, удерживающий первый ответ до выполнения конкурирующего действия через CountDownLatch. Случайные задержки для воспроизведения не используются. Запросы направлены только локальному тестовому серверу.

## Исправление

- После HTTP удаляется только обработанный id из заново прочитанной очереди. Новые сообщения сохраняются.
- Добавление, очистка, замена хранилища и изменение текущего списка используют один короткий монитор. Во время сети монитор не удерживается.
- Очистка и initStores меняют поколение очереди. Запрос старого поколения не продолжает отправку остатка и не переписывает новую очередь.
- API получает поколение исходной сессии до сетевого ожидания. Это защищает промежуток между выбором действия и началом HTTP от смены аккаунта.
- Три UI-вызова enqueue передают поколение сессии, захваченное до первоначальной попытки отправки. Поздняя ошибка старого запроса не должна добавлять его действие в новый аккаунт.

## Границы

Уже ушедший на сервер запрос нельзя отозвать локальной очисткой. Проверяется остановка последующего остатка и защита локальной очереди, а не отмена уже принятого сервером сообщения. Доставка ровно один раз при потерянном ответе/ошибке удаления, классификация временных HTTP-ошибок и надёжность миграции хранилищ остаются отдельными задачами. Полный интерфейс всех ролей и настоящие внешние сервисы не объявляются проверенными.
