# 📦 План профиля «Курьер» для Юлдаша (перед реализацией) — 2026-07

> Документ для согласования ДО кода. Задача: воспроизвести бизнес-логику **Яндекс Курьера / Яндекс Доставки**,
> адаптировав под принципы Юлдаша. Основа — ресёрч офиц. справки Яндекс Про + разборы (2025–2026).
> Аналог такси-профиля, но для доставки вещей. Цифры Яндекса — московские, для РБ берём как порядок величины.

---

## 0. 🕊 Красные линии (каждый элемент проходит проверку по ним)

1. **«Между своими».** Курьер — это чаще всего сосед/попутчик, который и так едет в райцентр, а не безликий конвейер. Доверие = продукт.
2. **Попутка (людей) остаётся бесплатной.** Платим только за доставку вещи, не за место в машине.
3. **Зарабатываем на услуге, не грабя.** Честная предсказуемая цена, **без динамического суржа**. Комиссия платформы — прозрачная (наш козырь против Яндекса, где % непрозрачен).
4. **Приватность по минимуму.** Телефон/точная гео раскрываются только когда нужно (после принятия заказа), не всем подряд.
5. **Честно и прозрачно.** Никакого мелкого шрифта: видно, кто платит, сколько, за что, и сколько берём мы.
6. **Двуязычие RU/BA везде** — статусы, кнопки, СМС/пуш, список запрещённого. Черновой башкирский → `docs/tasks.md` на проверку Александру.
7. **Главная зона — село ↔ райцентр.** Не «экспресс за час по городу», а «кто сегодня едет в город — довезёт».
8. **Безопасность.** Запрещённые вложения — жёсткий список. Ответственность за утрату — честная модель (объявленная ценность + рейтинг), без обещаний, которых не выполним.

## 1. 🧱 Что уже есть (переиспользуем — не пишем заново)

- **Архитектура такси** (машина состояний InstantOrder, presence/матчер по гео+рейтингу, зоны город/межгород/направление, приём/отклонение оффера, гейты) — **курьер строится по этому же лекалу**. Это главный рычаг: 70% каркаса уже отлажено и покрыто тестами (197 зелёных).
- **M3 «Посылки»** (PR #66) — лёгкая C2C-доставка «между своими»: отправитель создаёт заявку → попутный водитель берёт → везёт → **код вручения в приложении** (без СМС-шлюза) → доставлено, символический сбор. **Это фундамент курьер-профиля** — курьер-профиль его расширяет (см. §12).
- **Проверки водителя Уровень 1** (PR #60): селфи с документом + справка + «кто пригласил» (реф-цепочка доверия). **Переиспользуем для проверки курьера** — не изобретаем.
- **Гео-справочник** (`Settlement`, зоны, направления село↔райцентр, пресеты маршрутов) — курьер выбирает зону так же, как таксист.
- **Реферальная система + анти-фрод** (B8) — «кто пригласил курьера», честный подсчёт активных.
- **Кабинет/модерация, биллинг «на доверии» по СБП, Telegram-подтверждения** (F20/M1) — тот же механизм для комиссии курьера.

**Вывод:** курьер-профиль — это НЕ новый продукт с нуля, а **новая роль поверх существующего каркаса** (такси + посылки + проверки + зоны).

## 2. 🎯 Главное решение: какая модель роли (РЕШИТЬ ПЕРВЫМ)

Как человек «занимается курьерской доставкой»? Три варианта:

- **(A) Совмещённая** — любой водитель, едущий по маршруту, берёт посылку «по пути». Это ровно сегодняшний M3. Просто, но это не «профессия».
- **(B) Отдельная роль курьера** — человек выходит «на линию курьером» (как таксист), получает офферы на доставку независимо от того, везёт ли он пассажиров. Полноценная профессия.
- **(C) ⭐ Гибрид (рекомендую)** — есть **оба входа**: (1) «по пути» — попутчик видит посылки на своём маршруте и берёт (лёгкий M3); (2) «режим Курьер» — тот, кто хочет заниматься доставкой профессионально, включает роль, выбирает зону, получает офферы. Одна роль-переключатель внутри Юлдаша (Попутка / Такси / **Курьер**), один аккаунт.

**Почему (C):** сохраняет нашу фишку (доставка едет вместе с попутками село↔райцентр) И даёт профессию тем, кто хочет возить регулярно — ровно как просил Александр «как такси». Не плодим приложения, добавляем режим в существующий переключатель.

## 3. 🪪 Онбординг курьера (облегчённый — «между своими»)

Берём у Яндекса каркас, режем бюрократию:

| Яндекс | Юлдаш |
|---|---|
| Самозанятость обязательна | **На старте не требуем.** Возишь регулярно за деньги → оформишь позже. Для села жёсткое оформление = отпугнуть. |
| Отдельное приложение (Яндекс Про) | Режим «Курьер» внутри Юлдаша, один аккаунт |
| Тренинг + тест | Короткое согласие с правилами (что везём/не везём) при входе в режим |
| Проверка СБ | **Уровень 1 (уже есть):** селфи с паспортом + «кто пригласил» + бейдж «Проверен». Мягче Яндекса, но доверие есть. |
| Медкнижка (для еды) | Еду на старте не возим → не нужна. (Заложим флаг на будущее.) |
| Типы: пеший/вело/авто/грузовой | **Упрощаем до 2:** «Легковой» (обычные посылки) и «Грузовой/Газель» (мебель, крупное). Пеший/вело в селе почти не нужен. |

Экран «Стать курьером Юлдаша»: правила (комиссия прозрачно, запрещённое, ответственность), выбор транспорта, согласие. Состояния: подал / на проверке / одобрен / отклонён (как у таксиста).

## 4. 🚚 Типы доставки (адаптируем сегменты Яндекса)

1. **«По пути»** (C2C-лайт, = M3) — отправитель кидает заявку на маршрут, попутчик берёт. Дёшево, «между своими».
2. **«Заказать курьера»** (C2C-про) — отправителю нужен адресный забор→вручение, система ищет курьера на линии (как такси-заказ, но везём вещь).
3. **⭐ «Купи и привези»** (наш киллер-фича для села) — «съезди в город, купи лекарство/товар в аптеке/магазине, привези мне». Курьер тратит свои → получатель возвращает деньги + плату за услугу. Этого у Яндекса нет как отдельного продукта, а на селе это боль №1.
4. **«Грузовой»** (позже) — мебель/переезд, отдельный тариф.

По каждому типу: габарит/вес-намёк (как в M3 — small/medium/large), список запрещённого, дисклеймер.

---

## 5. 🔄 Жизненный цикл заказа (упрощаем 12 статусов Яндекса до 7)

Полная модель Яндекса (`new→estimating→…→delivered_finish` + ветки) избыточна. Наш минимум:

`создан → ищем курьера → назначен → забрал (код А) → в пути → прибыл к получателю → вручил (код Б)`
+ ветки: `отменён`, `возврат` (получатель не отвечает), `курьер не найден`.

**Подтверждение — код в приложении, НЕ СМС** (у нас уже так в M3): отправитель называет курьеру **код забора** при передаче, получатель называет **код вручения** при получении. Бесплатно, надёжно, СМС-шлюз не нужен (СМС — опционально позже). Двуязычный текст.

**Таблица «кто что видит»** (по образцу Яндекса, упрощённо):

| Статус | Отправитель | Курьер | Получатель |
|---|---|---|---|
| Создан | адреса, габарит, цена | — | — |
| Ищем курьера | «ищем…» | оффер: маршрут, оплата | — |
| Назначен | имя, рейтинг, ETA, **телефон открыт** | адрес забора, **телефон отправителя открыт** | уведомление |
| Забрал (код А) | — | вводит код забора | «в пути», ETA, трекинг |
| В пути | трекинг | навигация к Б | трекинг |
| Прибыл | — | «прибыл», звонит | «курьер на месте» |
| Вручил (код Б) | «доставлено» | вводит код вручения | называет код |
| Завершён | чек, оценка | оплата начислена | оценка |

Приватность: телефоны раскрываются **только после «назначен»** (до этого скрыты) — наш принцип §0.4.

## 6. 💰 Ценообразование (честно, предсказуемо, БЕЗ суржа)

Из чего цена (берём у Яндекса, убираем сурж):
- **Расстояние** А→Б (главное для село↔райцентр).
- **Габарит/вес** (small/medium/large — как в M3).
- **Срочность:** «по пути / в ближайший рейс» (дёшево) vs «нужен курьер сейчас» (дороже). Без «экспресс за час» — не наша зона.
- Опции: крупногабарит, хрупкое.
- **НЕТ динамического суржа** (§0.3) — цена стабильная и понятная заранее.

Цена считается **на сервере** (клиенту не верим, как в такси). Тарифы — в конфиге, правятся без пересборки (как `PARTNER_PLANS`/`AD_PACKAGES`). Минималка — небольшая.

---

## 7. 💸 Деньги (кто кому и сколько — «на доверии», прозрачно)

- **Кто платит:** отправитель (по умолчанию), как у Яндекса.
- **Наш доход:** маленькая **прозрачная комиссия** с доставки. Механизм — как комиссия такси (лесенка/фикс) ИЛИ подписка-фри на старте. На старте по СБП «на доверии» + Telegram-подтверждение (уже есть).
- **⭐ «Купи и привези» / наложенный платёж:** курьер берёт у получателя деньги (за товар + услугу). Модель **«на доверии»** с **объявленной суммой** и **потолком** (напр. до 5000 ₽ на старте) — чтобы риск «деньги на руках у соседа» был ограничен. Наличкой/СБП напрямую; платформа не держит деньги (как везде у нас сейчас).
- **Ответственность за утерю/порчу:** модель **Достависты** — **объявленная ценность**: отправитель указывает ценность, при споре она — ориентир; без объявления отвечает курьер по договорённости. Полноценной страховки (как Яндекс до 250–500 тыс.) на старте нет — честно пишем это, не обещаем.
- Чаевые/бонусы/гарантия за час/слоты — **откладываем** (это конвейер, не наша фаза).

## 8. 🗺 Зоны и логистика (переиспользуем такси-зоны)

- Курьер выбирает зону так же, как таксист: **🏙 мой город / 🛣 межгород + направление / 🌍 соседний регион**.
- **Пресеты маршрутов** село↔райцентр (уже есть: Сибай–Магнитогорск и др.) — курьер «на линии по направлению Акъяр→Сибай» видит посылки по пути.
- **Мультизаказ** (несколько посылок за рейс) — заложим структуру, механику батчинга — во 2-ю очередь.
- Слоты/плановые смены Яндекса — **не берём** (нет конвейера); вместо них — «еду тогда-то, возьму посылку».

---

## 9. ⭐ Рейтинг / качество / санкции (мягче Яндекса — у нас соседи)

- **Рейтинг курьера** — взаимные оценки после доставки (переиспользуем `Rating`/`Report`). Отзывы + история важнее цифры.
- **Лестница наказаний — мягкая** (как в такси-качестве): низкий рейтинг → реже офферы; тяжёлые жалобы (кража/подмена) → пауза + разбор человеком. **Без жёстких −7/блок на 30 мин** как у Яндекса — это конвейерная механика.
- Отмены/опоздания — учитываем, но по-соседски, с правом объяснения.

---

## 10. 🛡 Безопасность и приватность

- **Проверка курьера** — Уровень 1 (селфи + «кто пригласил» + бейдж). Мягко, но есть.
- **Запрещённые вложения** — жёсткий двуязычный список (оружие, наркотики, деньги без объявления, скоропорт без упаковки, животные, документы на предъявителя). Обязательное согласие при создании (как в M3 `rules_accepted`).
- **Приватность телефонов:** на старте — телефон раскрывается только после «назначен» (как такси/M3). **Подменные номера** (звонок через приложение, реальный скрыт) — как у Яндекса — **позже** (нужен телефонный провайдер/PBX, стоит денег).
- **Фото посылки** — опция для спорных ситуаций (позже).
- Телефоны/координаты не логируем.

---

## 11. ⏱ Отмены / ожидание / недозвон (упрощаем)

- **Отмена отправителем** — бесплатно **до «назначен»/до приезда курьера к нему** (как такси-отмена); позже — по-соседски.
- **Недозвон** — по образцу Яндекса: подождать, позвонить, потом «Возврат» (везёт обратно). Упрощённо.
- **Платное ожидание 3 ₽/мин** — **не берём** (лишняя бюрократия «между своими»); максимум — вежливый лимит без денег.

## 12. 🔗 Как это соотносится с M3 «Посылки»

- **M3 «Посылки»** = вход №1 «по пути» (лёгкий C2C). Он **остаётся** и становится частью курьер-профиля.
- **Курьер-профиль** = надстройка: добавляет **роль курьера** (онбординг, режим «на линии», офферы, зоны), **«заказать курьера»** (адресный забор→вручение), **«купи и привези»**, тарифы/комиссию, рейтинг курьера.
- Технически: расширяем модель `ParcelDelivery` (тип доставки, объявленная ценность, наложка) + добавляем `CourierApplication`/`CourierProfile` (по образцу `TaxiApplication`) + режим в переключателе. Миграции — линейной цепочкой поверх M3.

## 13. 🛠 Технический план по фазам (стек, как волна такси)

Каждая фаза = ветка + pytest зелёный + баланс скобок + draft PR. Строим поверх M3 (посылки) и такси-каркаса.

### C1 — Роль курьера + «заказать курьера» (ядро)
- **Модели:** `CourierApplication` (по образцу `TaxiApplication`: транспорт, статус, «кто пригласил»), `CourierProfile` (зона, на линии, класс легковой/грузовой). Расширить `ParcelDelivery`: `delivery_type` (по_пути / курьер / купи_и_привези), `declared_value_kop`, `cod_amount_kop` (наложка), `commission_kop`.
- **Онбординг** курьера (переиспользовать driver-check L1) + гейт «курьер включён/город/одобрен».
- **Режим «на линии курьером»** + офферы на доставку (переиспользовать presence/матчер такси по зоне/маршруту).
- **Цена на сервере** (расстояние+габарит+срочность, конфиг-тарифы, без суржа).
- UI: экран «Стать курьером», переключатель +«Курьер», лента офферов, экран доставки курьера (забрал/в пути/вручил по коду).
- Миграция `courier_c1`. Тесты pos+neg (гейты, приватность, коды, IDOR).

### C2 — «Купи и привези» + наложенный платёж
- Тип `купи_и_привези`: список покупок, объявленная сумма товара, потолок, возврат денег получателем. Наложка «на доверии» с потолком.
- Ответственность: объявленная ценность (модель Достависты).
- UI: создание «купи и привези», экран курьера «купить по списку», расчёт с получателем.
- Тесты: потолок наложки, отказ получателя, спор по ценности.

### C3 — Комиссия/биллинг курьера + рейтинг/качество
- Комиссия платформы (прозрачно, «на доверии» по СБП + Telegram-подтверждение) или подписка-фри на старте.
- Рейтинг курьера (взаимные оценки), мягкая лестница (переиспользовать quality).
- Statement дохода в кабинете (как у партнёра M1).

### C4 — Полиш и масштаб (позже)
- Мультизаказ (несколько посылок за рейс), подменные номера (PBX), СМС-код (шлюз), фото посылки, грузовой тариф, слоты (если понадобится).
