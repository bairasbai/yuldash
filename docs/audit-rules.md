# Правила ведения аудита (к `AGENTS.md` §13)

> Вынесено из `AGENTS.md` §13 при ужатии правил 12.10.2026 — текст правил не менялся, добавлена одна фраза: реестр искать поиском. Читать перед любой работой по аудиту.

Единый реестр аудита — правило от 20.09.2026.

- Актуальный порядок и состояния проверок ведём только в `docs/audit-blocks.md`; состав файлов и контрольные суммы — `docs/audit-code-inventory.json`. Исторические отчёты являются доказательствами, а не независимыми списками текущих задач.
- Перед продолжением аудита прочитай реестр и проверь изменения инвентаризации. Выбирай первый незакрытый пункт с учётом доступности окружения; отсутствие доступа к устройству/провайдеру отмечай явно, продолжая независимые локальные пункты. Реестр большой — нужный пункт ищи поиском, а не чтением целиком.
- Один блок/файл в момент работы имеет одного ответственного. Субагенту передаётся конкретный пункт, файлы, критерий результата и запрет выхода за область; не поручать нескольким агентам повторное исследование или переписывание одного материала.
- Не создавать очередной общий отчёт на каждое «продолжай». Обновляй пункт реестра: идентификатор, версия/хэши, доказательства, результат, остатки. Отдельный артефакт нужен только для нового воспроизведения или полезного журнала проверки.
- Повтор теста обосновывается изменением файла/зависимости/окружения, новым сбоем или итоговой интеграцией. Запиши причину. Не складывай повторные прогоны в число уникальных проверок; не повторяй неизменённый полный набор для каждого небольшого исправления.
- Инвентаризация, чтение файла, успешная сборка и выполнение тестов — разные виды доказательств. Не помечай блок полностью проверенным без выполнения его критериев. Изменение файла снимает актуальность соответствующего доказательства, но не стирает исторический результат.
- Для W1-E2E используй [проверку цепочек доказательств](audit-traceability/README.md): семь обязательных критериев,
  неизменяемая Git-база, текущие файлы, реальные журналы и независимая приёмка. Манифест хранит связи,
  а не второй статусный реестр. Успех формальной проверки и тестов инструмента не доказывает работу приложения.
