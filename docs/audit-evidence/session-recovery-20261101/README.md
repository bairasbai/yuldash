Серверная защита повторного платежа уже существовала и не переписана: после потерянного
ответа сохраняются одна строка Payment и ключ `yuldash-payment-{id}`. Новый тест использует
подменённого провайдера: первый вызов создаёт фиктивный счёт и теряет ответ; второй возвращает
тот же счёт; третий клиентский POST использует pending без нового создания у провайдера.
Это проверка поведения на синтетической SQLite, не доказательство реальных списаний или
одновременных PostgreSQL-транзакций.

При проверке кандидата восстановления обнаружилась отдельная ошибка времени жизни
состояния Compose: старый и новый обработчики после повторной проверки получили разные
busy и вызвали оплату дважды. Существующие stage/method/busy/paymentId перенесены выше
раннего выхода внутри прежнего key владельца/заказа. Это исправление кандидата,
не утверждение о двойном списании на исходной версии.

Публичный кеш способов входа не содержит личных данных. Существующие защиты поколением
сессии и проверки владельца сохранены; их отсутствие не заявляется. Серверная одноразовость
кодов, проверки доступных методов и жёсткий запрет онлайн-оплаты брони не ослаблены.

На текущем head единственное подключение PayOnlineCard в production находится в чеке
такси (`TaxiReceiptScreen.kt:832`); прежнее назначение общего компонента не считается
доказательством проверки всех режимов. В текущем чеке попутки онлайн-карточка отсутствует,
а серверный запрет `booking_online_pay_off` проверен отдельно и сохранён.

## Окружение и ограничения

- Java Temurin 21.0.13+9 и Android SDK установлены отдельно для проверки; версии Kotlin,
  Compose, AGP, Gradle и SDK в проекте не менялись.
- Из-за ограничений облачной среды команды с дочерними процессами и TestClient выполнялись
  с разрешённым выходом из sandbox. TLS не отключался: Java использовала системное
  хранилище доверенных сертификатов. Robolectric JAR получены из Maven Central
  и сверены с опубликованными SHA-512; runtime использовал offline dependency directory.
- Эмулятора и /dev/kvm нет. Матрица RU/BA × светлая/тёмная тема на устройстве не выполнена.
  Три новые башкирские строки записаны как черновики в «Переводы на проверку» docs/tasks.md.
- Локальный PostgreSQL/Docker отсутствуют. Проверки, требующие настоящих PostgreSQL
  блокировок, не подменяются SQLite-результатом.
- Реальные платежи, списания, личные данные пользователей, настоящий SMS/Telegram,
  рабочий сервер и выкладка не использовались.
- GitHub PR №213 по-прежнему конфликтует с main и не имеет workflow runs/check runs/statuses
  на проверенном head. Отсутствие проверок не означает зелёный результат.

Сверка GitHub — github-state.json; исходники и журналы привязаны хэшами в snapshot.json.
Независимые приёмки записаны с областью и ограничениями; готовность всего PR/режима
к слиянию или выпуску не заявляется.
