## План и граница

Два изолированных endpoint-теста подтверждают несовместимость снимка при изменении промежуточных точек. Сырые диагностические логи остаются в приватном стенде; регрессионные тесты используют только синтетические локальные запросы; публикация не заявляет проверку эксплуатации production.

Узкое исправление: добавить упорядоченные координаты остановок в taxi freeze identity; передавать один и тот же валидированный набор из estimate/create. Названия остановок не влияют на цену. Ввести новую версию namespace taxi, не читать старые неполные ключи. Это намеренно делает старые двухминутные записи неприменимыми после будущей выкладки; нужен отдельный release review, а не молчаливое обещание сохранения старого cache.

Сохраняются: действующие ставки, минимальная из старой/новой цены, TTL, существующее округление начальной/конечной точки, категории/опции/round-trip. Courier-ветка модуля не меняется. TF01 Android рассматривается отдельно. TF09 целиком НЕ закрывается: версии тарифов, rounding крайних координат, fallback/provider identity и полный финансовый снимок требуют отдельных решений/доказательств.

До кода: независимое ревью плана. Затем RED→GREEN на той же трассе, границы ключа/порядок/неизменный маршрут/удешевление/TTL/старый namespace, существующие courier/waypoints/scheduled регрессии, обязательный FULL по очереди, независимая приёмка. Не публиковать runtime-кандидат до выполненных гейтов.

## Проверка RED

Из backend запускается существующий isolated pytest wrapper: SQLite временная БД, mock SMS/payments, без demo; Python socket-подключения к нелокальным адресам блокируются wrapper. Это не OS sandbox. Запуск 16.11.2026: `tests/test_taxi_quote_route_identity.py -q --tb=short`, exit1, 2failed за2.42s. Речь о конкретных assertions цены после изменённого маршрута, не об ошибке подготовки. Исходный ошибочный запуск из неверной папки не является RED и в доказательство не включён.
