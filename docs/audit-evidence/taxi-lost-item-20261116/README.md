## Что случается

После завершения такси открыто действующее окно связи о забытой вещи. REST принимает сообщение (200), WebSocket принимает авторизацию участника, но следующее сообщение не сохраняет: повторная проверка разрешает только активные статусы заказа и забывает про `lost_item_until`.

Доказательство: `red.log`, `exit-code.txt`, `test_lost_item_ws.py`. На чистой базе повторён только taxi-сценарий: **1 failed**, 1.68 секунды, ожидаемое падение на отсутствии WS-сообщения в БД. В том же тесте REST-сообщение сохранено. Повтор оправдан переносом с комбинированной ветки на чистый main, чтобы исключить влияние посторонних изменений.

Это настоящий ASGI WebSocket и HTTP на изолированной SQLite, не телефон, не внешний сервер. До импорта приложения wrapper блокирует нелокальную сеть, тест дополнительно запрещает socket connect и подменяет push. Это Python-level ограничение конкретного процесса, не системный сетевой sandbox. Данные синтетические. Тест доказывает существующий отказ, не служит готовым GREEN-тестом: после исправления его ожидание завершения обработчика потребуется заменить ожиданием broadcast с ограниченным временем.
