# Такси: изолированное ядро предварительного расчёта

Пятница, облачный агент. 16.11.2026.

**Это не действующее ценообразование и не готовый редактор тарифов.** Новый модуль нигде не подключён к созданию/расчёту заказов. Текущие цены, модели, настройки, API, рабочая БД и существующие файлы приложения не изменялись. main/production не затронуты. Нет новых зависимостей.

План: [безопасные версии конфигурации](https://github.com/bairasbai/yuldash/blob/fef0a0a2479af86fa437516ee8a350b7afaa92f2/docs/plans/taxi/06-versioned-pricing-config.md), draft PR #242.

## Объём

- Новый `backend/app/taxi_pricing_config.py`: неизменяемый объект с метками версии, территории и класса; строгая проверка полей, типов и технических границ. Цены по умолчанию не заданы.
- Чистый preview только базовой составляющей: база + километры + минуты, затем оба множителя, одно округление ties-to-even и минимум. Целые копейки/метры/секунды/basis points, точная арифметика Fraction.
- Новый `backend/tests/test_taxi_pricing_config.py`: 130 сценариев, включая четыре класса, недопустимые значения, bool/float, переполнение, неизменность, округление, минимум и монотонность за несколькими ступенями округления.

Не входят: подача, ожидание, отмена, комиссии, промо, погода, опции, географический подбор тарифа, льготные километры межгорода, quote/publish/snapshot, редактор и миграции. Метка area_id не определяет полигон, version_id не доказывает публикацию. Результат нельзя выдавать за итог заказа. Выбранные точные примеры совпадают с legacy, но общей эквивалентности старой float-формуле не заявлено.

Будущие профили собственной/арендованной машины не выбираются этим модулем. Связка автомобиля и договора должна проверяться сервером, не галочкой клиента. Это не одобрение новой схемы парка или изменения пассажирских цен.

## Границы приёмки

119 пропусков не являются PASS. UI, эмулятор, реальные поездки, PostgreSQL отдельным прогоном и платёжные провайдеры в этом пакете не проверялись. Тесты чистого модуля и зелёный серверный прогон не доказывают готовность такси или безопасность включения нового расчёта в runtime.

Следующие стадии только после отдельной приёмки: полный контракт пакета тарифов, quote и неизменяемые условия заказа, безопасная миграция legacy, защищённая публикация/откат, совместимость клиентов. Изменение поддерживаемых ставок после такой реализации не должно требовать нового APK; внедрение нового контракта может потребовать первоначального обновления клиентов.
