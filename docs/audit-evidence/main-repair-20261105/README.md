## Подтверждённая проблема и источник исправления

После «Назад»/ухода с экрана или начала выхода поздний результат входа мог записать ключи аккаунта.
Проверка старой версии воспроизводит именно запись, включая временную, а не только последний вид экрана.
На исходном main: **14 FAIL / 5 PASS**, код выхода 1 (`auth-red.log`).
После исправления: **19 PASS**, код 0 (`auth-green.log`).

Это выборочный перенос существующего исправления из [PR #214](https://github.com/bairasbai/yuldash/pull/214),
commit [`f7f81c0c8f96e24f7cbcf92f3646bd3677aac781`](https://github.com/bairasbai/yuldash/commit/f7f81c0c8f96e24f7cbcf92f3646bd3677aac781),
а не новая конкурирующая реализация. `AuthProvider.tsx` совпадает с источником побайтно;
поток/экран и типы адаптированы к main. Из исходных 23 сценариев перенесены 19:
четыре случая обновления списка способов входа неприменимы к main и остались в #214.
Тестовая форма SMS включена только в синтетическом окружении, рабочая настройка не менялась.
Код #213, платежи и серверное управление способами входа в перенос не входят.

Сборка предупреждает о крупном JS-куске; предупреждение не является ошибкой, настройка зависимостей не менялась.

В адресном наборе настоящие LoginScreen/loginFlow/AuthProvider/client/storageHealth, но React-отрисовка,
HTTP, хранилище и планирование Web Locks синтетические. Браузерный проход использует настоящий Chromium,
React, localStorage, Web Locks и реальные нажатия; только ответы HTTP синтетические.
Браузер действительно удерживает `yuldash-session-write`, дожидается ожидающей публикации, отменяет её,
отпускает замок и проверяет **все записи** токена. Успешный вход отдельно сохраняет ровно одну пару.
Перед окончательной фиксацией успешного входа ожидаются `/map`, завершение HTTP (`networkidle`) и два кадра React.
Контекст закрывается до проверки накопленных ошибок; `passed=true` выставляется только после неё.
Внешние HTTP-запросы блокируются; итоговые случаи не сделали ни одного внешнего запроса и не имеют pageerror.
Все 8 снимков визуально просмотрены после завершения анимации карточки (`opacity=1`).

Для воспроизведения браузера: запустить `VITE_API_BASE=http://127.0.0.1:4199/api VITE_TELEGRAM_BOT=synthetic_fixture VITE_SMS_LOGIN_ENABLED=1 npm run dev --prefix webapp -- --host 127.0.0.1 --port 4199 --strictPort`,
создать `/tmp/yuldash-main-repair-evidence/browser`, затем выполнить `node docs/audit-evidence/main-repair-20261105/browser/matrix.cjs`.
Нужны Playwright и `/usr/bin/chromium`; в этой среде они предустановлены.
Скрипт намеренно пишет в указанный временный каталог. Service worker блокируется; это не установленная PWA.

Первый диагностический запуск остановился на неверном точном названии SMS-кнопки в помощнике.
