## Постоянные правила (выжимка)
- **Идемпотентный денежный эффект выполняй ДО пометки платежа `succeeded`, не после.** 2026-07-12 (prod-аудит, критично): `_activate_payment` ставил `payment.status="succeeded"` + commit, а `ledger.settle_*` звал ПОСЛЕ. Краш/таймаут в окне между двумя коммитами → ретрай вебхука упирался в `if status==succeeded: return` и начисление водителю НЕ выполнялось никогда (недоплата, ledger↔payment инвариант сломан навсегда). Правило: для идемпотентных эффектов (settle, гашение долга/комиссии) — сначала ЭФФЕКТ (он сам идемпотентен под своим FOR UPDATE+флаг), потом `succeeded`+commit; ретрай тогда всегда до-докручивает эффект. Для АДДИТИВНЫХ эффектов (boost/реклама/подписка — прибавляют период) наоборот: `succeeded` первым (защита от двойного применения при параллельном/повторном вебхуке). Плюс сам платёж бери под `with_for_update` (webhook+поллинг+админ могут прийти разом).
- **Любой accept/захват ресурса (заказ/бронь/посылка) — под `FOR UPDATE` или атомарным `UPDATE ... WHERE status=<ожидаемый>` + проверка rowcount.** 2026-07-12: приём посылки `parcel_accept` читал `get()`, проверял `status=='created'`, писал `courier_id` — без блокировки. Два курьера параллельно проходили проверку и оба «брали» посылку (last-write-wins). Правило: read-modify-write по общему статусу — всегда под row-lock (как `instant_service.transition`, `bookings.book`); грепни новый accept-эндпоинт на `with_for_update`.
- **Фоновые корутины/потоки: держи ссылку на задачу и лови исключения в Sentry — иначе тихо умирают.** 2026-07-12 (prod-аудит): `asyncio.create_task(...)` без сохранения ссылки → GC может убить задачу; а исключение из `pubsub.get_message` на Redis-блипе выходило из `while` → WS-доставка между воркерами останавливалась НАВСЕГДА, и только `print` (Sentry без `AsyncioIntegration` фон не ловит). Правило: `_task = asyncio.create_task(...)` в модульную переменную; тело фонового цикла — с reconnect-`try/except` + `capture(e)`; на shutdown задачу `cancel()`. Обработчик bare `Exception` (500) тоже сам зови `sentry_sdk.capture_exception` — регистрация хендлера подавляет авто-захват.
- **Деньги — только Decimal/ROUND_HALF_UP, никогда `float * / round()`.** 2026-07-12: комиссия курьера считалась `int(round(price*pct/100))` — float-умножение + banker's rounding, расходилось с `ledger.fee_kop_for` (Decimal) на .5-границах. Правило: любая денежная арифметика — через общий `fee_kop_for`/Decimal-хелпер; грепни новые money-формулы на `round(`/`float`/`* percent`.

## framer-motion затирает Tailwind `-translate-x/y-1/2` (центрирование уезжает)
**Симптом:** элемент с `absolute left-1/2 top-1/2 -translate-x-1/2 -translate-y-1/2` И одновременно `motion.*` с анимацией `scale/rotate/x/y` — центрируется неправильно (уезжает на пол-высоты). Поймали на OrnamentBand: цветок курая провисал ~15px ниже линии узора.

## nginx: `gzip on` без `gzip_types` жмёт ТОЛЬКО text/html — CSS/JS летят несжато
**Симптом:** на телефоне (зажатая LTE / ТСПУ-DPI) сайт открывается голым HTML — без стилей (видны сырые SVG). HTML дошёл, CSS — нет.
**Причина:** в `nginx.conf` стоял `gzip on;`, но `gzip_types` закомментирован. По умолчанию nginx gzip-ит только `text/html` → CSS (52KB) и JS (сотни KB) шли БЕЗ сжатия. На троттлящемся канале крупный несжатый CSS дропается/таймаутит → стили не применяются.
**Фикс:** `/etc/nginx/conf.d/gzip.conf` с `gzip_types text/css application/javascript image/svg+xml application/json …` + `gzip_comp_level 6` + `gzip_min_length 256` + `gzip_vary on`. Проверять `nginx -T | grep gzip_types` и `curl -H "Accept-Encoding: gzip" -D-` (должен быть `Content-Encoding: gzip`). Результат: CSS 52KB→11KB, JS 226KB→71KB.
**Правило:** после деплоя статики всегда проверять, что CSS/JS реально отдаются с `Content-Encoding: gzip`, а не только HTML.

## 2026-07-03 — SVG SMIL (`animateMotion`) без cx/cy → жёлтая точка в углу (0,0) на iOS

На карте РБ импульсы-точки были `<circle r="3">` + `<animateMotion path="M...">` без атрибутов cx/cy. Позиция задавалась ТОЛЬКО через SMIL. На iOS Safari (в т.ч. Яндекс.Браузер = WebKit) SMIL не всегда стартует → круг остаётся в базовой точке (0,0) = лишняя жёлтая точка в левом верхнем углу, движения нет. Правило: движение на мобильной вебе — чистым CSS, не SMIL. Пунктирные линии «текут» через `stroke-dashoffset` + `@keyframes` (класс `.route-flow`) — надёжно везде. Если SMIL всё же нужен (пульс-кольца узлов) — обязательно задавать статичные cx/cy, чтобы при несработавшем SMIL элемент сидел на месте, а не в углу.

## 2026-07-03 — framer `whileInView` + `rotate` initial → кривой элемент на iOS

Центральный курай в `OrnamentBand` имел `initial={{ scale:0.6, rotate:-20 }} whileInView={{ rotate:0 }}`. Если IntersectionObserver/hydration на iOS не отрабатывает вовремя — элемент застревает в initial-состоянии (повёрнут на -20°) = «криво стоит». Правило: для декоративных элементов, которые должны быть видны сразу, не завязывать финальный вид на `whileInView`. Использовать `animate` (стартует на монтировании) и не класть в `initial` трансформы, которые уродуют вид при незапуске (rotate, большой scale). reveal — только лёгкий scale/opacity.

## 2026-07-03 — Веб-лендинг грел телефон: вечные анимации + большие blur + автоплей-видео

**Симптом:** на телефоне сайт грел корпус, на LTE тормозил (на WiFi норм).

**Причина:** непрерывная GPU-нагрузка, которая на мобиле не нужна:
- Aurora-фон: 3 пятна 700px с `blur(140px)` + 2 SVG 460px — всё двигалось вечно через framer (5 бесконечных JS-циклов). Анимация blur-слоёв = постоянный recomposite → жар.
- 15 бесконечных CSS-анимаций (световые следы, фары, пульсы, бегущие кометы, border-beam, «проезд машины» в мокапе).
- Hero-видео с `autoPlay loop` крутилось и на телефоне — вечный декод = жар + трафик LTE.
- Постер героя вечно скейлился (Ken-Burns) полноэкранно.

**Фикс (принцип — на мобиле GPU должен ОТДЫХАТЬ):**
1. Aurora переведён на CSS; движение только `@media (min-width:768px)`, на мобиле пятна статичны (композит один раз). Вращающиеся watermark-и убраны совсем (видны на 5%, чистая потеря).
2. Мобильный блок в globals.css глушит вечные декоративные анимации (`animation:none` для hero-streaks/flare/glow-pulse/avatar-ripple/mockup-*/coverage-runner/go-* и постер-Ken-Burns).
3. Hero-видео на мобиле НЕ грузим и не автоплеим (`matchMedia max-width:767 / pointer:coarse`) → только статичный постер (он же LCP). Экономит трафик LTE и снимает вечный декод.
4. Framer-«парение» карточек приложения (AppShowcase) отключено на мобиле (`min-width:768 and pointer:fine`).

**Правило на будущее:** любая `animation: ... infinite` и `repeat: Infinity` — по умолчанию гейтить `@media (min-width:768px)` или отключать на `pointer:coarse`. Автоплей-видео на мобиле — только если это ядро контента, не фон. `blur()` >40px не анимировать никогда. Десктоп получает всю красоту, телефон — статичную дорогую картинку без нагрева.

## 2026-07-03 — framer `useInView` прятал КОНТЕНТ на мобиле (текст/цифры не появлялись)

**Симптом:** на телефоне «не все тексты показываются», часть цифр пустая/на нуле.

**Причина:** три компонента завязывали ВИДИМЫЙ контент на framer `useInView` (IntersectionObserver) — тот же ненадёжный на iOS Safari механизм, от которого секции уже увели в чистый CSS (`Reveal.tsx`). Если наблюдатель не срабатывал:
- `FounderLetter` — цитата основателя рендерилась как `<span className="opacity-0">` (fallback до печати) → **невидимый текст навсегда**. CSS-фейлсейф её не ловит (он про `style="opacity:0"` inline, а тут Tailwind-класс).
- `StatsBand` / `Counter` — count-up стартует по `inView`; нет события → число висит на `0` («1 200+» = «0»).
Hero не затронут (там `animate="show"`, не `whileInView` — стартует на монтировании).

**Фикс:** хук `useRevealOnce(ref)` = `useInView` + подстраховка таймером (`fallbackMs=1600`): контент считается показанным, как только попал во вьюпорт ЛИБО прошёл таймаут. Контент не прячем никогда; в худшем случае теряется только анимация въезда, значение/текст на месте. Заведён в `web/components/useRevealOnce.ts`, применён в `Counter`, `StatsBand`, `FounderLetter`.

**Правило на будущее:** нельзя гейтить ВИДИМОСТЬ текста/значений на `whileInView`/`useInView` — только доп. анимацию. Всё, что должно быть прочитано, обязано иметь путь появиться без IntersectionObserver (CSS-reveal или таймер-фейлсейф). Проверка: в Playwright занулить `window.IntersectionObserver` (класс-заглушка без вызова callback) и убедиться, что контент всё равно виден — headless Chromium сам по себе IO не ломает, iOS-баг так не повторить.

## 2026-07-03 — Web: `id="ym"` ломает Яндекс.Метрику через DOM-глобал

В браузере элемент с `id="ym"` может создать `window.ym` как DOM-элемент до выполнения скрипта Метрики. Если инициализатор пишет `m[i] = m[i] || function(){...}`, он видит truthy-значение, не заменяет его функцией и следующий вызов `ym(...)` падает с `TypeError: ym is not a function`. Правило: не давать тегу `<Script>` id, совпадающий с глобальным именем SDK; для Метрики использовать `id="yandex-metrika"` и дополнительно проверять `typeof window.ym === "function"` перед вызовом.

## 2026-07-03 — Web: мобильное скачивание APK должно быть настоящей ссылкой

Программный клик по созданному через JS `<a>` или `window.location.assign()` может вести себя нестабильно в мобильных браузерах и плохо проверяется как обычный пользовательский тап. Для APK-CTA использовать настоящий `<a href="/yuldash.apk" download>` прямо в DOM, а аналитику вешать на `onClick` без `preventDefault`. Нижние sticky-CTA не показывать поверх cookie-баннера: начальное состояние `cookieDone=false`, показывать только после `localStorage`/события принятия.

## 2026-07-04 — «Приложение не установлено» у друзей = release был arm64-only

**Симптом:** пользователи (ставят ВПЕРВЫЕ, не обновление) жалуются «Приложение не установлено» после скачивания APK с лендинга. Плюс скрин Google Play Защиты «заблокировано для защиты устройства».

- `apksigner verify` раздаваемого файла → подпись v2 OK (для Android 11+ обязателен) — не подпись.
- `aapt2 dump badging` → манифест чистый: **нет `testOnly`**, minSdk 26, не debuggable — не манифест.
- `curl -I https://yulbash.ru/yuldash.apk` → `Content-Length` байт-в-байт как локальный файл, `application/octet-stream`, nginx 200 — хостинг не корёжит.
- Осталось единственное: `native-code: 'arm64-v8a'` и всё. Release-блок собирался `abiFilters += "arm64-v8a"` (ради веса).

**Фикс:** release ABIs → `arm64-v8a` + `armeabi-v7a` (покрывает все реальные телефоны; x86_64 не берём — только эмуляторы). `versionCode` 1→2 (чтобы следующий APK ставился поверх, а не «уже установлено»). Пересобрал подписанный release (69 МБ vs 45), залил атомарно (scp `.new` → `mv`) в live `/var/www/yuldash-landing/yuldash.apk`, проверил на живом URL (обе ABI + подпись).

**Правило на будущее:** прямой APK «раздача друзьям» = ОБЯЗАТЕЛЬНО минимум `arm64-v8a` + `armeabi-v7a`. Не ужимать до arm64-only ради веса — потеряешь часть телефонов молча. arm64-only оправдан только для Google Play (там AAB сам режет сплиты под устройство). При «не установлено» первым делом смотреть `aapt2 dump badging` → `native-code` и `testOnly`, а не подпись.

## Прод-доводка (релиз-ветка): три реальных урока

**1. PostGIS-фолбэк без rollback ломал `/rides/near` и `/requests/near` на Postgres без PostGIS.**
`try: ST_DWithin(...) except: <log>` — но на Postgres упавший SQL **аварийно закрывает всю транзакцию** (`InFailedSqlTransaction`), и следующий «фолбэковый» запрос тоже падает. Комментарий обещал Python-фолбэк, а его не было. **Фикс:** в `except` — `session.rollback()` перед логом (запрос read-only, терять нечего). Урок: любой `try/except` вокруг сырого SQL на Postgres → `rollback()` в except, иначе фолбэк-код в той же сессии не выполнится.

**2. SQLite прячет ошибки внешних ключей — Postgres нет.**
Тесты вставляли синтетические строки с несуществующим FK (`Message(booking_id=999999)`). На SQLite (FK-проверка выключена в conftest) — проходило; на реальном Postgres — `ForeignKeyViolation` → падение. **Фикс:** тест создаёт настоящую цепочку `Ride → Booking → Message`. Урок: тестовые фикстуры пишем с валидными FK, как в проде. Добавлена CI-джоба `backend-tests-postgres` (реальный Postgres 16 + гонка брони под FOR UPDATE + FK), чтобы такие расхождения ловились автоматически.

**3. Массовая замена `print()`→`log.*` скриптом: НЕ терять `\n`.**
`re.match(r'print\((.*)$', body)` с `splitlines(keepends=True)`: `$` останавливается перед `\n`, а `group()` его **не включает** — если собрать новую строку из группы без хвостового перевода строки, каждая изменённая строка **склеивается со следующей** (тихо, синтаксис ломается ниже). **Фикс:** отделять `\n` до regex и дописывать обратно. Урок: построчные текст-трансформеры — сохраняй перевод строки явно; после прогона обязательно `python -c "import ..."` (smoke-import) + полный pytest как «компилятор».

Итог батча: единый логгер `app/logs.py` (уровни info/warning/error, `LOG_LEVEL` из env; `cleanup.py` осознанно оставлен на `print` — это CLI-отчёт). Полный прогон: **Postgres 753 passed**, **SQLite 752 passed + 1 skip** (гонка брони гоняется только на Postgres). `Mocks.kt` проверен — **не мёртвый** (символы `PartnerAd`/`AdStats`/`demoRides`/… используются в 1–8 файлах), оставлен как есть.
