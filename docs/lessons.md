- 2026-06-23 — Аудит тёмной темы (ui-ux-pro-max): хардкод `Color(0xFF..)` НЕ адаптируется → в тьме текст невидим / контраст ломается. Метод дочистки: грепнуть ВСЕ `Color(0xFF..)` (включая инлайн `Surface(color=` — паттерн `(^| )color` его пропускает!), классифицировать по роли и заменить на адаптивные токены: текст→`CanonText/CanonMuted`, поверхность→`CanonSurface/CanonMint`, danger/SOS→`CanonDangerBg/CanonRed`, акцент-зелёный→`CanonGreen2`, дивайдер→`CanonBorder`. Подводные камни: (а) `replace_all` хекса, который есть в ОПРЕДЕЛЕНИИ токена-геттера, корраптит сам def — для таких делать таргет-правку с контекстом; (б) `Canvas`/`DrawScope` — там @Composable-геттер нельзя, оставлять фиксированный `Color(0x..)`. Проверка готовности: `grep '(color|tint) = Color(0xFF[0-5]'` ничего не находит (кроме бренд-зелёных героя).
- 2026-06-23 — Тёмная тема в большом файле (~600 цветовых ссылок): НЕ переписывать 410 использований `CanonX`. Приём: палитра — `@Composable`-геттеры (`private val CanonGreen: Color @Composable get() = if (isSystemInDarkTheme()) dark else light`). Использования не трогаем — адаптируется определение. Подводный камень: `@Composable`-геттер НЕЛЬЗЯ звать вне composable → в `Canvas{}`/`DrawScope` и не-`@Composable` хелперах (`AdStatus.color()`) ошибка `@Composable invocations can only happen...`. Лечение: пометить хелпер `@Composable` ИЛИ вынести `val c = CanonX` ДО `Canvas{}`. Белые карточки (`containerColor = Color.White`) → адаптивный `CanonSurface`; белый текст/иконки на ЦВЕТНОМ герое — оставить белыми (герой не темнеет). Проверка: `adb shell cmd uimode night yes/no` + скриншот.
- 2026-06-23 — Compose: POST в `rememberCoroutineScope()` ЭКРАНА обрывается при уходе с экрана (scope отменяется) → запрос не доходит (ловили: публикация поездки не сохранялась, БД не росла). Правило: «отправил и забыл» POST'ы — на долгоживущем scope в синглтоне (`ApiClient.bg = CoroutineScope(SupervisorJob() + Dispatchers.IO)` + методы `fireXxx`), НЕ на scope экрана. Нужен результат для навигации → `appScope` (корневой `rememberCoroutineScope` в `YuldashApp`, переживает смену экрана) + метод возвращает id.
- 2026-06-23 — Передеплой бэкенда от root: `tar -xzf` делает файлы root-owned → сервис под юзером `yuldash` не пишет → `attempt to write a readonly database` (500 на запись). Правило: после распаковки ОБЯЗАТЕЛЬНО `chown -R yuldash:yuldash /opt/yuldash` ПЕРЕД рестартом (есть в шпаргалке передеплоя в server.md).
- 2026-06-22 — FastAPI+SQLModel: эндпоинт, который меняет НЕСКОЛЬКО ORM-объектов и сразу их возвращает, после `session.commit()` отдавал `[{}]` (пустые). Причина: `expire_on_commit` обнуляет объекты после commit. Правило: для одиночного объекта — `session.refresh(obj)` (уже делали), для списка — цикл `for o in items: session.refresh(o)` ПОСЛЕ commit перед возвратом.
- 2026-06-22 — Интерактивный `MapView` внутри прокручиваемого `LazyColumn`: список перехватывает жесты, тап по маркеру/панорамирование не доходят до карты. Правило: в `AndroidView` с картой ставить `view.setOnTouchListener { v, e -> if (e.actionMasked == ACTION_DOWN) v.parent?.requestDisallowInterceptTouchEvent(true); false }` — тогда жест остаётся у карты, а не у скролла.
- 2026-06-22 — ANR на эмуляторе при долгой сессии с MapKit. После многих установок/скриншотов/рендера карты x86-эмулятор (`sdk_gphone16k_x86_64`) уходит в стойкий ANR — ловился даже на онбординге (где карты нет) → причина среда, не код. Правило: не делать выводов о баге по ANR на затраханном эмуляторе; визуальную проверку тяжёлых GL-фич (карта) дублировать на реальном устройстве. Нативный краш MapKit (если был бы) ищется по `SIGSEGV`/`F DEBUG`/`libmaps`, а не `FATAL EXCEPTION`.
- 2026-06-22 — MapKit `Invalid api key` (РАЗРЕШИЛОСЬ: ключ активировался через ~час, тайлы загрузились). Интеграция верная (запрос уходит на `proxy.mob.maps.yandex.net`, краша нет), но сервер Yandex отвечает `Forbidden. Body :Invalid api key` → тайлы не грузятся, видна пустая сетка. Причина обычно — **свежий ключ ещё не активировался** (у Yandex это занимает до нескольких часов). Правило: после создания ключа MapKit не паниковать на `Invalid api key` — подождать активации; если через сутки то же — проверить тип ключа («MapKit – мобильный SDK») и статус в кабинете. В коде это не чинится.
- 2026-06-22 — Сборка из Git Bash (уточнение): рабочая команда — `export JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"` затем `cmd //c "...gradlew.bat -p <путь> :app:assembleDebug --no-daemon"`. ВАЖНО: НЕ ставить `MSYS_NO_PATHCONV=1` — он ломает трюк `//c` (cmd открывается интерактивно вместо запуска). `gradlew.bat`-лаунчеру нужен именно `JAVA_HOME` (даже при `org.gradle.java.home` в gradle.properties).
- 2026-06-21 — Сборка из Git Bash: `gradlew.bat` не находился. Правило: запускать через `cmd //c "set JAVA_HOME=... && C:\...\android\gradlew.bat -p C:\...\android :app:assembleDebug --no-daemon"` (двойной `//c`, полный путь к gradlew, `-p` вместо `cd`).
- 2026-06-21 — adb + Git Bash: пути устройства `/sdcard/...` подменялись на Windows-путь. Правило: `export MSYS_NO_PATHCONV=1` перед adb-командами с путями устройства (screencap/pull/push).
- 2026-06-21 — Прозрачный PNG: «вырезано» в редакторе ≠ прозрачно. Если файл RGB (без альфы) с клеткой — клетка вшита в пиксели. Проверять режим (`RGBA`) перед использованием. Лучший логотип пришёл уже как настоящий RGBA.
