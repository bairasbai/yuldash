## 0. 7 принципов справедливости (наш differentiator)

1. **Обе стороны слышимы.** На любое обвинение у второй стороны есть право объясниться ДО наказания
   («due process»). Ни один страйк не ставится молча.
2. **Мир по умолчанию.** Первый шаг — примирение/предупреждение, а не бан. Кнопка «Мы решили миром»
   закрывает спор без последствий. Наказание — крайняя мера.
3. **Соразмерность и лестница.** 1-е нарушение → предупреждение. 2-е → страйк. 3-е → короткая пауза
   (3 дня). Дальше 7 → 30. Мгновенный бан — только за тяжёлое (безопасность, мошенничество, харассмент).
4. **Затухание.** Страйки «сгорают» через 60 дней хорошего поведения. Никакого «клейма навсегда».
5. **Защита оболганного.** Одна жалоба-месть не рушит рейтинг: нужен паттерн/подтверждение. Спорную
   оценку админ исключает из среднего. Есть «щит рейтинга».
6. **Прозрачность.** Каждое решение приходит обеим сторонам с человеческим объяснением «почему».
   Пороги и правила видны в приложении. Никаких «заблокированы, причину не скажем».
7. **Возврат рейтинга.** Рейтинг — скользящее окно свежих поездок: старые ошибки тускнеют по мере того,
   как ты снова возишь/ездишь хорошо. Прогресс, а не приговор.

> Чем мы лучше: Яндекс Про жёсток к водителю (рейтинг <4.5 → отключают, отмена −7 приоритета, бан без
> объяснений). Яндекс Доставку критикуют за отказ от претензий и занижение компенсаций (Пикабу/vc.ru).
> Uber/Lyft берут «плату за неявку», но односторонне. Мы: **симметрично защищаем всех**, ставим МИР
> вперёд наказания, объясняем каждое решение и даём вернуть рейтинг.

## 1.1 🔑 Особый случай: «бампинг» — водитель бросил подтверждённых ради тех, кто больше платит

> Очень частая беда попуток: водитель повесил объявление по цене X, набрал попутчиков, подтвердил бронь, а
> в момент выезда звонит «не еду / машина сломалась» — и уезжает с теми, кто заплатил больше, или с роднёй.
> Это **прямой обман подтверждённой договорённости**. Разрешаем это тремя рычагами: замок цены, детект лжи,
> невыгодность.

### Рычаг 1 — «Гарантия цены» (цена-замок)
- **Подтверждённая цена неизменна.** `Booking.price` фиксируется в момент брони; в API НЕТ способа поднять цену
  подтверждённой брони. Водитель требует доплату на месте → это инцидент `overcharge`/`non_payment` (вина водителя).
- **Приоритет подтверждённых.** Место, занятое подтверждённой бронью, нельзя «перепродать» тому, кто больше платит:
  места кончились — новый (даже более щедрый) пассажир просто не может забронировать. Обман работает ТОЛЬКО через
  ручную отмену водителем — а её мы делаем тяжёлой и заметной (ниже).
- В приложении — бейдж **«Гарантия цены»** на поездке: пассажир видит, что цену не поднимут. Это наш козырь доверия.

### Рычаг 2 — детект фиктивной «не еду» (ловим ложь без слежки)
Отмена водителем **подтверждённой** брони — не то же самое, что отмена пассажиром: она бьёт по тому, кто уже
рассчитывал на поездку. Поэтому при `cancel_booking`, вызванной ВОДИТЕЛЕМ по `confirmed`/`onboard` броне:
1. Помечаем `cancelled_by=driver`, `cancel_reason` (в т.ч. `not_going`).
2. **Сигналы подмены** (любой → флаг `suspected_bump=true` на авто-инциденте, уведомление админу):
   - поездка **осталась `active`** после «не еду» (не отменил саму поездку, только сбросил пассажира);
   - поездка **заполнилась заново** (новая бронь на это место в течение N часов);
   - водитель **republish** — опубликовал другую поездку тем же `from→to` в ±2ч от того же времени в течение N часов
     (часто дороже);
   - несколько пассажиров одной поездки пожаловались на одного водителя (паттерн).
3. Авто-создаём инцидент `driver_no_show` (вина провизорно на водителе) и присылаем брошенному пассажиру
   **предзаполненную жалобу в один тап** + сразу альтернативы на его маршрут (уже есть «Ближайшие на маршрут»).
4. Настоящий форс-мажор (`cancel_reason=emergency`, можно фото) → **без страйка**. НО тогда поездка не состоится
   ни для кого; если она всё же состоялась с другими — это и есть улика (сигналы п.2 сработают).

### Рычаг 3 — сделать бампинг невыгодным (рынок наказывает сам)
- Отмена подтверждённой брони водителем весит в **Надёжности** тяжелее, чем неявка пассажира (сильнее роняет %).
- **Надёжность и «отмен: N» видны пассажирам** на карточке водителя (`/users/{id}/trust`) → ненадёжного объезжают.
- Повторные поздние отмены → `limited`: нет «поднятия»/буста, ниже в выдаче → стратегия «возьму кто больше заплатит»
  оборачивается меньшим числом будущих пассажиров. Жадность бьёт по самому бамперу.
- Мирный выход для честного водителя: предложить пассажиру **пересадку** (помочь перебронировать на другую поездку) —
  показывает добрую волю, смягчает последствия.

### Контракт-дельта (для реализации)
- `Incident` + поле `suspected_bump: bool = False`.
- `bookings.py::cancel_booking`: когда отменяет ВОДИТЕЛЬ по confirmed/onboard — записать причину, посчитать сигналы
  подмены (helper `detect_bump(session, ride, booking)`), при срабатывании создать `driver_no_show`-инцидент с
  `suspected_bump=true` + `notify_admin_telegram` + пуш пассажиру с альтернативами.
- Reliability: отмена водителем подтверждённой брони — отдельный тяжёлый минус (вес > passenger no-show).
- Android: бейдж «Гарантия цены» на карточке поездки; при получении пуша «водитель отменил» — экран с альтернативами
  + кнопка «Пожаловаться» (предзаполнено `driver_no_show`).

## 2. Лестница эскалации (как считаем и наказываем)

**Состояние пользователя (`standing`):** `good` → `warned` → `limited` → `suspended`.

- **warning** (замечание): не влияет на доступ, воспитательное. Ставится за 1-е лёгкое подтверждённое нарушение.
- **strike** (страйк): «жёлтая карточка». Копятся.
  - `strikes >= 2` → `limited` (мягкие ограничения: не может «поднимать»/буст, ниже в выдаче, баннер «восстанови рейтинг»).
  - `strikes >= 3` → `suspended` на `SAFETY_SUSPEND_1=3` дня. Следующая приостановка — 7 дней, затем 30.
- **severe** (безопасность/мошенничество/харассмент/утеря): минуя лестницу → немедленный `suspended` + разбор человеком; при подтверждении — до бессрочного.
- **Затухание:** страйк «сгорает» через `SAFETY_STRIKE_DECAY_DAYS=60` дней без новых нарушений. `last_strike_at` + фон-очистка/ленивый пересчёт.
- **Надёжность (`reliability`, 0–100%)** — наш добрый аналог «Активности» Яндекса, но считаем от факта и показываем ПОЗИТИВНО: `completed / (completed + no_show + late_cancel)` за последние `SAFETY_RELIABILITY_WINDOW=30` поездок. Новичок стартует с нейтральных 100% (презумпция добросовестности).

**Симметрия:** лестница одинакова для пассажира, водителя, курьера, отправителя. Никакой стороне не даём безнаказанно вредить другой.

## 3. Рейтинг: честный и восстановимый

- **Слепой двусторонний.** Оценку второй стороны не видно, пока: (а) ты сам не оценил, ИЛИ (б) не прошло
  24 ч после завершения. Убирает месть и вымогательство (Uber/Airbnb-паттерн).
- **Среднее с защитой.** `DriverProfile.rating` и рейтинг пассажира — среднее по `Rating.stars`, но:
  - исключаем `Rating.excluded == True` (спорные, снятые админом);
  - (v2, опц.) вес свежих оценок выше — «скользящее окно». В MVP: простое среднее не-исключённых.
- **Теги оценки.** К звёздам — необязательные теги (`polite`, `ontime`, `clean`, `safe` / негативные `late`,
  `rude`). Помогают понять «за что», мягче цифры.
- **Спорная оценка.** Если оценка привязана к жалобе-мести — при разборе `exclude_rating=true` убирает её из среднего.
- **Щит рейтинга** (`rating_shield`): админ может защитить оболганного — временно не даём новым 1★ ронять его.

## 4. Мирные механики (то, что делает нас добрее)

- **Кнопка «Мы решили миром»** (`/incidents/{id}/withdraw`): заявитель закрывает спор без последствий. Обе
  стороны получают тёплое «Спасибо, что договорились по-соседски». Поощряем.
- **Таймер ожидания** (клиент): при статусе «подъезжает/на месте» — видимый отсчёт 7 мин и напоминание
  пассажиру, прежде чем разрешить «Пассажир не вышел». Не наказываем за 30 секунд.
- **Форс-мажор** без штрафа: причина отмены `emergency` + фото → защищено.
- **Право на объяснение:** обвинённый всегда видит суть и пишет свою версию (`respond`), прежде чем решение.
- **Апелляция:** любое наказание обжалуется (`appeal`) → человек. Сроки — быстрые (цель 48 ч, не 30 дней как у Я.Доставки).
- **Тон:** спокойный, по-добрососедски, на двух языках, без обвинения пользователя.


## 6. КОНТРАКТ — эндпоинты (backend)

> Новый роутер `backend/app/routers/incidents.py` (+ зарегистрировать в `routers/__init__.py`).
> Расширения отмены/оплаты/no-show/parcel — в `bookings.py`. Standing/trust/policy — в новом роутере или safety.py.

**Инциденты (участники):**
- `POST /incidents` → Incident. Body `{booking_id?:int, respondent_id:int, type:str, description:str, evidence_urls?:[str]}`.
  Валидация: нельзя на себя; тип из белого списка; если booking_id — заявитель участник брони; rate-limit (анти-спам).
  Побочки: severe → уведомить админа (Telegram) сразу; пуш обвинённому «по поездке открыт разбор, опишите свою версию».
- `GET /incidents/mine` → `[IncidentOut]` (где я reporter ИЛИ respondent). Поле `my_role: reporter|respondent`.
- `GET /incidents/{id}` → IncidentOut (только участники + админ; иначе 403).
- `POST /incidents/{id}/respond` → Incident. Body `{statement:str, evidence_urls?:[str]}`. Только respondent. status→under_review.
- `POST /incidents/{id}/appeal` → Incident. Body `{text:str}`. Участник (обычно наказанный). appeal_status→requested, status→appealed.
- `POST /incidents/{id}/withdraw` → Incident. Только reporter. resolution→mutual_resolved, status→closed. («Решили миром».)

**Инциденты (админ):**
- `GET /admin/incidents?status=` → `[AdminIncidentOut]` (имена/телефоны обеих сторон, обе версии, evidence, тип, severity).
- `POST /admin/incidents/{id}/resolve` → Incident. Body
  `{resolution:str, fault:str, note:str, compensation_kop?:int, strike?:bool, suspend_days?:int, exclude_rating?:bool, shield?:bool}`.
  Применяет последствия: обновляет SafetyProfile обвинённого (strikes/standing/suspended_until по лестнице §2), при
  `exclude_rating` — помечает связанную `Rating.excluded=True`, при `shield` — `rating_shield=True`. Пуш ОБЕИМ сторонам с `note`.

**Standing / trust / policy:**
- `GET /me/standing` → `{standing, strikes, warnings, reliability:int, suspended_until?, suspend_reason, active_incidents:int, can_act:bool}`.
  `can_act=false`, если `suspended_until>now` (клиент блокирует создание поездок/броней с понятным баннером).
- `GET /users/{id}/trust` → публичный снимок доверия: `{rating:float, rating_count:int, trips:int, verified:bool, reliability:int, member_since}`. Без телефона/приватного.
- `GET /safety/policy` → все пороги §5.5 (клиент показывает «бесплатная отмена — 5 мин» из сервера, не хардкодит числа).

**Отмена / неявка / оплата / курьер (в bookings.py):**
- Расширить `POST /bookings/{id}/cancel` — принять опц. body `{reason?:str, note?:str}`. Записать `cancelled_by/cancel_reason/cancel_note/cancelled_at`. Если поздняя (§ порог) — вернуть флаг `late:true` в ответе (клиент мягко предупреждает). Обратная совместимость: без тела работает как раньше.
- `POST /bookings/{id}/no-show` → Incident. Body `{note?:str}`. Кто вызвал: водитель→`passenger_no_show`, пассажир→`driver_no_show`. Гейт: бронь была `confirmed/onboard`; не раньше времени выезда − небольшое окно; одна на бронь. Ставит `booking.no_show=true`.
- `POST /bookings/{id}/payment` → Booking. Body `{received:bool, note?:str}`. Только водитель, только `done`. `received=false` → `payment_state="unpaid"` + мягкий инцидент `non_payment`.
- `POST /bookings/{id}/parcel-photo` → Booking. Body `{phase:"pickup"|"delivery", url:str}`. Участник брони. Сохраняет фото-доказательство.

**Схемы Out** (пример `IncidentOut`): все поля + `booking_route:"Город→Город"?`, `other_name` (имя второй стороны для показа), `type_label` НЕ нужен (клиент локализует по коду). Телефон второй стороны — НЕ отдаём участникам (приватность), только админу.
