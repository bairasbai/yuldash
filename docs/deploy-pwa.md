**Почему ключ карт пустой.** На ноутбуке есть ключ геокодера (`YANDEX_GEOCODER_KEY`), но он
**серверный** — его специально убрали из приложения, чтобы не светить. JS-ключ сайта виден
любому, кто откроет страницу, поэтому это должен быть **отдельный** ключ с привязкой к домену
`app.yulbash.ru`: кабинет разработчика Яндекса → «JavaScript API и HTTP Геокодер» → новый ключ →
в ограничениях указать домен. Положить в `webapp/.env.production` → `VITE_YANDEX_MAPS_JS_KEY`,
потом `bash webapp/deploy.sh`. Можно после запуска — сайт от этого не зависит.

## Что нужно от тебя (10 минут + ожидание DNS)

1. **DNS.** У регистратора домена `yulbash.ru` добавить запись: `A  app  85.239.52.55`.
   Доедет за 5–30 минут.
2. **Выключить VPN.** Российские адреса через зарубежный VPN не идут: `ping 85.239.52.55`
   отвечает за 0 мс — это отвечает VPN-клиент, а не сервер (18.09 было именно так).
   Подробно — [server.md](server.md), «Не достучаться до сервера».
3. **Одна команда** из корня репозитория (PowerShell или Git Bash):
   ```
   bash webapp/server-setup.sh
   ```
   Если `bash` не находится: `& "C:\Program Files\Git\bin\bash.exe" webapp/server-setup.sh`.

   Скрипт сам, по шагам, с повторами при обрыве SSH:
   - проверит, что это **наш** сервер (`msk-1-vm-3azu`), а не чужой из `known_hosts`;
   - поставит временный nginx-конфиг под проверку Let's Encrypt;
   - допишет в `/opt/yuldash/.env` строку `CORS_ORIGINS=…,https://app.yulbash.ru` и VAPID-ключи
     (резервная копия `.env.bak-дата` рядом), перезапустит API, покажет `/health`;
   - проверит DNS **с сервера**. Если запись ещё не доехала — остановится с подсказкой;
     **просто запусти ещё раз позже**, сделанное не повторяется;
   - выпустит сертификат (`certbot certonly --webroot`), продление — само, таймер certbot;
   - поставит боевой nginx-конфиг из `webapp/nginx.conf.example` (SPA, кеш, security-заголовки);
   - соберёт сайт и выкатит (`deploy.sh`), проверит с сервера: главная 200, manifest 200,
     `sw.js` без кэша.

   Ждём в конце `DEPLOY_DONE` и `SETUP_DONE`.

## Каждая следующая выкатка (2 минуты)

```
bash webapp/deploy.sh
```
Собирает → заливает → атомарно подменяет папку, **не стирая старые assets два дня**
(старый service worker у людей может их ещё просить — иначе белый экран, как ловили на
лендинге в июле) → `nginx -t && reload` → проверяет **с сервера** главную, manifest и что
`sw.js` не кэшируется. С ноута публичный домен часто не виден (ТСПУ/VPN) — эта проверка
в конце только справочная, деплой она не валит.

- Войти по SMS-коду, открыть «Мои заявки», «Профиль → Мои данные».

## ⚠️ Бэкенд на проде — июльский

Сайт собран под **нынешний** сервер из репозитория. На проде код июля
([deploy-checklist-2026-09.md](deploy-checklist-2026-09.md) ещё не выполнен), поэтому до выкатки
бэкенда часть экранов сайта будет получать «404/Повторить»: пуши в браузере (ручки

экраны показывают состояние ошибки. Порядок: сначала бэкенд по чек-листу, потом (или
параллельно) сайт — друг другу они не мешают.

## Если сломалось

- Белый экран после выкатки → `ssh root@85.239.52.55 "ls /var/www/yuldash-webapp/dist/assets | wc -l"` —
  должно быть больше нуля; `ssh root@85.239.52.55 "curl -skI --resolve app.yulbash.ru:443:127.0.0.1 https://app.yulbash.ru/sw.js"` — `Cache-Control: no-cache`.
- API-ошибки на сайте при живом `/health` → почти всегда CORS — в консоли браузера слово `CORS`;
  проверить: `ssh root@85.239.52.55 "grep ^CORS_ORIGINS /opt/yuldash/.env"`.
- `server-setup.sh` упал на certbot → чаще всего DNS ещё не доехал до Let's Encrypt (подождать,
  запустить ещё раз) или порт 80 закрыт файрволом (`ufw status`).
- Откат сайта: предыдущей папки нет (заменяется атомарно), откат = собрать прошлый коммит
  и снова `deploy.sh`. Старые assets двое суток лежат рядом, так что старые вкладки не ломаются.
- Откат `.env` бэкенда: `ls /opt/yuldash/.env.bak-*` → скопировать обратно → `systemctl restart yuldash-api`.

## Как это устроено (справка)

- **Почему certbot без nginx-плагина.** В боевом конфиге прописаны пути к сертификатам; пока
  их нет, `nginx -t` падает, и плагин `--nginx` падает вместе с ним. Поэтому сначала временный
  HTTP-конфиг, выпуск через `--webroot` (каталог `/var/www/letsencrypt`, отдельный от `dist/`,
  который `deploy.sh` подменяет целиком), и только потом боевой конфиг. В нём для `/.well-known/acme-challenge/`
  оставлен HTTP-путь, чтобы продление не упиралось в редирект на HTTPS.
- **Почему проверка с сервера.** С Windows `curl` к `yulbash.ru` часто отвечает `000`
  (ТСПУ/VPN) при живом сервере — [lessons.md](lessons.md), 2026-06-24. Скрипты проверяют
  `curl --resolve app.yulbash.ru:443:127.0.0.1` прямо на сервере.
- **Почему удалённый скрипт передаётся файлом, а не heredoc'ом.** `retry cmd <<EOF` отдаёт
  heredoc первой попытке; повтор после обрыва SSH получал бы пустой скрипт и «успех».
