# Android: подтверждённая запись последнего офлайн-действия — 19.09.2026

Рабочая ветка `codex/push-routing-audit`, без коммитов и публикации. В локальном main `527dbb0d2c3973899e3b6db0c6e9c4026f3da174` и рабочей версии до этой группы TripPassStore.save/Outbox.writeAll использовали apply, а enqueue не возвращал результат сохранения. В BookingActiveTripScreen после enqueue безусловно появлялось обещание отправить позже. Отказ хранения нельзя было отличить от успешного добавления.

## Изменения

- `OfflineWrites.kt`: запись строки через commit, успешный Boolean только при подтверждённой записи. При отказе предпринимается восстановление прежнего значения: Android может изменить память даже при неудачной записи на диск.
- `TripPass.kt`: save и enqueue возвращают Boolean; счётчик очереди изменяется только после успеха. При отказе записи во время flush дальнейшая отправка останавливается. Параллельные enqueue сериализованы, чтобы перевод записи из UI в IO не создавал потери между двумя добавлениями.
- `BookingActiveTripScreen.kt`: добавление сообщения, статуса водителя и статуса пассажира выполняется в IO. Обещание отправить позже показывается только после успеха; иначе — ошибка сохранения. Сообщение получает существующую отметку неудачи с возможностью повтора. Оптимистичный статус пассажира откатывается при отказе сохранения, если он ещё соответствует этой попытке. Запись паспорта из suspend-функции тоже перенесена в IO.

Смысл изменения интерфейса вызова:

```diff
- enqueue(...): Unit; apply(); показать «отправим позже»
+ enqueue(...): Boolean; commit(); показать «отправим позже» только при true
```

Новая надпись: RU «Не получилось сохранить. Повтори попытку.» / BA «Һаҡлап булманы. Ҡабатлап ҡара.». Башкирский — черновик для проверки носителем, добавлен в tasks.md.

## Оставшиеся границы

Успешный commit не является гарантией против физической поломки накопителя. При полном отказе записи нельзя гарантировать и восстановление старого значения. Эта группа не доказывает отсутствие повторной доставки при потере ответа сервера или отказе удаления уже отправленного действия. Отдельно остаются гонки flush с новым enqueue/выходом и подтверждение переноса между хранилищами до удаления источника. Общая исправность приложения и всех ролей не объявляется.
