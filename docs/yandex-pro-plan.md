# 🚕 Яндекс Про → Юлдаш: что берём, что нет, и план (2026-07-20)

> Задача Александра: изучить «Яндекс Про» (приложение водителей и курьеров Яндекса, экс-«Таксометр»), взять полезное для Юлдаша — особенно для такси-части (кабинет водителя) и курьерской (посылки), написать подробный план.
> Ресёрч: 2 глубоких прохода по официальной базе знаний pro.yandex.ru / dostavka.yandex.ru + разборы (Habr, vc.ru, РБК) + форумы водителей и курьеров (Пикабу, Otzovik, 4PDA). ~90 источников. Ниже — выжимка и план.

## 1. Вывод (кратко)

1. **Мы не «маленький Яндекс» — мы его противоположность, и это надо закрепить.** Главные жалобы водителей на Яндекс Про: «работаешь вслепую» (не видно точку Б и цену до принятия), растущая комиссия, штрафы и блокировки «без суда», поддержка-бот, давящий таймер оффера, принудительный автоприём. **У нас всего этого нет по построению** — водитель видит весь маршрут, цену и попутчика ДО отклика, комиссии ноль, наказаний нет. Это наш манифест, его надо проговаривать в продукте и в маркетинге.
2. **Самое ценное для заимствования — не такси-механика, а курьерская:** статусная цепочка посылки («забрал → в пути → вручил»), код подтверждения вручения и **трекинг-ссылка получателю без приложения**. У нас посылки сейчас — просто галочка на поездке (получатель вообще не в системе). Это и есть «Посылки 2.0» — главный кусок плана.
3. **Дешёвые победы существуют**, потому что половина нужных механизмов у нас уже есть: `boarding_code` (готовый код вручения), `driver_phase` (готовые статусы), `TripShare` (готовый шеринг третьему лицу), live-трекинг WS (готовая позиция для трекинг-ссылки), лендинг `web/` (готовое место для страницы отслеживания).
4. **Геймификацию Яндекса не берём** (баллы приоритета, уровни Бронза–Платина, минус-баллы за отмены) — это кнут, встроенный в пряник, и водители его ненавидят. Берём только «пряник без кнута»: достижения-бейджи и честную статистику.

## 2. Манифест: их боли = наши ценности (закрепить в продукте)

| Боль водителя в Яндекс Про (из отзывов) | Как в Юлдаше |
|---|---|
| Точка Б и цена скрыты до принятия («едешь вслепую»); показ точки Б продавали за статус/доплату | **Всегда видно всё до отклика**: маршрут, цена, время, кто едет. Так и оставляем — это святое |
| Комиссия 22–25% + комиссия парка, «плата за ПО» | **0% комиссии.** Монетизация — донаты, буст, реклама партнёров |
| −7 баллов за отмену, блокировки 3ч→сутки→3 суток, принудительный автоприём | **Без штрафов и принуждения.** Отмена — уведомляем вторую сторону (уже сделано), репутация — только честный рейтинг |
| Поддержка-бот со скриптами | **Живой человек** (Александр в Telegram) + кнопка «Позвоните мне» |
| Обязательный фотоконтроль раз в ~10 дней | Разовая проверка документов (OCR + ручная) — достаточно для «между своими» |
| Таймер оффера 10–20 секунд | Отклики без таймера — водитель решает спокойно |

→ **Действие:** абзац «Почему водители выбирают Юлдаш» на лендинг и в онбординг водителя (двуязычно). Дёшево, а конверсию в водителей растит.

## 3. Карта функций Яндекс Про (что там вообще есть)

**Водительская часть:** онбординг (заявка → тест → фотоконтроль, самозанятость/парк), «На линии»/«Занят», оффер с таймером 10–20 сек, цепочки заказов, режимы «Домой»/«По делам»/«Мой район» (платные!), фильтр нал/безнал, тумблеры тарифов (Эконом…Премиум, Доставка, Межгород), карта спроса с фиолетовыми зонами surge, гарантии дохода, персональные бонусы, чаевые (Яндекс Чаевые), мгновенные выплаты на Карту Про, **Приоритет** (+1 за заказ, −4 пропуск, −7 отмена), уровни **Бронза/Серебро/Золото/Платина** (скидка на комиссию до 10%, показ точки Б), рейтинг из последних 150 оценок со свежим весом, стартовые 30×4.2 новичку, кнопка «Конфликт» (запись звука 10 мин), «Позвонить 112», детектор ДТП, страховка на заказ до 2 млн ₽, подменные номера, встроенный Навигатор, таксометр с платным ожиданием, статистика дохода, «Диагностика» (почему нет заказов), Заправки с кешбэком, чат с лайком и голосовым вводом.

**Курьерская часть + Доставка:** типы (пеший/вело/авто/грузовой; Еда/Лавка/Доставка), слоты с гарантией в час vs свободный график, оффер со скрытой точкой Б (открывается по статусу), статусная цепочка **«На месте → Забрал посылку → На месте → Подтвердить вручение»**, СМС-коды при заборе и вручении, «оставить у двери» + фото, платное ожидание с 9-й минуты, возвраты с оплатой обратной дороги, мультиточки и мультизаказы, тарифы Экспресс/«В течение дня»/ПВЗ-межгород, динамическая цена, **трекинг-ссылка получателю** (браузер, без приложения: карта с курьером, ETA, звонок/чат), подменные номера, страховка по объявленной ценности, наложенный платёж (B2B), чаевые 100% курьеру, список запрещёнки (штраф 10 000 ₽), «Приоритет» курьера.

## 4. ЧТО БЕРЁМ — такси-часть (Кабинет водителя 2.0)

### 4.1 ⭐ Режим «Еду домой / по пути» — P1, наш core-кейс
- **У Яндекса:** режим «Домой» — платный (% сверх комиссии), 2 раза в день, подбирает заказы в сторону дома.
- **У нас:** это буквально суть попуток. Водитель в кабинете жмёт «Еду в …» (город/направление) → лента заявок (`RequestsFeedScreen`) и карта фильтруются по его маршруту, новые подходящие заявки приходят пушем. **Бесплатно — это ценность, а не услуга.**
- **Как:** у нас уже есть `/requests/near` (гео+радиус) и matcher. Добавить: сохранённое «направление водителя» (from→to у водителя онлайн), эндпоинт «заявки по моему маршруту», пуш при новой подходящей заявке (дедуп раз в N минут). Клиент: одна кнопка в кабинете + чип-фильтр в ленте.

### 4.2 Быстрые ответы в чате — P1, дёшево
- **У Яндекса:** лайк-квитанция + голосовой ввод (библиотеки шаблонов нет — сделаем лучше).
- **У нас:** чипы над полем ввода: «Еду 👍», «Буду через 5 мин», «Я на месте», «Наберите меня» — двуязычные (черновой башкирский → `tasks.md` при реализации). Тап = отправка. Файл: `BookingActiveTripScreen.kt` (чат уже там).

### 4.3 Статистика водителя («мой дневник») — P1
- **У Яндекса:** заработок за день/неделю, детализация, время на линии, рекомендации.
- **У нас:** экран в кабинете: поездок за неделю/месяц/всё время, заработано (сумма цен подтверждённых броней — деньги идут напрямую, мы просто считаем), пассажиров перевезено, рейтинг и его динамика. Бэкенд: 1 эндпоинт-агрегат (SQL по броням `done`). Без «целей» и бонусов — просто честные цифры.

### 4.4 «Диагностика: почему мало откликов» — P2
- **У Яндекса:** раздел «Диагностика» (ограничения, проверки, что сделать).
- **У нас:** карточка-подсказка в кабинете, локальная логика + существующие данные: нет фото профиля → «с фото бронируют чаще»; не пройдена проверка → «пройди, бейдж повышает доверие»; цена сильно выше `price_hint` → «средняя по маршруту … ₽»; мало мест/нет условий. Без санкций — только советы.

### 4.5 Бейдж «Новичок» вместо пустого рейтинга — P2
- **У Яндекса:** новичку дарят 30 оценок по 4.2 (маскируют пустоту).
- **У нас:** честнее: до 5 оценок показываем тёплый бейдж «Новичок · будь первым, кто оценит» вместо «—». Не фейкуем цифру — «между своими» врать нельзя.

### 4.6 Рейтинг: скользящее окно + свежий вес — P2 (бэкенд)
- **У Яндекса:** последние 150 оценок, свежие весят больше → человек может исправиться.
- **У нас:** сейчас среднее за всё время. Перейти на «последние 50 со свежим весом» (масштаб наш меньше). Одно место: `user_rating()` в `services.py`. Мягкая миграция: если оценок <50 — как раньше.

### 4.7 Достижения-«пряники» — P2/P3
- **У Яндекса:** уровни с кнутом. **Берём только пряник:** бейджи в профиле — «10 поездок», «50 поездок», «Год с Юлдаш», «0 отмен за 3 месяца», «Помог 5 посылкам». Считаются из существующих данных, влияют ТОЛЬКО на красоту профиля (никакого распределения заказов). Двуязычные названия.

### 4.8 Кнопка «Проблема с поездкой» в активной поездке — P2 (безопасность)
- **У Яндекса:** кнопка «Конфликт» пишет звук 10 минут (нам нельзя — 152-ФЗ, согласие на запись, юр-минное поле).
- **У нас:** без записи: кнопка в активной поездке → быстрый выбор («опасное вождение», «конфликт», «другое») → создаёт `Report` с привязкой к брони + алерт админу в Telegram (алерт о жалобах уже сделан в PR #95). SOS остаётся для угрозы жизни.

### 4.9 Спрос без surge — P3
- **У Яндекса:** фиолетовые зоны с коэффициентом, surge-цены.
- **У нас:** surge-цен НЕ будет (цену ставит водитель; накрутка в час пик — против «между своими»). Берём только **информацию о спросе**: в кабинете «🔥 Сейчас ищут: Баймак→Уфа — 3 заявки» (из `/feed` + активных заявок). Информируем, не манипулируем ценой.

## 5. ЧТО БЕРЁМ — курьерская часть («Посылки 2.0», главный кусок)

> **Что сейчас:** «посылка» = категория поездки + поля `receiver_name`/`parcel_size`. Получатель НЕ в системе, статусов нет, пуши — общие («Водитель выехал»), подтверждения вручения нет. По сути — договорённость в чате.

### 5.1 ⭐ Статусная цепочка посылки — P1 (Фаза A)
- **У Яндекса:** На месте → Забрал → На месте → Вручил; после «вручено» контакты исчезают.
- **У нас:** для брони-посылки водитель жмёт: **«Забрал посылку» → «Вручил посылку»**. Реализация — расширить существующий механизм `driver_phase` (эндпоинт `/bookings/{id}/driver-status`, `bookings.py`) значениями `picked_up`/`delivered` для parcel-броней. Отправителю — двуязычные пуши: «Посылка у водителя», «Посылка доставлена» (хелпер `send_push_bi` уже есть, PR #95). В карточке активной поездки-посылки — свои кнопки вместо «выехал/подъезжаю».

### 5.2 ⭐ Код вручения — P1 (Фаза A, почти бесплатно)
- **У Яндекса:** СМС-код получателю; курьер вводит код — только тогда «вручено».
- **У нас:** **`boarding_code` уже существует** (код посадки в каждой брони). Переиспользуем: отправитель сам сообщает код получателю (звонком/смс — мы не шлём смс, экономим и не собираем лишний телефон). Водитель при передаче вводит код → `POST /bookings/{id}/deliver {code}` сверяет с `boarding_code` → статус «вручено» + пуш отправителю. Честное «доставлено», ноль новой инфраструктуры.

### 5.3 ⭐ Трекинг-ссылка получателю (без приложения) — P1 (Фаза B, самый большой кусок)
- **У Яндекса:** получателю уходит ссылка; в браузере — карта с курьером, имя, транспорт, ETA, звонок/чат. Отправители называют это главной любимой фичей.
- **У нас:** всё сырьё есть: live-позиция водителя (WS-реле `/ws/trip/...`), ETA, механика шеринга третьему лицу (`TripShare` — «поделиться поездкой с близким»), лендинг `web/` (Next.js на yulbash.ru). Делаем: отправитель в активной поездке жмёт «Ссылка для получателя» → сервер выдаёт токен-ссылку `yulbash.ru/t/<token>` → страница в браузере: карта (Яндекс JS-карта или статик), точка водителя (обновление поллингом раз в ~10 сек — без WS проще), «Ильдар везёт вашу посылку · ≈40 мин», статус (забрал/в пути/вручено).
- **Приватность (§8):** токен случайный, живёт только пока бронь активна (позицию мы и так чистим по завершении — уже сделано), телефоны не показываем, точность позиции можно огрубить до ~200 м. Работает и для ОБЫЧНЫХ поездок — «маме ссылку, что я еду» (замена/апгрейд `TripShare`-СМС).

### 5.4 Список «что нельзя передавать» — P1 (Фаза A, текст)
- **У Яндекса:** запрещёнка, штраф отправителю 10 000 ₽; курьер за содержимое запечатанного не отвечает.
- **У нас:** экран создания посылки — свёрнутый блок «Что нельзя передавать» (оружие, запрещённые вещества, деньги/документы чужие, хрупкое без упаковки…) + строка «Водитель не отвечает за содержимое; передача — на доверии между своими». Двуязычно. Это и юр-щит, и честность.

### 5.5 Фото «оставил у двери» — P3
- **У Яндекса:** фото как подтверждение.
- **У нас:** фото в чат уже можно (`uploadChatPhoto`). Достаточно подсказки в UI «оставил не лично в руки — сфоткай в чат». Отдельную кнопку не делаем.

### 5.6 Памятка «получатель не отвечает» — P2 (текст)
- **У Яндекса:** формальный алгоритм звонков + возврат с оплатой обратной дороги.
- **У нас:** без формальных возвратов (это договорённость своих): подсказка в активной посылке — «Не дозвонился получателю? Напиши отправителю в чат, решите вместе». Плюс совет отправителю при создании: «Предупреди получателя и передай ему код».

### 5.7 «Отблагодарить водителя» (чаевые) — открытый вопрос
- **У Яндекса:** чаевые через сервис, 100% курьеру.
- **У нас:** денег платформа не трогает. Вариант «на доверии»: после «вручено»/«поездка завершена» — экран оценки + кнопка «Сказать рәхмәт ❤️» (опционально показывает реквизиты СБП водителя, если тот их указал). Спорно (телефон = реквизит СБП → приватность). **Решение за Александром — см. §7.**

## 6. ЧТО НЕ БЕРЁМ (и почему — чтобы не возвращаться)

| Фича Яндекса | Почему нет |
|---|---|
| Комиссия с заказа, «плата за ПО» | Монетизация Юлдаша — донаты/буст/реклама. 0% — наше главное преимущество |
| Surge-цены (повышающий коэффициент) | Накрутка в час пик — против «между своими». Цену ставит водитель |
| Приоритет с минус-баллами, автоприём, блокировки за отмены | Кнут. Водители Яндекса это ненавидят — мы на этом растём |
| Уровни Бронза/Серебро/Золото/Платина | Соревновательная иерархия чужда «своим». Берём только бейджи-пряники (§4.7) |
| Скрытие точки Б / цены до принятия | Анти-ценность. У нас прозрачность — манифест (§2) |
| Регулярный фотоконтроль, селфи-проверки | Friction без нужды на нашем масштабе. Разовой проверки достаточно |
| Подменные номера (телефония) | Дорого (аренда номеров/телефония). Наш ответ уже работает: телефон скрыт до подтверждения брони + чат в приложении |
| Запись звука «Конфликт» | 152-ФЗ, согласие на запись — юр-минное поле. Наш вариант — §4.8 без записи |
| Страховка поездок/посылок, наложенный платёж | Требует юрлица и договоров со страховой. После юрлица — можно вернуться |
| Слоты с гарантией в час, гарантии дохода, персональные бонусы | Платформа не платит водителям — нечего гарантировать. Не наш формат |
| Мультизаказы/мультиточки с оптимизацией маршрута | Сложный роутинг. Несколько посылок = несколько броней на одну поездку — уже возможно без оптимизатора |
| Очередь аэропорта, Заправки, Карта Про, налоги ФНС, путевые листы | Экосистема корпорации. Не наш масштаб и не наша боль |
| Платное ожидание, таксометр | Попутки — не таксометр: цена договорная и видна заранее |

## 7. Открытые вопросы (решает Александр)

1. **Посылка и места:** посылка занимает пассажирское место (`seats`) или едет «нулевым местом»? Сейчас бронь-посылка списывает место. Предлагаю: маленькая (S) — не занимает, M/L — занимает 1. Нужно твоё слово.
2. **«Сказать рәхмәт» с реквизитами СБП водителя** (§5.7) — делаем или нет? Плюс: мотивация водителей. Минус: телефон-реквизит = приватность, и мы «почти трогаем» деньги.
3. **Отдельная вкладка «Посылки»** в нижней навигации или посылки остаются категорией внутри «Поездок»? Предлагаю пока категорией (5 вкладок уже заняты), но с заметным фильтром.
4. Точность позиции на трекинг-ссылке: точная или огрублённая (~200 м)? Предлагаю огрублённую до статуса «забрал», точную после.

## 8. Поэтапный план (каждая фаза = зелёная сборка, ничего не ломаем)

### Фаза A — «Посылки: честный статус» (бэкенд + немного UI; ~1 заход)
1. `driver_phase` += `picked_up`/`delivered` для parcel-броней (`bookings.py`, валидация по категории поездки).
2. `POST /bookings/{id}/deliver {code}` — вручение по коду (сверка с `boarding_code`), идемпотентно.
3. Пуши отправителю: «Посылка у водителя» / «Посылка доставлена» (`send_push_bi` + deep-link `data` — уже есть с PR #95). Черновой башкирский → `tasks.md`.
4. UI активной поездки-посылки: кнопки «Забрал посылку»/«Вручил (ввести код)» вместо «выехал/подъезжаю»; блок «код вручения» у отправителя с подсказкой «передай код получателю».
5. Экран создания посылки: блок «что нельзя передавать» + дисклеймер (§5.4). Тесты бэкенда на статусы/код.

### Фаза B — «Трекинг-ссылка получателю» (бэкенд + web/; самый ценный кусок)
1. Бэкенд: `POST /bookings/{id}/track-link` → токен (реюз идеи `TripShare`); `GET /track/{token}` — публичный JSON (статус, огрублённая позиция, ETA, имя водителя, маршрут A→Б) — только пока бронь активна.
2. `web/`: страница `yulbash.ru/t/<token>` — карта + статус + ETA, поллинг ~10 сек, двуязычная, мобильная. Никаких телефонов.
3. UI: кнопка «Ссылка для получателя» в активной посылке (и «Поделиться поездкой» для обычных — апгрейд TripShare).
4. Приватность-гейты: токен умирает по завершении; позиция уже чистится (сделано).

### Фаза C — «Кабинет водителя 2.0» (можно параллельно с B — разные файлы)
1. «Еду домой»: направление водителя + фильтр ленты заявок + пуш о подходящей заявке (§4.1).
2. Статистика-дневник (§4.3): эндпоинт-агрегат + экран.
3. Быстрые ответы-чипы в чате (§4.2).
4. Манифест «Почему водители выбирают Юлдаш» на лендинг + онбординг (§2).

### Фаза D — полировка (по одному, без спешки)
Бейдж «Новичок» (§4.5) · скользящий рейтинг (§4.6) · «Диагностика откликов» (§4.4) · достижения (§4.7) · кнопка «Проблема с поездкой» (§4.8) · «спрос без surge» (§4.9) · памятки (§5.6).

**Порядок внедрения:** A → B и C параллельно → D. Но СНАЧАЛА — текущие гейты из `launch-readiness.md` (деплой #95, сборка #96, 5 UX-блокеров, тест пуша на телефоне): фундамент раньше пристройки.
