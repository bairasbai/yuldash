## Почему пороги разные, а не «80% везде»

Общий процент в Compose-проекте почти ничего не значит. Девять из десяти строк байткода —
это рисование экранов: отступы, цвета, анимации. Гнаться за общим процентом значит писать
тесты на кнопки — работа есть, пользы нет.

Поэтому меряем **раздельно**:

- **Слой данных** — сеть, деньги, токены, паспорт поездки, очередь без сети. Ошибка здесь —
  «пассажир заплатил дважды» или «телефон водителя утёк». Планка как в любой взрослой
  компании.
- **Экраны** — низкая планка сознательно. Их правда проверяют глаза и живой прогон на
  телефоне, а не число в отчёте. Контентные тесты (`*ContentTest`) закрывают главное:
  что надпись на месте и на двух языках, что состояния «загрузка / пусто / ошибка» есть.

> Число «25% по всему приложению» само по себе ни о чём не говорит: экраны покрыты на 19%
> и весят девять десятых кода, поэтому общий процент — это в основном они. Смотри на строку
> «слой данных» — она про то, что ломается тихо.

## Как гонять

**Бэкенд:**
```bash
cd backend && python -m coverage run --source=app -m pytest -q && python -m coverage report
```
`coverage report` вернёт ненулевой код, если упали ниже 85% (`.coveragerc`).
Подробный разбор по строкам — `python -m coverage html` → `htmlcov/index.html`.

**Приложение:**
```bash
cd android && ./gradlew.bat :app:jacocoCoverageVerification
```
Задача сама прогоняет тесты, строит отчёт и падает, если покрытие ниже порога.
Отчёт глазами — `app/build/reports/jacoco/jacocoTestReport/html/index.html`.
`./gradlew check` теперь тоже включает эту проверку.

**Оба порога проверяет CI на каждый push** (`.github/workflows/ci.yml`): бэкенд —
`--cov-fail-under=85`, приложение — `jacocoCoverageVerification`. Порог, который гоняют
только руками, — не порог: его забудут ровно в тот раз, когда он был нужен. Число в CI
и в `backend/.coveragerc` должно совпадать.

## Что считается хорошим тестом в этом проекте

1. **Название — на русском, человеческим языком.** `` `обрыв связи показывает ошибку, а НЕ «заявок пока нет»` ``
   читается в отчёте как предложение. Александр должен понять, что сломалось, не открывая код.
2. **В комментарии — цена ошибки, а не механика.** Не «проверяем парсинг JSON», а «пассажир
   на перевале останется без телефона водителя».
3. **Проверяем поведение, а не реализацию.** Тест не должен падать от переименования приватного
   метода.
4. **Плохой путь важнее хорошего.** Нет сети, 500 от сервера, битый JSON, отозванное разрешение,
   двойное нажатие — вот где живут настоящие баги.

## Четыре сторожа, которые ловят целые классы ошибок

Обычный тест проверяет одно место. Эти четыре проверяют **правило по всему коду сразу** —
поэтому они ценнее сотни точечных.

### 1. Адреса приложения и сервера не разъезжаются
`backend/tests/test_api_contract_android.py`

Читает `ApiClient.kt`, вынимает все адреса и сверяет со списком маршрутов FastAPI.
Переименовали ручку на сервере, забыли в приложении — тест краснеет **до** того, как кнопка
начнёт молча возвращать 404.

### 2. Каждая ручка идёт куда задумано
`android/…/data/ApiClientEndpointContractTest.kt`

178 ручек, у каждой проверены метод, адрес, разбор нормального ответа и то, что ответ 500
превращается в ошибку, а не в «пустой успех». До этого теста их адреса не проверял никто.

### 3. Единый стиль
`android/…/CanonSourceGuardTest.kt`

Читает исходники экранов и падает, если кто-то написал свой размер шрифта, отступ, радиус
или длительность анимации мимо шкал `Canon*`. Правила — [design.md](design.md).

### 4. Двуязычие
`android/…/BilingualSourceGuardTest.kt`

Не даёт приложению заговорить по-русски там, где обещан башкирский: ловит пустое башкирское
поле, русский текст мимо `appText` и рост числа надписей, где башкирский — это копия русского.
Сегодняшний долг (143 надписи) зафиксирован планкой: 144-я уронит сборку. Список слов
на перевод — в [tasks.md](tasks.md), самый верх.

## Нагрузка

`backend/loadtest/locustfile.py`, инструкция — [loadtest/README.md](../backend/loadtest/README.md).

```bash
cd backend/loadtest && locust -f locustfile.py --host http://STAGING:8000 \
  --headless --users 150 --spawn-rate 30 --run-time 2m
```

Вердикт печатается в конце, код выхода ≠ 0 при p95 > 300 мс или доле ошибок > 1% —
можно вешать в CI.

**Гонять только против staging.** Против прода — никогда: там живые брони и настоящие SMS.

## Чего покрытием не измерить

Тесты не заменяют живую проверку. Перед пометкой «готово» по-прежнему нужны:

- прогон на эмуляторе глазами (тёмная тема, башкирский, узкий экран);
- проверка на реальном телефоне для всего, что про железо: пуши, GPS, скорость запуска;
- два телефона для сценариев «водитель ↔ пассажир» — их не подделать ни одним тестом.
