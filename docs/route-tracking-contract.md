## 1. Live-позиция участников (Фаза 2) — главное

### Принципы приватности (требование Александра)
- Точное гео участника передаётся **ТОЛЬКО когда поездка активна** (`booking.status ∈ {confirmed, onboard}`).
- До подтверждения и после `done/cancelled` — поток координат запрещён, last-position удаляется.
- Видят друг друга только **два участника одной брони** (водитель ↔ пассажир). Никто третий.

### WebSocket-канал (на инфре чата + Redis pub/sub)
```
WS  wss://yulbash.ru/ws/trip/{booking_id}/location
```
- Первое сообщение от клиента: `{"type":"auth","token":"<jwt>"}` (как в чате).
- Сервер проверяет: токен валиден И юзер — участник брони `booking_id` И `booking.status ∈ {confirmed,onboard}`. Иначе close(4403).

**Клиент → сервер (раз в 5–10 c, пока активная поездка на экране):**
```json
{"type":"loc","lat":53.9306,"lng":58.3142,"bearing":270.0,"ts":1751270400}
```
- `bearing` (0–360, опц.) — куда смотрит машина, для поворота иконки.

**Сервер → другому участнику (рассылка через Redis между воркерами):**
```json
{"type":"loc","role":"driver","lat":53.93,"lng":58.31,"bearing":270.0,"ts":1751270400}
```
- `role`: `"driver"` | `"passenger"` — клиент рисует нужную иконку.
- Рассылать ТОЛЬКО другому участнику той же брони.

**Хранение:** last-position на бронь в Redis, ключ `trip:loc:{booking_id}:{role}`, **TTL 60 c**.
При подключении второго участника — сразу отдать последнюю известную позицию первого (чтобы маркер не ждал тика).

**Очистка:** при `driver-status=done` / `/bookings/{id}/cancel` → удалить оба ключа `trip:loc:{booking_id}:*`, закрыть WS-сессии канала.

### Статусы поездки через WS (бонус, чтобы UI обновлялся без push)
В этом же канале сервер шлёт смену статуса:
```json
{"type":"status","status":"departed"}   // departed|arriving|onboard|done|cancelled
```
Клиент мгновенно обновит экран активной поездки (сейчас зависит от push).

## 2. Заявки пассажиров на карте (Фаза 3, часть «1.3»)

Чтобы водитель видел на карте, кто рядом ищет попутку.

### Модель: `RideRequest` — добавить координаты
```
from_lat: Optional[float]   # геокодить from_city при создании заявки (geocode_city, уже есть)
from_lng: Optional[float]
to_lat:   Optional[float]
to_lng:   Optional[float]
```
Заполнять в обработчике `POST /requests` тем же `geocode_city`, что и поездки.

### Эндпоинт радиус-поиска заявок (зеркало `/rides/near`)
```
GET /requests/near?lat=X&lng=Y&radius_km=N[&to_city=...]
→ {count, items: [RideRequestOut{id, from_city, to_city, from_lat, from_lng, seats, max_price, distance_km, passenger_name}]}
```
- PostGIS `ST_DWithin` по `from_lat/lng` (фоллбэк haversine), как у `/rides/near`.
- Приватность: отдаём город/точку отправления заявки (это и есть «откуда нужна попутка»), без личного адреса/телефона.

Клиент покажет такие заявки отдельным маркером («ищет попутку»), тап → карточка заявки.
