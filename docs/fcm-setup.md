# 🔔 Push-уведомления (FCM) — как настроить (для Александра)

> FCM = Firebase Cloud Messaging, бесплатный сервис Google. Сервер шлёт телефону уведомление
> (новое сообщение в чате, бронь, SOS) даже когда приложение закрыто.
> Код регистрации и отправки есть: [сервер](../backend/app/services.py#L452), [регистрация устройства](../backend/app/routers/auth.py#L1439), [Android](../android/app/src/main/java/com/yuldash/app/data/FcmService.kt). Это не подтверждение доставки на конкретный телефон. По последней ограниченной приёмке INTEGRATION-20261106 живой телефонный прогон остаётся отдельным открытым пунктом [реестра](audit-blocks.md).
>
> Запись о настройке Firebase от 28.06.2026 — историческая. Наличие и актуальность ключей на сервере и в локальной машине при этой уборке не проверялись. Результаты сборки и инициализации SDK не заменяют настоящее уведомление на телефон.
>
> Ключи размещает владелец вручную. Агенту их не присылать: по [§11 AGENTS.md](../AGENTS.md) запрещено читать, копировать, связывать ссылками и удалять файлы ключей; в Git они не попадают.

## Зачем
Цель — уведомить о брони/сообщении/SOS вне открытого приложения. Фактическая доставка зависит от настроек, разрешения Android и регистрации конкретного устройства; проверяется отдельным реальным сценарием.

---

## Твои шаги (нужен Google-аккаунт, ~10 минут)

### Шаг 1. Создать проект
1. Открой **console.firebase.google.com** → войди Google-аккаунтом.
2. **«Создать проект»** → название **`Юлдаш`**.
3. Google Analytics можно **выключить** (не нужен) → «Создать».

### Шаг 2. Добавить Android-приложение
1. В проекте нажми иконку **Android** (Добавить приложение).
2. **Имя пакета:** `com.yuldash.app` (важно, точь-в-точь).
3. Псевдоним: `Юлдаш`. SHA-1 — пока **пропусти** (не обязателен для push).
4. **«Зарегистрировать приложение»**.

### Шаг 3. Скачать `google-services.json`
1. Firebase предложит скачать **`google-services.json`** → скачай.
2. Дальше шаги «добавить SDK» — **пропусти** (это сделаю я). Жми «Далее» до конца / закрой.

### Шаг 4. Ключ для отправки с сервера
1. ⚙️ (шестерёнка вверху) → **«Настройки проекта»** → вкладка **«Сервисные аккаунты»**.
2. **«Создать закрытый ключ»** (Generate new private key) → скачается **JSON-файл** (большой, с `private_key`).

---

## Как обращаться с файлами настройки

Файл настройки Android и сервисный ключ Firebase размещает Александр либо назначенный владелец через свои средства. Не отправлять их в чат или в Git. Агент не читает и не переносит эти файлы; для локальных проверок использует допустимую конфигурацию без копирования ключей. Изменение сервера выполняется отдельно по §8.

## Безопасность
Оба файла — секреты (особенно сервисный ключ: он позволяет слать пуши от имени проекта). В git НЕ кладу, как токен бота. Если светанул — перевыпустишь в тех же «Сервисных аккаунтах».

## Что уже есть в коде и что проверять отдельно
- Android: Firebase SDK + плагин, `FirebaseMessagingService` (приём + показ уведомления), запрос разрешения `POST_NOTIFICATIONS` (Android 13+), регистрация токена устройства → на сервер.
- Сервер: таблица токенов устройств, отправка пуша через FCM при новом сообщении / брони / SOS (Firebase Admin SDK + сервисный ключ).
- Отдельно проверить доставку реального уведомления на телефон: нужный участник, открытое/закрытое приложение, разрешение уведомлений. До фактического прогона не называть этот шаг закрытым.
