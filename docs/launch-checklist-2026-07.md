## ✅ ГОТОВО в коде — production-grade (проверено)

### Надёжность и деньги
- Деньги — только целые копейки (`int`), комиссия через `Decimal ROUND_HALF_UP` (без float-дрейфа).
- Критичные операции (бронь мест, приём заказа/посылки, списание долга, активация платежа) — под `SELECT … FOR UPDATE`, идемпотентны. Проверено на **реальном Postgres** тестом гонки потоков.
- `UNIQUE(commissiondebt.order_id)` — двойной «завершить» не задваивает комиссию.
- Долг/комиссия гасятся только по снапшоту суммы — не «прощаются» бесплатно в окне оплаты.
- Все внешние вызовы (FCM, SMS, ЮKassa, Redis, геокодер, S3) обёрнуты — сбой провайдера не роняет запрос (мягкая деградация).

### Безопасность и приватность (152-ФЗ)
- Секретов в git нет; `.gitignore` покрывает `.env`, `local.properties`, `*.jks`, `google-services.json`.
- `validate_production()` **падает на старте**, если в проде остались dev-дефолты (слабый JWT-секрет, CORS `*`, mock-платежи без ключей и т.д.) — защита от «случайно выкатили небезопасное».
- JWT HS256 с явным алгоритмом, refresh — одноразовая ротация; logout бьёт REST и WebSocket.
- IDOR закрыт (проверка владельца/участника за каждым доступом по id); админ-эндпоинты — только админам.
- Телефоны и точные координаты — только после accept; в открытых списках гео округлено (~1 км); TTL у live-ссылки поездки; чувствительное не логируется в проде.
- Rate-limit (общий + строгий на `/auth`, `/sos`, `/donate`); антифрод по гео-телепортам.

### Инфраструктура
- Пул БД настроен под нагрузку: `pool_pre_ping`, `pool_recycle=1800`, лимиты соединений под воркеры.
- Миграции alembic — одна линейная голова (`w3_release_hardening`); в CI прогоняются на настоящем Postgres (upgrade/downgrade).
- Наблюдаемость: Sentry (+ асинхронный интегратор), единый логгер с уровнями, дневная сводка.
- CI: `backend-tests` (SQLite, coverage-gate 70%) + `backend-tests-postgres` (реальный Postgres, FK+гонки) + `android-build` (реальный компилятор Kotlin) — **все блокирующие, зелёные**. Линтер ruff.

### Клиент (Android)
- Все три профиля (попутка, такси, курьер) — полный набор состояний (загрузка/пусто/ошибка+повтор), 401 → перелогин централизованно.
- Дизайн ~8.5/10: единый `UiKit` и токены `Canon*`, тёмная тема, доступность (тач-цели ≥48dp, `sp`, contentDescription), анимации, двуязычие RU/BA.
- Сборка: `applicationId`, R8/`minify`, `shrinkResources`, обе ABI (`arm64-v8a` + `armeabi-v7a`), безопасные дефолты без секретов, HTTPS-only в релизе.

## 🔴 ОСТАЛОСЬ за Александром — блокеры публикации (кодом не решаются)

1. **Ключ подписи (keystore).** Создать `*.jks` + `keystore.properties` (вне git). Без него `assembleRelease` даёт **неподписанный** APK — публиковать нельзя. Ключ беречь: потеря = невозможность обновлять приложение.
2. **`google-services.json`** положить в `android/app/`. Без него push (FCM) и Analytics молча выключены (краша нет). Firebase уже настроен на проде — нужен только файл.
3. **Юридическое (152-ФЗ + требования сторов):**
   - URL политики конфиденциальности (нужен и для Google Play, и по 152-ФЗ);
   - согласие на обработку персональных данных;
   - заполнить в сторе **Data Safety** (телефон, геолокация, аудио) + возрастной рейтинг (IARC).
4. **Аккаунт разработчика** Google Play ($25 разово) и/или RuStore.
5. **Графика для карточки стора:** иконка 512×512, feature graphic 1024×500, 4–8 скриншотов (тексты карточки — в `docs/store-listing.md`, черновик готов).
6. **Тест на 2 реальных телефонах** (`docs/e2e-2phones-checklist.md`): особенно **live-трекинг поездки** и **доставка FCM-пуша** — их ядро ни разу не проверялось вживую, только на эмуляторе/в коде. Плюс финальный smoke именно release-APK на arm-телефоне.
7. **Бизнес-решения (вне кода):** когда включать флаги `TAXI_ENABLED` / `COURIER_ENABLED` (+ города), провайдер платежей `payments_provider` (mock → sbp_manual → yookassa по мере готовности документов ЮKassa), стартовый город, юрлицо/самозанятость, финальные тарифы.

## Как выкатывать (когда пункты 🔴 закрыты)
1. Влить PR #73 в `main` (вся волна одной веткой).
2. На сервере: `alembic upgrade head`.
3. Собрать подписанный release-APK/AAB (keystore на месте).
4. Включать флаги (`TAXI_ENABLED`, `COURIER_ENABLED`, `payments_provider`) по мере готовности — по одному, не всё разом.
5. Задать `REVIEW_PHONE`/`REVIEW_CODE` для модерации сторов.
