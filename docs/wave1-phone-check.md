# Проверка попуток на двух телефонах — волна 1

> 13.10.2026, сверено21.10.2026 по ветке `codex/rideshare-parity-20261018`, код957bf60f. Это инструкция будущего прохода; в adb21.10 нет устройств, E2E-07 не закрыт. Посадку отмечает водитель; добавлены две остановки и различение полного рейса/участка в квитанции. Ты — **водитель** (телефон А), знакомый — **пассажир** (телефон Б). Время прохода зависит от ожидания разрешённой посадки и пути до промежуточной остановки.
> Для ссылки «близкому» нужен третий экран — твой компьютер или любой телефон с браузером.

## Перед началом

1. **Версии трёх частей совпадают с проверяемыми правками:** сервер, PWA и Android. Укажи отдельный коммит каждой части: код957bf60f находится в рабочей ветке, наличие его на GitHub ещё не означает выкладку. Порядок выкладки — `release-runbook.md`; слияние и выкладка требуют отдельного поручения Александра. Без актуального сервера/сайта телефонный проход не доказывает поведение этой версии.
2. **На обоих телефонах — та подписанная сборка, что пойдёт в магазин**, и ходит она на `yulbash.ru` (не на компьютер). Собирает её Александр на своём ноутбуке из принятого коммита, который содержит проверяемые правки: ключ подписи только там (`docs/release-runbook.md`, «Как Александр собирает подписанный релиз», п. 1–4), APK ставится на телефоны руками. Отладочная локальная сборка и неподписанный файл проверки R8 не заменяют этот APK. Инструкция сборки из `main` применима после включения принятой ветки в `main`; пока ветка не включена, сборка старого `main` не содержит новых правок.
3. **На обоих телефонах есть Telegram** — вход идёт через бота.
4. Включи на телефонах время в строке состояния: по нему потом легко найти запись на сервере. Разреши уведомления в Android и PWA; если их нельзя включить, отметь фоновую доставку как непроверенную.
5. Запиши версию Android, версию установленной PWA и версию сервера. Для изменений18.10 сервер должен поддерживать обе точки брони и квитанции; один push ветки этого не обеспечивает. Состояние выкладки здесь не подтверждается. Основной проход сделай с Android-пассажиром и PWA-водителем, затем на новой поездке поменяй клиенты ролями; результаты фиксируй раздельно.

«Сел» сервер принимает не раньше чем за30минут до начала всего рейса; отдельного сдвига по промежуточной остановке у этой проверки нет. Для «Подъезжаю» время пути до известной промежуточной остановки учитывается отдельно — дождись разрешённого срока. Посадку отмечай только при фактической встрече; разрешённая по времени кнопка не означает, что человек уже в машине. Основания: `backend/app/routers/bookings.py:1195` и `:1011`.

## Что ещё входит в полную приёмку

- На новой поездке повтори путь через заявку пассажира: водитель «По пути» → выбирает уже существующий рейс → отклик → принятие → посадка/завершение/обе квитанции. Второго рейса и второго списания места быть не должно.
- На отдельных поездках: отказ водителя, отмена до/после подтверждения, последнее место, неверный порядок остановок, неявка, отмена ошибочной посадки в показанное окно. После настоящей посадки неявка недоступна.
- На отдельных шагах теряй сеть, закрывай процесс и повторяй действие: бронь/подтверждение/посадка/завершение и сообщение не должны дублироваться; код после посадки не возвращается, выбранные точки сохраняются.
- Проверь посторонний аккаунт, выход, отзыв ссылки близкому и окончание её видимости после завершения; после прежнего окна контактов водитель не получает личный участок. Старую неизвестную высадку приложение не должно придумывать.
- Отдельно зафиксируй RU/BA и обе темы, крупный шрифт; реальные FCM, GPS/карта при свёрнутом приложении и сигнал SOS. Текущие локальные доказательства и незакрытые критерии — `audit-blocks.md`, W1-E2E-20261018. Один удачный основной проход не закрывает эти варианты автоматически.

**Если ты ещё не проверенный водитель** (нет бейджа «Проверен»): до шага 1 отправь в приложении фото прав и машины, потом в Telegram-боте нажми ✅ под сообщением «Проверка водителя». На телефоне А должно прийти «Документы проверены», а у Б в ленте у твоей поездки — бейдж «Проверен».

## Как отметить результат

Для каждой связки клиентов отдельно запиши шаг, время, «прошёл / ошибка / не проверен», номер своей поездки и снимок без лишних личных данных. Пропущенный шаг не равен успешному. После основного пути отдельно пройди заявку и отказы из списка выше; один результат не подставляй вместо другого.

Новый выбор даты/времени проверь на русском и башкирском, в обеих темах: клавиатура не закрывает активное поле, 24:60 нельзя сохранить, правильные дата/время остаются после повторного открытия. Для SOS без места координат и копирования точки нет; после точного разрешения/повтора появляется свежая точка, после отзыва разрешения она исчезает. Новые башкирские формулировки в `tasks.md` пока требуют проверки Александром.

Основания инструкции21.10: Android обычный старт — `android/app/src/main/java/com/yuldash/app/AppStart.kt:16`; публичная ссылка — `android/app/src/main/java/com/yuldash/app/YuldashApp.kt:661`; доступные гостю PWA-маршруты — `webapp/src/App.tsx:249`; текст SOS — `android/app/src/main/java/com/yuldash/app/SosVerifyScreens.kt:756` и `webapp/src/screens/SosScreen.tsx:354`; постановка Telegram-уведомления в фон — `backend/app/routers/safety.py:348`. Это источники ожидаемого поведения, а не доказательство телефонного прохода. Проверенные здесь локальные результаты — только W1-E2E-20261018 в `audit-blocks.md`.

## Если что-то не так

- **Сделай снимок экрана** именно того телефона, где не так, — чтобы было видно время в строке состояния.
- Запиши: **номер шага**, кто (А или Б), что нажал и что увидел вместо ожидаемого.
- Снимок ссылки у мамы — тоже снимок экрана браузера (адрес ссылки можно закрыть пальцем: по нему видно поездку).
- Пришли всё Claude одним сообщением. Повторять шаг не нужно — по времени на снимке мы найдём запись на сервере.

## Для разработчика: как прогнать те же пути без телефонов

Пять прежних путей (PATH-01/02/03/12/13) — тесты `backend/tests/journeys/`: каждый шаг обращается к настоящим серверным обработчикам по HTTP. Вход подготовлен синтетическим запросом вебхука Telegram; настоящий мессенджер и доставку кодов эти тесты не проверяют (`backend/tests/journeys/conftest.py`). Они не заменяют телефонный проход выше.

```bash
cd backend
python -m pytest tests/journeys -q                      # в процессе, на SQLite (входит в общий прогон)
DATABASE_URL=postgresql+psycopg2://…/db python -m pytest tests/journeys -q   # на PostgreSQL
```

Против живого сервера по сети: запусти `uvicorn app.main:app` с `ENV=dev`, `RATE_LIMIT_ENABLED=false`, `ADMIN_PHONES=<номер админа>`, **`SMS_PROVIDER=mock`** (путь близкого шлёт SMS на выдуманные номера — с настоящим провайдером они ушли бы чужим людям) и **пустым `TELEGRAM_WEBHOOK_SECRET`** (тесты играют за бота без секрета). Базу — только временную, не прод. Лог сервера пиши в файл. Затем:

```bash
JOURNEY_BASE_URL=http://127.0.0.1:<порт> JOURNEY_SERVER_LOG=<лог сервера> \
JOURNEY_ADMIN_PHONE=<тот же номер> python -m pytest tests/journeys -q
```

### Проверка на эмуляторе (когда нет телефона)

Тот же путь можно пройти на эмуляторе: свой сервер на временной PostgreSQL 16 (`ENV=dev`, `SMS_PROVIDER=mock`, пустой `TELEGRAM_WEBHOOK_SECRET`), `adb reverse tcp:8000 tcp:8000`, debug-сборка с `YULDASH_DEBUG_API_BASE_URL=http://127.0.0.1:8000`. Бота играет вебхук (как в `backend/tests/journeys`). Подвохи и обходы — `docs/lessons.md`, раздел «Проверка на эмуляторе без телефона…». Сборка без `local.properties` теперь проходит весь путь: имя бота имеет дефолт, карта без ключа показывает заглушку.

### Проверка сжатой сборки без ключа подписи

Из своей папки `android/`, с JAVA_HOME/ANDROID_HOME из §5 `AGENTS.md`:

```powershell
.\gradlew.bat :app:assembleRelease '-Pyuldash.unsignedRelease' --no-daemon
```

Кавычки вокруг аргумента с точкой нужны в PowerShell. Этот режим проверяет сборку и сжатие R8, но даёт неподписанный файл: устанавливаемую версию для двух телефонов Александр собирает отдельно. Адрес сервера и отсутствие отладочного режима проверяются по результату сборки, а не по имени APK. Никакого телефонного прохождения или доставки уведомлений эта команда не доказывает.
