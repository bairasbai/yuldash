## 1. Что такое Юлдаш

**Юлдаш** (башк. «спутник, попутчик») — мобильное приложение поездок **«между своими»**
для Республики Башкортостан. Слоган: **«Поездки между своими»**.

**Ключевая идея, отличающая от агрегаторов:** это не такси-агрегатор, а сеть доверия между
соседями. Продукт строится вокруг трёх вещей:

- **Доверие** — уровни «свой», бейджи проверки, инвайты, рейтинги, история поездок.
- **Безопасность** — SOS, «поделиться поездкой с близким», код посадки, скрытый номер,
  зимний протокол «ты доехал?», фильтр «женщинам — водитель-женщина».
- **Локальность** — сёла и райцентры Башкортостана, а не мегаполисы; двуязычие
  **русский + башкирский**; сценарии, которых нет у конкурентов (довезти лекарство бабушке,
  поездка к клинике, ориентиры вместо адресов «у мечети, синие ворота»).

**Эталоны по качеству UI:** Яндекс Такси, inDrive, Uber, Maxim — но приложение должно
выглядеть **дороже и спокойнее** конкурентов, а не быть их копией.

**Публичный адрес:** `https://yulbash.ru` (лендинг + API на одном домене).

## 3. Четыре продукта в одном приложении

Юлдаш — это не один сценарий, а четыре потока, живущие в одном приложении и на одном бэкенде.
**Важно:** они намеренно разделены на уровне данных и правил — блокировка такси не трогает попутку.

### A. Попутка (rideshare) — ядро, работает всегда
Плановые поездки между населёнными пунктами. Водитель публикует маршрут → пассажиры бронируют.
Или наоборот: пассажир создаёт заявку → водители откликаются (с торгом о цене).
Сущности: `Ride`, `Booking`, `RideRequest`, `RequestResponse`.
**Бесплатно, комиссии нет, деньги платформа не трогает.**

### B. Такси («Быстрый заказ», instant) — за флагом `TAXI_ENABLED`
Классический сценарий «здесь и сейчас»: пассажир указывает А→Б → сервер считает цену →
matcher рассылает офферы водителям на линии → водитель принимает → подача → поездка → чек.
Сущность: `InstantOrder` (машина состояний). Есть предзаказ «на время», классы машин
(Эконом / Комфорт / Бизнес / Минивэн), сурж, комиссия по лесенке 3 → 5 → 8 %.
**Требует юр. оформления (580-ФЗ: служба заказа = ИП или ООО), поэтому по умолчанию выключен.**

### C. Курьер и посылки — за флагами `COURIER_ENABLED` / всегда (poputka)
Три подтипа доставки в одной сущности `ParcelDelivery`:
- `poputka` — «отправить с попутчиком» (любой попутчик берёт коробку по пути), работает всегда;
- `courier` — заказать профессионального курьера (только одобренным курьерам на линии);
- `buy_bring` — «купи и привези» (курьер тратит свои деньги на товар, получатель возвращает).

### D. Доступность и семья — всегда
Простой режим для пожилых, голосовая заявка, «заказ за близкого», заявка по звонку
(пассажир вообще без приложения — админ или автоподбор оформляет за него), доверенные контакты.

## 4. Роли пользователей

| Роль | Как получают | Что может |
|---|---|---|
| **Пассажир** | по умолчанию после входа | искать/бронировать поездки, создавать заявки, заказывать такси и доставку, чат, SOS, оценки |
| **Водитель попутки** | заполнил профиль водителя | публиковать поездки, отвечать на заявки, торговаться о цене, вести живую поездку |
| **Проверенный водитель** | загрузил документы → одобрил админ (`User.verified`) | бейдж «проверен», доступ к платным сценариям, выше в выдаче |
| **Таксист** | заявка `TaxiApplication` → одобрение админа | выход на линию, приём офферов, кабинет, заработок, долг по комиссии |
| **Курьер** | заявка `CourierApplication` → одобрение админа | выход на линию, приём доставок, кабинет курьера |
| **Партнёр (бизнес)** | регистрация в кабинете «Мой бизнес» → модерация | размещать купоны «Скидки по пути», реклама |
| **Админ** | телефон в `ADMIN_PHONES` (сравнение с кодом страны) | 19 админ-экранов: модерация водителей/курьеров/таксистов, споры, SOS, платежи, долги, тексты, отзывы, реклама, промокоды, пульс такси |
| **Ревьюер стора** | `REVIEW_PHONE` + `REVIEW_CODE` в `.env` | обычный пассажир, помечен `is_reviewer`; нужен для модерации Google Play / RuStore |

| **Яндекс MapKit** | `4.39.0-full` | карта, маркеры, линия маршрута, роутинг |

поломок сборки.

### Секреты и конфиг сборки

Ничего секретного в git не попадает. Значения читаются из `local.properties` (в `.gitignore`)
или переменных окружения и прокидываются в `BuildConfig`:

- `YANDEX_MAPKIT_KEY` — ключ карты;
- `YULDASH_DEBUG_API_BASE_URL` — адрес сервера для debug (по умолчанию `http://10.0.2.2:8000`
  = хост глазами эмулятора; для теста на живых телефонах задаётся переменной окружения);
- `YULDASH_RELEASE_API_BASE_URL` — `https://yulbash.ru`;
- `YULDASH_WEB_BASE_URL` — база для расшариваемых ссылок `yulbash.ru/r/{id}`;
- `YULDASH_SUPPORT_PHONE`, `YULDASH_TELEGRAM_BOT`, `YULDASH_VK_APP_ID`, `YULDASH_SENTRY_DSN`;
- `YULDASH_SMS_LOGIN` — вход по SMS заморожен, оживляется этим флагом.

**Ключ геокодера в APK намеренно отсутствует** — поиск адресов идёт через серверный прокси
`/geocode`, потому что APK распаковывается за минуту и `BuildConfig` хранит строки открытым текстом.

**Подпись релиза:** данные из `keystore.properties` (файл на месте, в git его нет). Нет файла —
сборка релиза **падает с инструкцией**, а не выдаёт молча неустанавливаемый APK. Исключение —
флаг `-Pyuldash.unsignedRelease` только для проверки R8 в CI.

**Release-сборка:** R8 (`minify` + `shrinkResources`), ABI `arm64-v8a` + `armeabi-v7a`
(без v7a дешёвые 32-битные телефоны ловят «Приложение не установлено»). Для AAB отключено
дробление по языкам — иначе Play выкинет «лишний» башкирский, а у нас свой рантайм-переключатель.

**Манифест — что изменилось в сентябре 2026:**
- Копии данных выключены дважды: старым `allowBackup="false"` и новым файлом-правилом
  `res/xml/data_extraction_rules.xml` (Android 12+ — ни в облако, ни на новый телефон).
  Внутри приложения лежат телефон, токен входа, история поездок и адреса.
- Ссылка на поездку `yulbash.ru/r/{id}`: Android подтверждает владение сайтом только по `https`,
  поэтому `http` вынесен **отдельным** intent-filter без `autoVerify`. Раньше обе схемы стояли
  в одном проверяемом фильтре — из-за этого проверка домена ломалась, и ссылка открывалась бы
  в браузере, а не в приложении.

### Архитектура клиента

```
MainActivity.kt (931 строка)  — общее ядро: enum Screen, HomeTab, LocalizedText, хелперы
   └── YuldashApp.kt (2423)   — корневой composable: when(screen) → ветка на каждый экран
          └── 90+ файлов экранов (по экрану/домену на файл)
   YuldashViewModel.kt        — состояние приложения (переживает поворот и смерть процесса)
   data/                      — сеть, сокеты, push, геокодер, монитор сети
   CanonTokens.kt (208)       — все дизайн-токены
   UiKit.kt (469)             — готовые компоненты
   AppText.kt                 — двуязычие
```

**Состояние — в `YuldashViewModel`** (`ViewModel` + `SavedStateHandle`), а не в `remember`
внутри composable. Причина описана прямо в коде: раньше поворот экрана на активной поездке
сбрасывал `selectedRide`/`activeTrip` в null и гард-редирект кидал на главный экран.
Переживают смерть процесса: `screen`, `language`, `startHomeTab`, `activeBookingId`.

⚠️ **`YuldashApp.kt` дописывать нельзя.** Функция настолько большая, что инструментовка
покрытия (JaCoCo) падает с `Unable to instrument file with Jacoco: YuldashAppKt.class`.
Проверено дважды: в августе — на вложенном блоке, 2 сентября — **на одной строке-аргументе**.
Новая логика уносится в отдельный экран или функцию; новая связь с `YuldashApp` — только
через то, что там уже есть.

**Самые крупные файлы** (строк, замер 2026-09-03): `data/ApiClient.kt` 6022,
`InstantOrderScreen` 4491, `ProfileScreen` 4102, `RidesRequestsChatScreens` 2845,

## 6. Навигация и все экраны

Навигация — **самодельная, без Navigation-Compose**: `enum Screen` (**91 значение**) +
гигантский `when` внутри `YuldashApp()` + back-stack в ViewModel.
Правило проекта: **новый экран = значение в `enum Screen` + ветка в `when` + строка в
`docs/architecture.md`**. Соответствие стережёт `tools/navcheck.py`.

**Пять вкладок главного экрана** (`enum HomeTab`): `Map` · `Rides` · `Request` · `Chat` · `Profile`.

### Полный список экранов (`enum Screen`)

**Вход и старт:** `Splash`, `Intro` (брендовое интро при первом запуске: морф «Попутчик»→«Юлдаш»,
слоган RU→BA), `Onboarding`, `Login`, `Home`.

**Попутка:** `CreateRide`, `Booking`, `ActiveTrip`, `CreateRequest`, `RequestsFeed`,
`RequestResponses`, `DriverResponses` (торг о цене), `RepeatTrip`, `RouteWatches`
(«карауль поездку»), `Filters`, `TripReceipt`, `DriverProfile` (публичный профиль водителя).

**Такси:** `InstantOrder` (пассажир), `InstantDriverTrip` (водитель), `InstantChat`,

## 9. Двуязычие RU + BA

**Железное правило:** любая видимая надпись — сразу на двух языках через хелпер
`appText(ru, ba)`. Односторонняя строка запрещена, держит тест `BilingualSourceGuardTest`.

- Переключение языка — рантайм (`AppLanguage`), не системные ресурсы. Поэтому в AAB
  **отключено дробление по языкам** (иначе Play выкинет башкирский).
- Ошибки сервера тоже двуязычные: ответ приходит как `{"detail": {"ru": "...", "ba": "..."}}`.
  Пишутся через хелпер `herr(код, «по-русски», «башҡортса»)`.
- **Башкирский, написанный моделью, — это черновик.** Складывается в `docs/tasks.md`
  (раздел «Переводы на проверку»), носитель (Александр) подтверждает. Очередь копится
  постоянно: за август-сентябрь добавились строки PWA, курьерских экранов, SOS и промо.
- Тон: на «ты», по-добрососедски, **одинаково в обоих языках**. Отдельным заходом исправлено
  45 мест, где башкирский говорил «вы», а русский «ты»; 13 мест оставлены вежливыми осознанно
  (обращение к обеим сторонам спора).

### Две планки-храповика (числа на 2026-09-03)

| Сторож | Планка | Что означает |
|---|---:|---|
| `BilingualSourceGuardTest` (Android) | **122** | столько мест, где в башкирское поле подставлен русский текст. Планка может только опускаться |
| `test_bilingual_errors_guard` (бэкенд) | **204** | столько ответов сервера с ошибкой пока только по-русски (админские не считаются). Новая односторонняя ошибка роняет прогон |

> **Поправка к версии 2026-08-12.** Там было написано, что серверная планка «опущена с 204

### Ключевые решения

- **Каждый роутер монтируется дважды:** на корень (`/rides` — так ходит живой клиент) и под
  версионным префиксом (`/api/v1/rides` — на будущее). Старые URL не ломаются.
- **В проде спрятана интерактивная схема** (`/docs`, `/redoc`, `/openapi.json`) — она раскрывала
  бы карту всех приватных admin/payment-эндпоинтов. В dev доступна.
- **Middleware по порядку:** RateLimit (отсекает раньше всего) → CORS → SecurityHeaders →
  AccessLog → DailyDigest.
- **Redis** — pub/sub для WebSocket между воркерами и GEO-присутствие водителей (TTL heartbeat
  60 с). Без Redis чат работает локально, а такси не работает вовсе.
- **Alembic** — 85 миграций, единственный путь изменения схемы. Индексы создаются
  `CONCURRENTLY` с `lock_timeout`, чтобы деплой не вешал прод.
- **Storage-абстракция** — медиа в S3 или локально; при падении хранилища мягкая двуязычная 503,
  а не 500.
- **Сиды при старте:** тарифы такси, справочник населённых пунктов РБ (~6600 сёл + приграничье
  соседей), точки сбора, клиники-партнёры. Идемпотентно.

### Фоновые задачи (systemd-таймеры)

| Задача | Что делает | Периодичность |
|---|---|---|
| `taxi_worker` | закрывает зависшие заказы (телефон сел), активирует предзаказы, двигает протухшие офферы | постоянно |
| `automatch` | берёт лучший отклик (рейтинг → цена) для заявок «по звонку» после паузы 120 с | по таймеру |
| `rate_reminder` | двуязычный push «оцените поездку» тем, кто ещё не оценил | ~раз в 30 мин |
| `cleanup` | ретеншен: чат > 30 дн, OTP > 1 дн, ad-events > 90 дн, закрытые SOS/жалобы > 180 дн. **Бережёт вечно:** аккаунты, документы, рейтинги, платежи, открытые SOS | ежедневно 04:00 UTC |
| `doc_check` | напоминает о сроках ОСАГО/разрешения, снимает допуск к такси при просрочке | ежедневно |
| `digest` | дневная сводка админу в Telegram | после 21:00 местного |
| `backup-db.sh` | `pg_dump` + gzip локально (14 копий) + офсайт-копия в S3 | ежедневно 04:00 |
| `monitor.sh` | пинг `/health`, алерт в Telegram при смене состояния | раз в минуту |

Остальные: `wallet`, `chat`, `support`, `reviews`, `discovery`, `promo`, `debt`, `trust`,

**Приватность в API — сквозное правило:** телефон и точный адрес не отдаются, пока не наступило

в открытом списке заявок адресов нет вообще.

## 13. Вход и авторизация

**Основной вход — через Telegram-бота** (`@yuldash_sms_bot`, уже настроен: токен + вебхук).
Поток: `POST /auth/tg/start` → человек жмёт «Старт» у бота → бот присылает код →
`POST /auth/tg/verify` → выдаются токены.

- **SMS-вход заморожен** (нет юр. лица для договора с sms.ru). Код цел, оживляется флагом
  `YULDASH_SMS_LOGIN=true` + `SMS_PROVIDER=smsru` на сервере.
- VK и WhatsApp — заглушки-callback'и.
- **Токены:** access живёт **12 часов** (было 7 дней — окно кражи ужали в ~14 раз),
  refresh **90 дней** и **ротируется при каждом обновлении**. Хранятся в `EncryptedSharedPreferences`.
- **Админ по телефону:** сравнение идёт по нормализованному ключу **с кодом страны**.
  Раньше сравнивались последние 10 цифр, и иностранный номер с совпадающим хвостом получал
  админку при обычном входе — дыра найдена аудитом 2026-08-08 и закрыта.
- **Согласия пишутся фактом входа:** оферта, политика, 18+ фиксируются в реестре `Consent`
  с датой, идемпотентно. Раньше на экране это была просто надпись, а в базе следа не было.
- **Тестовый аккаунт для сторов:** `REVIEW_PHONE` + `REVIEW_CODE` — реальная SMS не шлётся,
  любой другой код для этого номера не работает.

## 14. Сценарий A — Попутка (ядро продукта)

### Путь водителя
1. Заполняет профиль водителя, при желании загружает документы → админ проверяет →
   `verified` + бейдж «проверен».
2. **Публикует поездку** (`POST /rides`): откуда, куда, промежуточные точки, время, места, цена,
   предпочтения (животные, детское кресло, только женщины, курение, багаж, кондиционер,
   «тихая поездка»). Есть подсказка справедливой цены (оценка бензина на маршрут).
3. Получает брони, подтверждает их, ведёт живую поездку, завершает.

> **Поправка к версии 2026-08-12.** Там было написано, что перед публикацией показывается
> предупреждение о погоде на маршруте (гололёд, метель). **Такой функции в коде нет.**
> Погода влияет только на цену такси (коэффициент до +10 %, `pricing.py`). «Погода на маршруте»
> лежит в бэклоге — см. `docs/00-INDEX.md`.

### Путь пассажира
1. **Ищет** на карте или в ленте (`GET /rides`, `/rides/near`) с фильтрами.
2. **Бронирует** (`POST /bookings`) → бронь `pending` → водитель подтверждает → `confirmed`.
   **Телефон раскрывается только после подтверждения.**
3. На встрече — **код посадки** (4 цифры) подтверждает, что это тот самый человек и та самая машина.
4. Живая поездка: карта, чат (текст + голос), «поделиться с близким», SOS.
5. Завершение → чек → оценка (звёзды + текст + быстрые метки).

### Обратный путь — заявка
Пассажир создаёт **заявку** (`POST /requests`) → водители видят её в ленте и **откликаются**
(`POST /requests/{id}/respond`) с ценой → пассажир может **предложить встречную цену**
(`counter`), водитель — принять или предложить свою. Раунды торга ограничены.
Принятый отклик превращается в бронь.

Для человека **без приложения** (позвонил, попросил родственник) заявку оформляет админ
(`POST /admin/request-for-phone`), а лучший отклик через 120 секунд автоматически выбирает
`automatch` по правилу «рейтинг → цена».

### Дополнительно
- **«Карауль поездку»** (`RouteWatch`) — подписка на маршрут, push когда появится подходящая.
- **Boost** — платно поднять объявление выше: 20 ₽ / 2 ч, 50 ₽ / 24 ч, 70 ₽ / 6 ч (цены на
  сервере, не в клиенте). Влияет только внутри релевантных результатов; нерелевантная поездка
  наверх не попадает. Один бесплатный подъём на 24 ч даёт реферальный бонус.
- **Оплаченное поднятие не сгорает при отмене поездки** (сделано 2026-09-02). Раньше в коде
  отмены слова «boost» не было вовсе: водитель платил, снимал поездку — и остаток оплаченного
  времени исчезал. Теперь остаток переезжает на ближайшую активную поездку того же водителя
  (уже поднятой добавляется сверху), а если другой поездки нет — водителю уведомление,
  админу заявка в Telegram на ручной возврат. Бесплатный подъём возвращается бонусом.
- **Просроченная поездка** уходит в статус `expired`. Раньше такого статуса не было, и три
  поездки от 5, 6 и 15 июля висели «активными» вечно — пассажир их не видит, водитель не может закрыть.

## 15. Сценарий B — Такси («Быстрый заказ»)

**Мастер-флаг `TAXI_ENABLED` (по умолчанию `false`).** Причина не техническая: по 580-ФЗ
служба заказа легкового такси — это только ИП или ООО, самозанятый не может. Пока Александр
не оформит ИП, режим показывает «Скоро» и пассажиру, и водителю. **Попутка при этом не
затрагивается вообще.** Когда флаг включён, доступность решает список городов `TaxiCity`.

### Поток заказа
1. **Пассажир** указывает А→Б. Сервер (не клиент!) считает цену: `haversine × road_k(1.3)` →
   дорожная дистанция, либо реальная длина и ETA из Яндекс Routing API. Формула:
   `max(min_price, base + per_km·dist + per_min·eta) × k`, округление до 10 ₽.
2. **Коэффициенты** перемножаются один раз и вместе ограничены потолком **×1.5**:
   спрос (по городу за 10 минут в радиусе 7 км, спрос/предложение по ступеням),
   ночь (22:00–06:00), погода (до +10 %), дальняя подача (до +12 %).
   **Всё видно пассажиру ДО заказа. На попутке суржа нет.**
3. **Matcher** ранжирует водителей на линии: близость подачи (вес 1.0) + рейтинг (вес 0.4),
   штраф при рейтинге ниже 4.6. Максимум 8 офферов на заказ, у водителя 20 секунд на ответ.
4. `accepted` → **телефоны раскрываются обеим сторонам** → `arriving` → `onboard` → `done`.
5. Чек, оценка, «рәхмәт», «забыл вещь», «наличные получил».

### Честность и защита
- **«Я подъезжаю» сверяется с GPS водителя** (радиус 800 м). Массовая жалоба на inDrive —
  водитель жмёт «приехал», стоя за километры, а пассажир выходит на мороз. Если позиция
  неизвестна — пропускаем как раньше: молчащая кнопка хуже неточной.
- **Отмены и ожидание:** 3 минуты бесплатной отмены после принятия, 5 минут бесплатного
  ожидания, дальше 5 ₽/мин, «пассажир не вышел» через +3 минуты. Деньги при этом **не двигаются** —
  фиксируется факт и выдаётся страйк (3 страйка за 7 дней → пауза заказов на 24 часа).
- **Водителю за отмены после принятия** — свои, более мягкие числа (3 отмены за 7 дней →
  пауза офферов на 3 часа). Мягче намеренно: в райцентре свободных машин 2–3, и сутки паузы
  водителю бьют по пассажирам сильнее, чем сам проступок.
- **8-часовой лимит смены** + недельный потолок 40 часов (скользящее окно), отдых 8 часов,
  разблокировка не раньше 6:00 местного (Уфа = UTC+5). Активный заказ не рубится — дают довезти.
- **Классы машин** (Эконом / Комфорт / Бизнес / Минивэн) считаются **по характеристикам машины**,
  водитель их не выбирает. Класс открывается пассажирам, только когда в городе набралось
  3 подтверждённых водителя (для Бизнеса и Минивэна — 2). Пустая кнопка, за которой никого нет,
  дороже отсутствующей.
- **Просроченные документы не рубят активный заказ.** Гейт 580-ФЗ стоит на выходе на линию,
  приёме оффера и зоне; `arrived` / `onboard` / `done` через него не ходят — иначе пассажир
  остался бы посреди дороги из-за истёкшего ОСАГО.
- **Предзаказ «на время»** — до 7 суток вперёд, воркер активирует ко времени подачи.
- **Предрейсовое подтверждение** (самочувствие, машина, без алкоголя) — экран и ручки работают
  всегда, но гейт `PRETRIP_CHECK_REQUIRED` выключен: включённый мгновенно оставил бы без работы
  всех действующих таксистов на старых версиях приложения.
- **Промо запуска «первым водителям — 0 %»** живёт датой на сервере и по умолчанию выключено.
  С 2026-09-02 приложение показывает эту строку, **только когда набор реально идёт**, и берёт
  процент со срока с сервера. Раньше обещание висело вечно независимо от настройки.

## 16. Сценарий C — Курьер и посылки

### Философия (красные линии)
Попутка **людей** остаётся бесплатной. Символический сбор берётся только за вещь-доставку —
за реальную услугу «свели отправителя и попутного курьера».

### Поток
1. Отправитель создаёт заявку: откуда/куда, **что везём** (размер + **вес** + тип груза +
   «хрупкое»), адреса свободным текстом, имя и телефон получателя, принимает правила
   «не возим запрещённое».
2. Курьер видит заявку в открытом списке — **но без телефона и адресов**. Условия груза
   (размер, вес, тип) видны сразу: размер отвечает на «влезет ли», вес — на «унесу ли»,
   и это разные вопросы (раньше курьер соглашался на «большую» и находил мешок картошки на 40 кг).
3. Принял → получил телефон и адреса → `in_transit`.
4. **Вручение по коду:** отправитель передаёт `confirm_code` получателю вне приложения,
   получатель называет код курьеру, курьер вводит → `delivered`. Подтверждение вручения
   без раскрытия персональных данных.
5. Не получилось вручить → вторая попытка → возврат (`returning` → `returned`).
6. Есть чат по посылке, трекинг-ссылка получателю (видит только свой адрес), спор, чек, рейтинг.

### Три типа
- **`poputka`** — работает всегда, без гейта. Любой попутчик берёт коробку по пути.
- **`courier`** — за флагом `COURIER_ENABLED`, только одобренным курьерам на линии,
  комиссия по лесенке 3/5/8 %, блокировка режима курьера при долге 1000 ₽.
- **`buy_bring`** — «купи и привези»: курьер тратит свои деньги на товар, получатель возвращает.
  Фактическая стоимость покупки вводится курьером, проверяется на потолок суммы.

**Сервисный сбор за `poputka` (`PARCEL_FEE_ENABLED`) выключен и это честно, а не забывчивость:**
попутчик, завёзший коробку по дороге, — не курьер, кабинета и долга у него нет, счёт выставить
некому. Пока сбор начислялся «в воздух», отчёт админа показывал деньги, которых нет.

**Зависшая посылка** авто-закрывается через 72 часа (у такси — 6). Срок больше намеренно:
доставка между сёлами законно едет сутками.

## 17. Сценарий D — Доступность и семья

- **Простой режим** — крупные элементы, минимум действий, для пожилых.
- **Голосовая заявка** — сказать маршрут вслух, расшифровка проходит модерацию текста.
- **Заказ за близкого** (`FamilyOrder`) — оформить поездку родственнику.
- **Попросить звонок** (`CallbackHelp`) — человек без приложения оставляет номер, ему перезванивают.
- **Доверенные контакты** + «поделиться поездкой»: близкий видит живую ссылку статуса
  (`shared` → `sat` → `arrived` → `done`). Ссылка живёт по TTL и гаснет вместе с поездкой.
- **Поездки к клинике** (`ClinicRides`) — справочник клиник-партнёров и попутки к выбранной.
- **Подростки** — отдельная ветка правил для несовершеннолетних пассажиров.

## 18. Деньги: комиссия, долг, платежи

### Что реально движется, а что нет

| Поток | Как устроено | Платформа трогает деньги? |
|---|---|---|
| Попутка | пассажир и водитель платят друг другу напрямую (наличные / СБП). `PayMethod` — **запись договорённости**, а не платёж | ❌ нет |
| Такси (Модель А) | водитель получает деньги напрямую, комиссию **должен** платформе | ❌ нет, только долг |
| Такси (Модель Б) | деньги через ЮKassa Александра → комиссия → выплата водителю | 🔒 код готов, флаг `PAYOUTS_ENABLED=false` |
| Boost, донат, «поддержать Юлдаш» | ЮKassa либо перевод по СБП на номер владельца, админ подтверждает вручную | 🟡 да, но «на доверии» |
| Оплата завершённой поездки/брони | только после `done`, только владельцем заказа; безнал начисляет водителю через ledger | 🟡 при включённой ЮKassa |
| Чаевые «рәхмәт» | бесплатный жест работает всегда; денежная часть — прямой перевод водителю | 🔒 флаг `TIPS_MONEY_ENABLED=false` |

### Комиссия «лесенкой»
| Стаж | Такси | Курьер |
|---|---:|---:|
| 1-й месяц (≤ 30 дней) | 3 % | 3 % |
| 2-й месяц (≤ 60 дней) | 5 % | 5 % |
| дальше | 8 % | 8 % |

Для сравнения: Яндекс берёт 22–30 %. Все проценты — в конфиге (`.env`), меняются без пересборки.
⚠️ **Если поменять ставку на сервере, тексты в приложении за ней не пойдут:** курьерские экраны
до сих пор печатают «от 0 % до 8 %» своим числом, хотя сервер отдаёт настоящую ставку
(`current_fee_percent` в `/courier/me`). Это открытый хвост, см. §25.

### Долг таксиста
Комиссия копится в `CommissionDebt`, срок оплаты 7 дней. Водитель переводит по СБП и жмёт
«Я оплатил», админ подтверждает. Долг больше **1000 ₽** → **блокируется только режим такси**,
попутка продолжает работать. «Слово» водителя снимает блокировку максимум **2 раза** — раньше
лимита не было, и кнопку жали бесконечно.

### Ledger
Двойная запись `LedgerEntry`: `earn` (+вся сумма), `fee` (−комиссия), `payout`.
Баланс = earn − fee. Есть админ-сверка `/admin/ledger/reconcile`.

### Защита платежей (сделано 2026-09-02)
- **Ключ идемпотентности ЮKassa привязан к строке платежа** (`pay-<id>`). Раньше он
  генерировался заново на каждый вызов — то есть защита от повтора была выключена, и оборванный
  по сети запрос при повторе списывал деньги второй раз.
- **Повторное нажатие «Оплатить» возвращает тот же платёж, а не создаёт второй.** Правило было
  только у подписки бизнеса — перенесено на поднятие, донат и поддержку. Сходство строгое:
  тот же человек, назначение, сумма, поездка и тариф, не старше 15 минут. Другая сумма —
  это новая покупка, её не подменяем.
- **Оплата от отклонённого бизнеса больше не уходит в тишину:** подписка не воскрешает
  `rejected` (защита от фрода), но админу теперь приходит Telegram «верни деньги или пересмотри
  отказ». Раньше об этом не узнавал никто.

### Выплаты (готовность, выключены)
ЮKassa Payout API, минимум 100 ₽, максимум 150 000 ₽ за раз. Оживают, когда Александр
оформит ИП + бизнес-ЮKassa и выставит `PAYOUTS_ENABLED=true`.

### Прочая монетизация
- **Купоны «Скидки по пути»** — партнёрский маркетплейс, подписка бизнеса (тарифы `PARTNER_PLANS`).
- **Реклама** — founder-слоты (лимит 10) + пакеты «Город» / «Маршрут» / «Главный партнёр».
- **Промокоды** — кампании блогеров, реферальные бонусы.

Полная картина всех 16 направлений заработка, включая то, что существует только в плане, —
`docs/monetization-audit-2026-08-31.md`.

## 19. Доверие и безопасность

### Уровни доверия L0–L3 (вычисляются, не назначаются)
| Уровень | Название | Условие |
|---|---|---|
| **L0** | Новичок | телефон подтверждён |
| **L1** | Знакомый | заполнил имя и фото |
| **L2** | Проверен | прошёл проверку документов (`User.verified`) |
| **L3** | Свой | вошёл в круг по инвайту от L2/L3 |

Итоговый уровень = `max(вычисленный, дарованный)`. Запас инвайтов — 5 на человека, код
одноразовый (иначе его расшарили бы в публичный чат). **L0 — полноправный пользователь:**
уровни не унижают, а открывают доступ по мере доверия.

### SOS
Кнопка → событие `SosEvent` (пишется **синхронно**, до всех рассылок) → SMS доверенным
контактам + Telegram админу + SMS на телефоны админов. Не принят за **10 минут** — повторный
сигнал. Часовой кеп: **6 рассылок в час** (событие пишется всегда, глушится только SMS —
иначе мэш-кнопка = поток платных сообщений).

**Честность сигнала (сделано 2026-09-02).** Экран обещал «SMS твоим доверенным контактам»
безусловно — а у нового человека список пуст, и сигнал уходил только дежурному. Узнать об этом
можно было в беде. Теперь сервер возвращает два числа: `notified` (скольким реально ушла SMS)
и `contacts_total` (сколько контактов заведено), и приложение говорит правду **до** нажатия
(«доверенных контактов нет — SMS отправить некому, добавь близкого: Профиль → Безопасность
поездки») и **после** («SMS ушло близким: N»). Два числа отделяют «близких нет» от «SMS
придержал часовой кеп». То же самое исправлено у кнопки «застрял на трассе».

Отдельно есть «я застрял» для поездки, такси-заказа и посылки — одна реализация на три сценария.

### Справедливость (споры и наказания)
- **Жалоба** (`Report`) → **спор** (`Incident`): обе версии рядом, фото-улики, телефоны,
  решение админа с объяснением, возможность объясниться и подать апелляцию, вариант «помириться».
- **Страйки:** 2 → `limited`, 3 → авто-пауза по лестнице **3 дня → 7 дней → 30 дней**.
  Страйки сгорают за 60 дней хорошего поведения.
- **«Надёжность»** считается по последним 30 терминальным броням.
- **Качество:** рейтинг ниже 4.8 → мягкий совет (не чаще раза в неделю); ниже 4.6 → штраф
  в matcher (реже заказы); 3 подтверждённые жалобы за 30 дней → авто-пауза такси на 72 часа.
- **Тяжёлая категория** (безопасность) → мгновенный Telegram админу + авто-пауза такси до разбора.
- **Такси наказываем строго, попутку мягче** — пауза касается только такси.

### Приватность
- Телефон скрыт до подтверждения брони / принятия заказа / принятия посылки.
- Точная геолокация скрыта до подтверждения поездки.
- Координаты для внешних запросов **округляются** перед отправкой наружу — сервису нужен
  масштаб города, а не точный адрес человека.
- Телефоны и точные координаты **не логируются** и вычищаются из Sentry.
- Документы водителя отдаются через отдельный защищённый путь `/secure/docs/{name}`.
- Удаление аккаунта реально чистит данные (и не ломает чужие деньги — отдельные тесты).
- Копии данных приложения выключены и старым способом, и новым (Android 12+).

### Прочее
- **Женщинам — водитель-женщина** (opt-in). Бейдж «женщина за рулём» ставится только после
  подтверждения модератором по водительским документам — пол человека и право на бейдж
  это разные вещи.
- **Зимний протокол** «ты доехал?» — для попутки, такси и посылок одинаково: трасса Сибай–Уфа
  зимой опасна во всех трёх сценариях.
- **Анти-фрод и сговор:** `antifraud.py`, `collusion.py`, роутер `sybil`, `DeviceBan`,
  дедупликация документов по хешу файла.
- ⚠️ **Переключатель «Проверенные водители на карте»** фильтрует ровно то, что написано —
  список «Ближайшие» на карте. До 2026-09-02 он обещал «показывать **и принимать** поездки
  только от проверенных», хотя ленту не трогал и на приём броней не влиял; обещание сужено
  до правды. Сделать его настоящим фильтром — открытое продуктовое решение (§25).

## 20. Модерация и реклама по закону

### Модерация
- **Движок модерации текста** стоит на комментариях, заявках, откликах, отзывах, заказах, чате,
  имени профиля, поле «Где встречаемся» и текстах спора. Помеченное попадает в `TextFlag`.
- **Экран «Помеченные тексты»** в кабинете админа: кто и за что.
- **Текстовые отзывы не публикуются без модерации** — экран `AdminRatings`.
- **Документы водителя:** авто-проверка через Yandex Vision OCR помечает заявку;
  авто-отказ только на явный мусор (пустое/нечитаемое фото); **авто-одобрение выключено** —
  финальную кнопку жмёт человек.
- **Отзывы о приложении** проходят модерацию и после одобрения попадают на лендинг
  (`GET /reviews/public`).
- ⏳ **Осталось за Александром:** список башкирского мата для фильтра.

### Маркировка рекламы (erid) — сделано 2026-09-02
Закон о рекламе не знает состояния «крутим, номер вот-вот присвоят»: до присвоения `erid`
объявление показывать нельзя вообще (ст. 14.3 КоАП — до 500 000 ₽ юрлицу). Раньше требование
стояло только в форме админа на Android, а опубликовать объявление можно ещё тремя путями:
ручкой API, одобрением модерации и подтверждением оплаты. Через них проходили и пустой erid,
и заглушка «ожидает присвоения» — и приложение честно рисовало её пользователю.

Теперь три рубежа:
1. `erid_ok()` — настоящий номер ОРД (латиница, цифры, `-`, `_`, 6–64 символа); кириллица,
   пробелы и пустота не проходят;
2. `_is_live()` не отдаёт объявление без маркировки **никогда**, даже если статус `active`
   проставили в обход модерации (так делает подтверждение оплаты);
3. одобрение и публикация отвечают 400 с двуязычным объяснением.

Клиент отбрасывает такие объявления вторым рубежом (на случай старого сервера), а в админ-карточке
красным написано «Нет erid из ОРД — объявление не показывается».

⚠️ **Что ещё не сделано по закону:** данные о показах **не передаются в ОРД**. Пока нет
интеграции — нужен ручной регламент подачи сведений.

## 22. Инфраструктура и деплой

- **Сервер:** VPS Timeweb Cloud, Ubuntu 24.04 LTS. Доступ только по SSH-ключу, пароль
  отключён, ufw открывает 22/80/443. Точные адреса и команды — `docs/server.md`.
- **API:** systemd-сервис `yuldash-api` (uvicorn на `127.0.0.1:8000`, `Restart=always`),
  код в `/opt/yuldash`, конфиг `/opt/yuldash/.env` (не в git).
- **nginx:** `yulbash.ru/` отдаёт статический лендинг из `/var/www/yuldash-landing`,
  все нефайловые пути уходят на `:8000`. WebSocket через `Upgrade`-заголовки, `wss://` работает.
- **HTTPS:** Let's Encrypt + `certbot.timer`. HTTP → 301 на HTTPS.
- **Заголовки безопасности:** HSTS, `nosniff`, `SAMEORIGIN`, `Referrer-Policy`,
  `Permissions-Policy` (geolocation/microphone/camera выключены).
- **Кэш:** статика Next → `immutable`, медиа → 30 дней, **HTML → `no-cache`** (иначе после
  деплоя старый HTML тянет удалённые чанки → белый экран, ловили на iPhone).
- **БД:** PostgreSQL. Схему меняет только Alembic (`alembic upgrade head` в деплой-скрипте).
  Бэкап `pg_dump | gzip` ежедневно в 4:00, хранится 14 копий + офсайт-копия в приватный
  S3-бакет Timeweb.
- **Мониторинг:** `monitor.sh` пингует `/health` раз в минуту, шлёт алерт в Telegram только

**Стоп-правила:** не трогать `mobile/` · не коммитить секреты · не добавлять односторонние
строки · не помечать «готово» без сборки · не переписывать работающие экраны без просьбы ·
экран без состояний загрузки/ошибки/пусто — не готов · хардкод `Color(0xFF…)` в экране нельзя ·
молча менять версии Kotlin/Compose/SDK нельзя · **один файл — один агент в один момент** ·
**`YuldashApp.kt` не дописывать** (JaCoCo падает даже на одной строке).

**Два приёма, которые в августе-сентябре дали больше всего находок:**
1. **Деньги, привязанные к объекту** — пройди по ВСЕМ переходам объекта (отмена, завершение,
   архив, удаление, бан) и ответь, что происходит с оплатой в каждом. Пустой ответ «ничего» —
   это и есть дыра (так нашлось сгорающее поднятие).
2. **Обещание на экране против факта в системе** — текст, который что-то обещает, должен
   получать подтверждение оттуда, где обещание исполняется. Так нашлись SOS без контактов,
   вечное «0 % комиссии» и фильтр «только проверенные», который фильтровал одну карту.

**Отчёт Александру — как школьнику:** сначала что это меняет для человека, потом как сделано.
Не «добавил `imePadding`», а «кнопка пряталась за клавиатурой — теперь видна».
