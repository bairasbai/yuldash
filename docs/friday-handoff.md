  не продолжать общий аудит других режимов по более раннему широкому поручению.

  и пересечение; отсутствие видимых изменений не доказывает отсутствие локальной работы.
  Если область занята или согласование отсутствует, оставить предложение и продолжать
  непересекающуюся часть такси. Не считать чтение этой заметки состоявшейся координацией.
- Проверенные изменения Пятницы публикуются в отдельных ветках GitHub. **Не сливать
  в main и не развёртывать production** без отдельного разрешения владельца.
  Этот документ не заменяет актуальные указания владельца и не выдаёт новых разрешений.

- Никаких production-запросов ради проверки, реальных поездок, SMS, денег или изменения тарифов.
  До сетевых UI/API-тестов подтвердить тестовый адрес, БД и изоляцию сети по руководству.

## 4. Восстановление после сброса среды

1. Прочитать последнюю редакцию этого файла в `docs/friday-handoff-20261116` и её Git-историю.
   Сверить новые указания владельца: сохранённая запись не отменяет позднее сужение или остановку.
2. Проверить доступ к GitHub и remote main; получить нужные ветки в **новый собственный** checkout.
   До создания файлов проверить `git status --short`, `git branch --show-current`, `git rev-parse HEAD`.
   Не выполнять reset/clean/force-push и не переписывать рабочую копию другого агента.
3. Сравнить полный SHA и diff с указанной базой. Документационную ветку не использовать как
   актуальный код всех продуктовых работ. Получить только согласованный пакет нужной code-ветки.
4. Прочитать относящиеся инструкции и актуальные участки реестра; выяснить владельцев общих
   файлов/сборок/стендов. Выделить непересекающуюся область такси, не повторять работу попутки.
5. Восстановить зависимости штатным способом. Старые установленные инструменты, APK, кэш,
   тестовые БД и журналы не считать сохранившимися. Если доказательства недоступны, пометить
   «не проверено после восстановления», не заменять их старой устной сводкой.
6. Для разрешённого REA/Ghidra исследования сверить источник/версию, SHA-256 входного артефакта,
   scope и журнал команды. REA над PWA не равен анализу APK; статический анализ APK не раскрывает
   серверный алгоритм. Не запускать APK конкурента и не извлекать/использовать чужие токены.
7. Продолжить с первого оставшегося безопасного шага, затем сохранить проверенный результат
   в отдельной ветке и проверить remote commit. Не ждать очередного сброса для сохранения.

## 5. Как поддерживать журнал без конфликтов

Владелец попросил **поддерживать этот документ по мере работы**, а не создавать одноразовый отчёт.
Пятница обновляет его после завершённого пакета, изменения границ, нового блокера и перед передачей.
Один писатель на файл; помощники передают факты ответственному за журнал, не правят его параллельно.

- Перед записью перечитать текущий файл и head ветки. Вносить минимальное изменение с ожидаемой
  версией файла; при конфликте перечитать и согласовать, не применять force-push или слепую замену.
- В строке результата: дата UTC, исполнитель «Пятница / облако», задача, полные base/head SHA,
  ветка/commit/PR, изменённые пути, команды/exit code, ссылка на доказательства,
  независимый вывод, NOT_RUN/блокеры и следующий шаг. Если факт только сообщён исполнителем,
  так и написать; не присваивать чужой результат и не выводить авторство из имени ветки.
- Текущий снимок держать коротким, прежние записи не превращать задним числом в PASS.
  Длинные доказательства хранить в существующих проектных местах и ссылаться на них.
- Канонические статусы аудита менять только в `docs/audit-blocks.md` по его правилам.
  Этот журнал хранит происхождение и продолжение работы, а не конкурирующие статусы.
- `docs/tasks.md` общий с другими агентами. Ссылку на этот журнал сейчас не добавлять:
  владелец поручил не трогать общий файл до согласования. После согласования его писателя
  можно добавить минимальную ссылку/план по §5 AGENTS.md, не переписывая чужие записи.
- Перед публикацией: проверить diff/ссылки, сканировать только разрешённые изменённые документы
  на секреты, получить независимое чтение, затем прочитать опубликованный файл обратно.
  Сборки для docs-only по `/gotovo` не требуются; это не освобождает code-пакет от его проверок.
