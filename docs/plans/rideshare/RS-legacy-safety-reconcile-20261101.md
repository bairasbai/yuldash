## Приёмка и остановки

Каждый блок: review diff против принятого S, собственные предметные тесты из R плюс тесты RS01–03. Для порядка посадок нужны разный порядок ответов/повтор/перезапуск/смена пользователя; для GPS — несколько броней/последняя бронь/срок/потеря сети; для снимков — поздняя запись после закрытия/чужой пользователь/перезапуск/повтор квитанции. UI-тесты переносить с исправлениями, включая `f687c155`, `c539113b`, `b6b2f801`.

GPS включается только явным действием водителя на данном устройстве. Смена обслуживающей брони не продлевает исходный TTL (срок разрешённой передачи); изменение часов и перезагрузка не должны воскрешать остановленную или просроченную передачу. Проверить эти случаи отдельно, включая отсутствие автоматического включения при восстановлении поездки.

Для офлайн-снимков обязательна управляемая имитация отказа записи и снятия защитной отметки на диске. Проверить различие `NOT_DURABLE` (надёжное сохранение не подтверждено) и `DURABLY_BLOCKED` (запрет восстановления надёжно сохранён), а не только успешный путь. Для каждого отказа сочетать позднюю запись, перезапуск и смену пользователя; подтвердить, что закрытая или чужая поездка не восстановится и интерфейс не заявляет успешное сохранение без подтверждения диска.

Итоговые обязательные проверки: backend ruff F + pytest и реальная PostgreSQL-матрица; Android assembleDebug + затронутые тесты и GuardTest; webapp check/lint + build. Android-сборка и эмулятор только у одного владельца по locks. Видимое — светлая/тёмная × русский/башкирский, узкий экран и крупный текст. После зелёных проверок — свежая независимая приёмка сильнейшей модели, обновление мозга Root и уборка зарегистрированных ресурсов.
