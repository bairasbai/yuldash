## 1. Что получит человек
- **Было → стало.** Тётя Гульназ из Акъяра не пользуется Telegram — войти ей нечем. Станет: первым на экране входа — «Номер телефона». Ввела номер — пришла СМС, телефон сам подставил код, «Войти». Не пришла — через минуту «Отправить ещё раз» или «Прислать в WhatsApp». У кого Telegram или VK — кнопки ниже.
- **Один человек — один аккаунт.** Рустам вчера входил через Telegram, сегодня по СМС с тем же номером — это тот же аккаунт с поездками и отзывами, а не второй.
- **Выключатели у Александра.** В админке четыре переключателя: СМС, Telegram, VK, WhatsApp. Без договора с sms.ru СМС не включить — переключатель серый и говорит, чего не хватает. Выключенный способ люди не видят; видно, кто и когда включал.
- **Защита.** Код не подобрать, номер не завалить СМС, счёт не разорить.

## 3. Что сделать
Четыре PR по порядку: **А** механизм + админка + СМС; **Б** VK ID; **В** WhatsApp (после выбора провайдера); **Г** профиль и смена номера. До слияния каждого — обязательная проверка агентом `yuldash-security-privacy`, вердикт — в PR.

### Сервер (`backend/`)
**А1. Переключатели.** `LoginMethodSwitch` (`method`, `enabled`, `admin_id`, `created_at`) — только добавление: состояние = последняя строка метода, все строки = журнал. Строк нет → Telegram вкл., остальные выкл.
**А2. `login_methods.py`:** `missing(method)` — имена недостающих переменных: `sms` — `SMS_PROVIDER=smsru` + `SMS_RU_API_ID` (или smsdar); `telegram` — `TELEGRAM_BOT_TOKEN` + `TELEGRAM_WEBHOOK_SECRET`; `vk` — `VK_ID_CLIENT_ID` (+ секрет, если нужен); `whatsapp` — `WHATSAPP_PROVIDER` + ключи. Вне прода mock-СМС = настроен. `available_methods()` = включён ∧ настроен; кеш 10 с.
**А3. `routers/login_admin.py`** (в `routers/__init__.py`), только `role == admin`: `GET /admin/login-methods` — по методу `enabled`, `missing`, последняя смена (кто, когда), журнал (50); `POST /admin/login-methods/{method}` `{enabled}` — не настроен → 409 `login_method_not_configured` + `missing`; выключение последнего доступного → 409 `login_method_last` (иначе не войдёт никто, и Александр тоже); строка + `admin_action`; то же значение — 200 без строки.
**А4. Двери:** все ручки входа и привязки — через `refuse_disabled` (RS-01); бот при выключенном Telegram отвечает «Вход через Telegram сейчас выключен» без кода.
**А5. СМС — защита:**
1. Номер после `normalize_phone` — только `+79\d{9}`, иначе 422 `phone_not_supported` (иностранные платные номера — главный способ разорить счёт).
2. Лимиты выдачи — под замком номера, по `OtpCode`, все каналы вместе: номер — раз в 60 с, ≤ 5/час, ≤ 10/сутки; IP — ≤ 10/час; устройство (`X-Device-Id`) — ≤ 5/час; весь сервис — `SMS_DAILY_CAP` в сутки (по умолчанию 300) → 503 `sms_daily_cap` + одно сообщение дежурному. Превышение → 429 `otp_rate_limited` + `retry_after_sec`.
3. `OtpCode` + `channel`, `ip_hash`, `device_hash` (HMAC с секретом сервера); уборка — `auth.py:690-705`.
4. Код: 6 цифр, 5 минут, попытки — как сейчас. Хранить HMAC кода, сверка `compare_digest` (живые коды при выкладке перестанут подходить — 5 минут, допустимо).
5. Ответ один для любого номера: `{"sent": true, "resend_after_sec": 60, "expires_in_sec": 300}`.
6. Тело `{phone, lang: "ru"|"ba", channel: "sms"|"whatsapp"}`. СМС — на языке экрана, одним сегментом (≤ 70 знаков кириллицы), последней строкой `@app.yulbash.ru #<код>` (автоподстановка на сайте); отправитель `SMS_FROM` после модерации sms.ru.
7. Журнал: код — никогда, номер — `mask_phone`; код в лог при сбое — только `env == "dev"` (сейчас — любой «не прод»).
8. `send_text` (SOS, близкие, «новое устройство») — отдельный `SMS_NOTIFY_ENABLED` (по умолчанию `false`), им же считается `sms_will_reach`: включение СМС для входа не меняет молча SOS и не тратит деньги. Включение уведомлений — отдельное решение (Q2, Q11).
**А6. Один человек — один аккаунт:**
1. Ключ — подтверждённый номер (`User.phone`); без номера вход не завершается (как `auth.py:989-993`).
2. СМС и WhatsApp подтверждают номер → поиск по номеру (`find_user_by_phone`).
3. Telegram, VK: по своему id, иначе по номеру от провайдера; слот пуст — привязать; занят другим id → 409 `method_linked_other`, второй аккаунт не создаётся (и вместо «застревания» в `auth.py:958, 986-993`).
4. Нашли по id, а номер провайдера у другого аккаунта → 409 `phone_taken_other_account`; слияние — только поддержка.
5. «Номер сменил хозяина» (`phone_looks_recycled`) — одинаково для всех.
**Б. VK ID** (`vk_id.py`, `User.vk_id` уникальный):
1. PKCE (S256) на клиенте, `code_verifier` не покидает устройство; `client_id`, `redirect_uri`, `scope` — в `/config/login-methods`.
2. `POST /auth/vk/finish` `{code, code_verifier, device_id, redirect_uri}` — сервер сам меняет код у VK и читает профиль (адреса — по документации VK ID). `vk_id` от клиента не принимаем никогда — так был дыряв старый вход (`auth.py:1022-1026`).
3. Берём только `vk_id`, имя (`_safe_display_name`) и подтверждённый номер; почту, фамилию, фото, друзей — нет; токен VK не храним. Нет номера → 403 `phone_required_vk`. Дальше — А6.
**В. WhatsApp** (`whatsapp_otp.py`): тот же код другим каналом — `channel="whatsapp"`, общие `OtpCode`, лимиты и сверка. Только официальный WhatsApp Business API (шаблон «authentication») у провайдера с договором в России; личный номер и «серые» рассылки — нельзя (бан, утечка номеров). Провайдер не выбран: адаптер `send_code(phone, code, lang) -> bool` + одна реализация под выбор Александра. Доставка в России нестабильна — только запасной.
**Г. Профиль и смена номера:**
1. `GET /me/login-methods` — номер маской, Telegram и VK (привязан или нет).
2. Привязка — поток Telegram/VK с токеном сессии; id свободен → в текущий аккаунт, иначе `method_linked_other`.
3. `POST /me/login-methods/{method}/unlink` — только если остаётся другой доступный сейчас способ; номер не отвязывается, только меняется.
4. Смена номера: `POST /me/phone/request-code` → `/me/phone/confirm` — вход не старше 10 мин, код на новый свободный номер, раз в 7 дней; затем выход на других устройствах (`revoke_all_refresh`) и пуш.
