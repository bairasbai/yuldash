## 1. Что получит человек
**Было.** Рустам опубликовал «Сибай → Уфа через Акъяр» и вспомнил, что заедет ещё в Баймак, а в Акъяр — нет. Исправить
остановки нельзя: только снять поездку и опубликовать заново. Пассажиры из Баймака его рейс не находят, а сторожа маршрута
получают «появилась поездка» дважды.

**Стало.** В кабинете водителя — «Изменить остановки»: добавить (до четырёх), убрать, переставить, и тут же поправить цену до
каждой остановки. Пассажир из Баймака сразу находит рейс, подписчик «появилась поездка» на Баймак получает одно уведомление.
Если кто-то уже забронировал, отказ честный: «Пассажиры уже выбрали, где садиться. Отмени брони или договорись в чате».
Если Айгуль бронирует в ту же секунду, когда Рустам меняет остановки, побеждает кто-то один — брони «на остановку, которой
больше нет» не бывает.

## 3. Что сделать
### Сервер (`backend/`)
1. **Вход.** `RideEditIn`: `waypoints: Optional[str] = Field(None, max_length=500)`, `drop_offers: bool = False`; цены до остановок —
   в формате RS-02 (поле, которое RS-02 добавит в `RideIn`).
2. **Разбор** (в `edit_ride` сразу после проверок владельца и статуса, до остальных полей): `new = _clean_publish_stops(body.waypoints)` —
   те же 400 `stops_too_many`/`stop_invalid`, что при публикации; `old = " | ".join(split_raw(ride.waypoints))`. `new == old` (и цены
   RS-02 те же) — это не правка: клиент шлёт форму целиком, 409 при бронях тут быть не должно (как `:447-451`).
3. **Живые брони** (`live`, `:393-396`) — 409 `ride_stops_booked`, `bookings: N`, ничего из запроса не применяется (ни цена, ни
   комментарий): «На рейс уже есть брони — пассажиры выбрали, где садиться. Остановки меняются, пока броней нет: отмени брони
   или договорись в чате». Отклик, принятый по заявке, — тоже живая бронь (`requests.py:1338-1343`); отменённые и завершённые не мешают.
4. **Открытые предложения по заявкам** (`RequestResponse.ride_id == ride.id`, статус из `LIVE_RESPONSE_STATUSES`): без `drop_offers` —
   409 `ride_stops_offers_open`, `offers: N`: «Ты предложил этот рейс по заявкам (N). Если поменять остановки, предложения перестанут
   действовать. Изменить всё равно?». С `drop_offers=true` — после успешной записи эти отклики `status="closed"`, пассажиру заявки
   пуш (`ref_kind="request"`): «Водитель изменил остановки — его предложение больше не действует. Заявка активна — жди других
   откликов». Без закрытия принять их всё равно нельзя (`requests.py:1281-1284`), закрытие — чтобы человек не ждал зря.
5. **Модерация:** `moderate_open_text(new, user.id, check_contact=False, place="waypoints", ref_id=ride.id, session=session)`.
6. **Запись без гонки** — до изменения остальных полей, одним условным `UPDATE`:
   `WHERE id = :id AND status = 'active' AND waypoints = :old_raw AND seats_left = :seats_left_read AND NOT EXISTS (живая бронь рейса)`
   → `waypoints = new` (+ цены RS-02). 0 строк — `rollback`, 409 `ride_changed_retry`: «Рейс только что изменился — появилась или
   отменилась бронь. Обнови и попробуй ещё раз». Условие на `seats_left` той же строки ловит чужую бронь и на PostgreSQL (перепроверка
   строки после ожидания блокировки), `NOT EXISTS` и сравнение текста — на SQLite, где `FOR UPDATE` пуст. Затем `ride.waypoints = new`
   в объекте и `changed.append(("остановки", <BA — черновик>))`. Ответ — свежий рейс (`session.refresh(ride)`).
7. **Встречная сторона — бронь** (`bookings.py:610-618`): в условие списания мест добавить `Ride.waypoints == ride.waypoints`
   (остановки, по которым разобрано место). 0 строк — после `rollback` перечитать рейс (`populate_existing=True`): остановки другие —
   409 `ride_stops_changed` («Водитель только что изменил остановки. Открой поездку ещё раз и выбери место»), иначе прежнее «Места
   только что разобрали». Места и брони не трогаются. Ошибку — через `_pickup_refusal` (`bookings.py:302-303`), с кодом.
8. **Принятие отклика** уже защищено (`requests.py:1320-1328`) — код не меняется, только тест.
9. **Цены до остановок (RS-02):** при смене остановок цены присылаются для нового набора и проверяются той же функцией, что при
   публикации RS-02 (одно правило — одна функция); не прислал, а RS-02 требует — его же 400. Правка только цен без смены остановок —
   правило цены `:399-414` (при бронях только вниз, цены броней и `pay_amount` вниз). Если RS-02 это уже сделал — не дублировать.
10. **Сторожа маршрута:** после `commit` — `notify_route_watchers(session, ride)` и `session.refresh(ride)` (урок `:356-362`). В
    `notify_route_watchers` — не слать подписке, которой уже ушло «Появилась поездка» по этому рейсу (`Notification` с
    `user_id`, `type="route_watch"`, `ref_kind="ride"`, `ref_id=ride.id`). Сверку по остановкам делает RS-10; до его слияния новых
    совпадений просто нет, вызов безвреден.
11. **Поиск и карта:** поиск по остановкам видит правку сразу (читает базу); общая лента — через ≤20 с кэша (как после публикации);
    `notify_map_changed` уже есть (`:472`).
12. **Идемпотентность и права:** повтор того же запроса — «не правка», 200, без уведомлений; права и статус — существующие 403/400
    (`:389-392`); правится один рейс, остальные рейсы серии не трогаются (как цена и время сейчас).

## 8. Приёмка
Агент другой «семьи» (Q9), по умолчанию «не принято».
1. Приложены зелёные выводы: `ruff`, полный `pytest` (обе гонки), `npm run check`, `npm run build`, `:app:assembleDebug`, тесты Android.
2. Эмулятор, Android-водитель и сайт-водитель, RU/BA × светлая/тёмная: «Сибай → Уфа через Акъяр» → «Изменить остановки» →
   добавить Баймак, убрать Акъяр, переставить → пассажир (сайт и Android) ищет «из Баймака» — находит, «из Акъяра» — нет.
3. Пассажир бронирует → водитель меняет остановки → понятный отказ, рейс не изменился; цена вниз по-прежнему работает.
4. Предложение по заявке на этот рейс → вопрос «Изменить всё равно» → пассажиру заявки уведомление; старое предложение не принимается.
5. Узкий экран и крупный шрифт: четыре длинных башкирских названия не ломают шторку.
6. Двигает W1-E2E-01 (поиск по остановкам после правки) и W1-E2E-03 (нет брони на исчезнувшую остановку). Остаётся: W1-E2E-07 (Q11),
   BA носителем, RS-16. Статус — только `docs/audit-blocks.md`.
