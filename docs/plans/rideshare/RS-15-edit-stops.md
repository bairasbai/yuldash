## 1. Что получит человек
**Было.** Рустам опубликовал «Сибай → Уфа через Акъяр», а потом решил заехать в Баймак вместо Акъяра. Остановки не исправить —
только снять поездку и опубликовать заново. Пассажиры из Баймака рейс не находят.

**Стало.** В кабинете — «Изменить остановки»: добавить (до четырёх), убрать, переставить и тут же поправить цену до каждой.
Пассажир из Баймака сразу находит рейс, подписчик «появилась поездка» получает одно уведомление. Если кто-то уже забронировал —
честный отказ: «Пассажиры уже выбрали, где садиться. Отмени брони или договорись в чате». Если Айгуль бронирует в ту же секунду,
когда Рустам меняет остановки, побеждает кто-то один — брони «на остановку, которой больше нет» не бывает.

## 3. Что сделать
### Сервер (`backend/`)
1. **Вход:** `RideEditIn.waypoints: Optional[str] = Field(None, max_length=500)`, `drop_offers: bool = False`; цены —
   `RideEditIn.stop_prices` из RS-02 (п. 10 его плана). Ошибки — `herr(status, ru, ba, code=...)` (код в `herr` добавляет RS-02).
2. **Разбор** (в `edit_ride` после проверок владельца и статуса `:389-392`, до остальных полей): `new = _clean_publish_stops(...)` —
   те же 400, что при публикации; `old = " | ".join(split_raw(ride.waypoints))`. `new == old` и цены те же — не правка (клиент шлёт
   форму целиком), 409 при бронях быть не должно.
3. **Живые брони** — 409 `ride_stops_booked`, `bookings: N`, из запроса не применяется ничего: «На рейс уже есть брони — пассажиры
   выбрали, где садиться. Остановки меняются, пока броней нет: отмени брони или договорись в чате». Принятый отклик — тоже живая бронь;
   отменённые и завершённые не мешают.
4. **Открытые предложения по заявкам** (`RequestResponse.ride_id == ride.id`, статус из `LIVE_RESPONSE_STATUSES`): без `drop_offers` —
   409 `ride_stops_offers_open`, `offers: N` («Ты предложил этот рейс по заявкам (N). Если поменять остановки, предложения
   перестанут действовать. Изменить всё равно?»). С `drop_offers` — после записи `status="closed"` и пуш пассажиру заявки
   (`ref_kind="request"`): «Водитель изменил остановки — его предложение больше не действует. Заявка активна — жди других откликов».
5. **Модерация:** `moderate_open_text(new, user.id, check_contact=False, place="waypoints", ref_id=ride.id, session=session)`.
6. **Запись без гонки** — до остальных полей, одним условным `UPDATE`:
   `WHERE id = :id AND status = 'active' AND waypoints = :old_raw AND seats_left = :прочитанное AND NOT EXISTS (живая бронь рейса)`
   → `waypoints = new` (+ цены RS-02). 0 строк — `rollback`, 409 `ride_changed_retry` («Рейс только что изменился — появилась или
   отменилась бронь. Обнови и попробуй ещё раз»). `seats_left` той же строки ловит чужую бронь на PostgreSQL (перепроверка строки
   после блокировки), `NOT EXISTS` и текст — на SQLite (там `FOR UPDATE` пуст). Затем `ride.waypoints = new`,
   `changed.append(("остановки", <BA — черновик>))`.
7. **Бронь** (`bookings.py:610-618`): в условие списания добавить `Ride.waypoints == ride.waypoints`. 0 строк — после `rollback`
   перечитать рейс (`populate_existing=True`): остановки другие — 409 `ride_stops_changed` («Водитель только что изменил остановки.
   Открой поездку ещё раз и выбери место») через `_pickup_refusal` (`:302-303`), иначе прежнее «Места только что разобрали».
8. **Принятие отклика** уже защищено (`requests.py:1320-1328`) — только тест.
9. **Цены до остановок (RS-02):** при смене остановок — цены для нового набора, проверка той же функцией, что публикация RS-02;
   не прислал, а RS-02 требует — его же 400. Правка одних цен — по правилу цены `:399-414` (при бронях только вниз, вместе с
   ценой брони и `pay_amount`), если RS-02 этого ещё не сделал.
10. **Сторожа маршрута:** после `commit` — `notify_route_watchers(session, ride)`, затем `session.refresh(ride)`. В самой функции —
    пропуск подписки, которой уже ушло «Появилась поездка» по этому рейсу (`Notification`: `user_id`, `type="route_watch"`,
    `ref_kind="ride"`, `ref_id`). Сверку по остановкам делает RS-10; до него новых совпадений нет, вызов безвреден.
11. **Поиск и карта:** поиск по остановкам видит правку сразу; лента без фильтров — через ≤20 с кэша, как после публикации.
12. **Повтор и границы:** тот же запрос второй раз — 200 без уведомлений; права — существующие 403/400; правится один рейс серии.
