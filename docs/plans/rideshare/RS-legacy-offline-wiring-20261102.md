# Подключение защиты офлайн-поездки ко всему Android-пути

Дата: 02.11.2026. Владелец: Root. Это детализация блока4 принятого `RS-legacy-safety-reconcile-20261101.md` и `RS-legacy-safety-failure-constraints-20261102.md`, не новая продуктовая гарантия. До свежей независимой проверки этого плана проводку не писать. Текущие результаты — только в `docs/audit-blocks.md`.

## Граница и цена решения

Работа только в местной ветке S `codex/rideshare-safety-reconcile-20261102`. Core03 и storage8 заморожены, проходят собственные проверки; реальные12 фаз адаптера не заменяют сеть/экран. Backend, PWA, деньги, версии, ключевые файлы, mobile, main/push/прод не меняются. D7, участки RS02, DTO/версии/приватность точек RS03 и новые GPS-переходы сохраняются.

После нового процесса никакие выжившие байты/списки/WS/маркеры сами не открывают активную поездку, телефон, код или точные места. Нужен свежий авторизованный серверный ответ текущего владельца. Без сети после перезапуска активное восстановление недоступно; тёплое разрешённое чтение остаётся. Текущий корректный онлайн200 не превращается в сетевую ошибку из-за недоступного optional-диска или часов: запрещается кеш, а свежая проекция обрабатывается честно отдельно.

## Один владелец и доказательство запроса

Новый `data/OfflineTripSnapshots.kt` создаёт единственные на процесс owner-reference, gate, repository и storage adapter. Владелец: origin + userId + канонический durable UUID scope + session generation. Новый вход получает новый scope; refresh сохраняет scope/generation, но сам не выдаёт разрешение поездки. Init восстанавливает только identity/scope, gate пуст. Logout/смена origin/пользователя/отказ сохранения auth сначала отзывают память, затем очищают доступный диск. Повреждённый optional scope запрещает snapshot, не уничтожая здоровый вход.

Новый `data/SnapshotTransportRead.kt` связывает ticket с фактическим вызовом `ApiClient.call`, не с наличием DTO. Attempt/startWire(authorized)/status/body/parse/retry/refresh регистрируются по реальному выполнению. **401/403/404/410 отзывают gate сразу после получения status, до чтения тела и refresh**; доступная durable-защита дополняет отзыв. 403/404/410 и terminal запрещают fallback независимо от последующей ошибки тела. После успешного refresh повторный авторизованный GET получает новый ticket; старый ticket остаётся отозванным. Ошибка/401 первой попытки не маскируется как разрешение загрузить старый кеш. Смена generation требует нового чтения, чужой поздний ответ ничего не отзывает у нового владельца.

Новый `data/OfflineTripSnapshotHooks.kt` привязывает реальные ROLE/DETAILS/HISTORY, а также accepted boarding/consent/undo и закрытия. GET списков/WS/queued-событие не выдаёт live/private. Прямые и queued driverStatus/setTripStatus/cancel/no-show/cancelRide/completeRide проходят те же проверки. Принятое закрытие отзывает память до mutex и записи; NOT_DURABLE/DURABLY_BLOCKED сообщаются честно. Поздний accepted/GET/write не открывает более новую посадку или закрытую поездку.

## Приватная проекция

Новый `data/TripPrivateProjection.kt` формирует неизменяемую проекцию из свежих DETAILS текущей брони/роли. Полный fingerprint содержит все фактически показываемые поля паспорта: booking/ride/role/status и посадочную эпоху/receipt, contact_unlocked; города/время/водитель/машина/номер/телефон; посадку, координаты, RU/BA ориентиры и пояснения; участок/остановки; места, цену, способ/сумму/пояснение оплаты как текущие целые рубли. `savedAt` — техническое время, не основание совпадения. Hash и значения не логируются/не отправляются в аналитику.

Код посадки имеет отдельный источник: только настоящий успешный code GET, связанный с той же свежей DETAILS revision/owner/booking/ролью пассажира. При смене DETAILS epoch поздний code не дополняет старую проекцию; нужны новые DETAILS. До ответа кода текущая проекция может показать только свои разрешённые поля, без прежнего кода. Водителю пассажирский код не сохраняется. Одна ROLE не разрешает приватный blob: ROLE200 + старый паспорт + DETAILS failure остаются без кода/телефона/точек.

`TripPassStore.load`, update/save и `RideshareTripContacts` получают общий gate и fingerprint. Старый зашифрованный паспорт — кандидат, не authority. При отказе записи свежая проекция живёт в памяти, старый blob не подставляется. Приватность проверяется также непосредственно перед отрисовкой, кликом и callback; закрываются semantics и уходящий кадр анимации, а не только видимые пиксели.

## Восстановление, история и минимальные файлы

Все входы — deep link, SavedState, Home/PassengerCabinet, новая бронь, принятое предложение, openDriverTrip — сначала разрешают кандидата через общий owner/gate. Списочная строка/сохранённый Ride не устанавливают live activeTrip. Состояния загрузки/ошибки/повтора обязательны на двух языках. Тёплый снимок показывается отдельным читающим экраном без chat/actions/GPS. Disposal конкретного окна прекращает только его callbacks, не отзывает общий gate другого окна.

Новые файлы приложения: `OfflineTripSnapshotNavigation.kt`, `OfflineActiveTripSnapshot.kt`, `ActiveTripOfflinePassState.kt`. Новый экран при необходимости получает `Screen` в `MainActivity.kt`, ветку навигации и запись architecture. Узкие существующие точки: `YuldashViewModel`, `BookingLinkDestination`, `AppNavHome`, `YuldashApp`, `BookingActiveTripScreen`, `ActiveTripDetails`, `CancelledInTransit`, `TripReceiptScreen`, `RideshareCompletedScreen`. Сохраняются `DriverRideUi.returnToDriverRide/driverFinishedBooking/endTripScreen` и канонический rideId.

Terminal и HISTORY отдельны. Receipt200 разрешает только текущую проекцию своего чека; не live/code/GPS. Закрытие booking/ride сохраняет допустимую историю, access denial/scope-retire отзывает. A/B/C чеков не перезаписывают новый старым. Чек другой брони не меняет текущую активную. Отмена в пути сохраняет существующие SOS и безопасную проекцию машины, без старых телефона/кода/точных мест.

API7889/7905 и активный экран3541/3541 не расширять сверх потолков: вынести только относящиеся к блоку разбор ROLE/cancel-response и состояния/эффект паспорта в новые helpers, сохранив публичные методы. Никакой замены гигантов целиком. Один source-writer на проводку; Root один запускает Gradle/устройство. Пересекающиеся GPS-файлы передаются только после freeze и текущей проверки.

## Проверка и приёмка

1. Реальный HTTP: status до body-fault, refresh/new-ticket, чужой поздний owner; ROLE200 + старый паспорт + DETAILS error; fresh DETAILS с изменёнными точками RS03 и поздним code.
2. Все четыре отказа диска через restore/UI, late GET/write, терминальное закрытие, смена owner/origin, unmount/rotation, истечение/откат часов. Различать управление commit=false и физическую поломку диска.
3. Настоящий новый PID при отключённой сети не открывает active/private; fresh terminal/403 запрещает surviving ciphertext, fresh own DETAILS разрешает только актуальную проекцию. Свой тестовый ресурс/alias регистрируется отдельно, auth/общий ключ не читается и не копируется.
4. Прямые/queued accepted correction и last/remaining-booking переходы, HISTORY A/B/C, прежние consent/D7/RS03/GPS/guards. Android assembleDebug + affected/full unit по текущим изменениям, compileAndroidTest, **unsignedRelease/R8**; UI RU/BA × светлая/тёмная, узкий экран/крупный текст.
5. Свежая независимая приёмка текущих исходников и настоящих доказательств, обновление architecture/tasks/audit и уборка своих ресурсов. Приёмка блока не заменяет полный состав режима по §13. Телефоны и проверка BA носителем остаются отдельно отложенными Александром.
