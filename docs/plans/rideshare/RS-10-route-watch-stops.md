## 1. Что получит человек
Гульнара живёт в Ургазе, ей нужно в Акъяр, поездок нет, и она подписалась на «Ургаза → Акъяр». Рамиль публикует «Сибай → Акъяр через Ургазу». Сейчас Гульнара не узнает: приложение сверяет только начало и конец маршрута, а Ургаза у Рамиля — остановка посередине. Если Рамиль публикует «каждый понедельник», сообщение придёт только про первый рейс.

Теперь подписка работает так же, как поиск: что нашёл бы поиск, о том придёт сообщение, с пометкой «садишься в: Ургаза». Про серию — одно сообщение «рейсов: 5». На сайте кнопка «Следить за маршрутом» стоит прямо там, где поездок не нашлось. В «Подписках» видно, когда было последнее сообщение и включены ли уведомления на телефоне.

## 3. Что сделать
### Сервер (`backend/`)
1. **S1 (совпадение).** `route_watch_fit(session, watch, ride, entry)` в `services.py`: `fv/tv = stop_search.variants(…)`, `from_stops/to_stops = stop_searchable(…)`, `stop_search.route_fit(ride, fv, tv, entry, …)`; для `direction == "both"` ещё раз с поменянными местами. `entry = request_snapshot(settlements_snapshot(session))` один на рассылку; вердикт кешируется по (откуда, куда, направление, вид маршрута рейса). `_city_keys` остаётся для `notify_request_watchers` (заявки — вне плана).
2. **S2 (серия).** «Братья» рейса: активные рейсы того же водителя с теми же `from_city`, `to_city`, `waypoints`, `category` и `created_at` в пределах 10 с. Для подписки берутся братья, подошедшие по S1 и по дню `watch_date` (по местному дню рейса). Подошёл хоть один — **одно** оповещение, ref — самый ранний. Работает и для `recurrence` (`rides.py:325`), и для пачки RS-09 (она вызывает рассылку один раз после создания всех рейсов).
3. **S3 (кому нельзя).** Добавить к существующим (свой рейс, `may_be_notified`): водитель на паузе (`safety_logic.suspended_user_ids`), рейс не активен, нет мест (`seats_left <= 0`) или уже уехал.
4. **S4 (текст).** RU: заголовок «Появилась поездка» / «Появились поездки»; тело `«{откуда} → {куда}»`, плюс « · садишься в: {matched_stop}» / « · выйдешь в: {matched_dropoff_stop}» при совпадении по остановке, плюс « · рейсов: N» для серии. Язык пуша — по `User.language` получателя (один запрос на всех, как `push_notification:775`); BA — черновик исполнителя.
5. **S5 (без дублей).** Перед записью: уже есть `Notification(user_id, type="route_watch", ref_id=<самый ранний>)` — пропустить. Повторный вызов на тот же рейс ничего не шлёт.
6. **S6 (статус).** `RouteWatchOut` + `last_notified_at`, `push_channels{app, web}` (есть `DeviceToken` / `WebPushSubscription` у владельца), `quiet_from`, `quiet_to` (`settings.quiet_hours_*`, 0 = выключены). Честно только то, что сервер знает: запись в центре есть всегда, пуш — если есть устройство; «дошло ли» не обещаем.
7. **S7 (ввод).** `POST /route-watch`: место должно проходить `stop_searchable` и содержать ≥ 2 букв, иначе `HTTPException(400, {ru:"Название места — буквами, без цифр", ba:<черновик>, code:"watch_place_invalid"})`. Дубль по-прежнему обновляет подписку. `DELETE` без изменений.
