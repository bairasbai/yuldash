## 1. Что получит человек
Гульнара едет из Ургазы в Акъяр с дочкой и мамой — нужны три места. Сейчас лента показывает всё подряд: она открывает поездку за поездкой и только на брони узнаёт, что свободно одно место. Теперь она выбирает «Мест: 3» — остаются поездки, где на её участке свободно три и больше. Это число само встаёт в бронь и сохраняется как намерение группы; нехватка мест требует её явного решения уменьшить группу. Выбор можно запомнить, как другие условия.

Если подходящего нет, приложение не молчит: «Для 3 мест поездок нет. Есть 2 поездки, где свободно 2 места — искать на 2?» и предлагает следить за маршрутом.

## 3. Что сделать
**Фаза A** (PR А) — по `seats_left`. **Фаза B** (PR Б, после RS-02) — места на участке человека; параметры и ответ те же.

### Сервер (`backend/`)
1. **S1 (А).** `GET /rides/near` и `GET /rides`: `seats: Optional[int] = Query(None, ge=1, le=8)`  (вне диапазона → обычный 422 FastAPI). **`seats ≤ 1` приравнивается к «параметра нет»** — общий кеш работает; при `seats ≥ 2` параметр входит в `any([...])` у `no_filter`. **`GET /rides`** применяет `Ride.seats_left >= seats`. **`GET /rides/near`** сначала отбирает все положительные кандидаты `seats_left > 0` (после RS-02 — `any_free_sql(1)`); SQL-порог `>= N` здесь запрещён, иначе кандидаты для подсказки исчезнут до split.
2. **S2 (А).** `/rides/near`: в лёгкие колонки — `Ride.seats_left.label("seats_free")` в конец. Сначала вычислить маршрут/дистанцию и применить `hide_blocked`, `hide_suspended`, `hide_trusted_only` к общему набору; при `verified_only` сохранить отдельный счёт непроверенных только среди достаточных по местам. Затем одинаково применить `verified_only` и разделить кандидатов по числу свободных мест в `kept (free ≥ N)` / `short (0 < free < N)`; проверка **по каждому рейсу**, не по виду маршрута. Ни скрытые поездки, ни их количество в подсказку не попадают.
3. **S3 (А).** В ответ — `hidden_by_seats = len(short)` (все скрытые только нехваткой мест), `max_free_seats = K = max(free(short))` и **`count_at_max_free = M = count(short where free == K)`**, только при `seats > 1`; пустой short → `0, null, 0`. Подсказка «Есть M поездок, где свободно K мест» использует именно `count_at_max_free`, а не `hidden_by_seats`. `count`/страницы считаются уже с фильтром мест. `hidden_unverified` — как прежде: рейсы, спрятанные только «проверенными» среди прошедших по местам.
4. **S4 (Б).** Лёгких колонок `/rides/near` (`:978-982`) для этого не хватает: дописать в конец **`Ride.seats_free_max` и `Ride.leg_free`** (если RS-02 уже дописал — не дублировать; `_NEAR_SHAPE_AT` не сдвигать). В `/near` сохранить широкий SQL-отбор `any_free_sql(1)`, затем для каждого рейса вычислять `free`: участок однозначен (предвыбор карточки `_matched`/`_dropoff`) → `ride_seats.free_on(…)`, иначе `max_free`. Split S2 делает сравнение с N; `short` и его статистика используют то же `free`. SQL-отбор `/rides` — `ride_seats.any_free_sql(seats)`. Колонки в том же SELECT — запросов не прибавляется (`test_no_query_per_item` зелёный).

### Android (`android/`)
1. **A1 (А).** `ApiClient.kt`: `getNearbyRidesPaged(…, seats: Int = 1)` (`seats > 1` → `&seats=`); `NearbyPage` + `hiddenBySeats`, `maxFreeSeats`, `countAtMaxFree`.
2. **A2 (А).** `NearbySeats.kt`: чип «Мест» / «Мест: 3» (включён при > 1; цвет — `animateColorAsState`, `CanonMotion`) в тот же единственный ряд фильтров (`MapScreen.kt:488`) + шторка «Сколько вас едет» (кнопки −/+ ≥ 48dp, 1…8, `contentDescription` RU+BA, «Показать N поездок» по `nearbyTotal`); карточка `NearbySeatsCard`.
3. **A3 (А).** Запоминание как у условий: `FilterPrefs.loadSeats/saveSeats` (ключ `default_seats` в ящике `yuldash_filters`, `putInt`), строка «Сколько вас обычно едет» в `FiltersScreen`. Лента стартует с него; чип меняет только этот поиск. Ключ — в `SessionKeys.CLEARED_BY_FILE["yuldash_filters"]` (сторож).
4. **A4 (А).** `nearbySearch(…)` и ключи `LaunchedEffect` (`MapScreen.kt:318-319`) получают `seats` — смена места сбрасывает страницу.
5. **A5 (А).** Пусто: `seats > 1`, `hiddenBySeats > 0`, ничего не найдено → новое состояние «seats» (`MapScreen.kt:499-507`): «Для {N} мест поездок нет. Есть {M} поездок, где свободно {K} мест — искать на {K}?», где M = `countAtMaxFree`, K = `maxFreeSeats`, кнопка «Искать на {K}» (seats = `maxFreeSeats`) и «Следить за маршрутом» (RS-10). Скрытых нет — прежнее «пусто» с кнопкой RS-10. «Сбросить фильтры» сбрасывает и места (для этого поиска). При `seats > 1` под заголовком ленты: «Показаны поездки, где свободно {N} и больше».
6. **A6 (А).** В бронь: `wantedSeats` — поле `YuldashViewModel` (`:22`), а не глобальный объект; `MapScreen.kt` берёт ту же модель через `viewModel()` и пишет в неё при смене чипа; `clearUserData()` (`:398`) сбрасывает в 1 при выходе и смене сессии (`AGENTS.md` §7). `YuldashApp.kt:1335` стартует с `vm.wantedSeats` **без автоматического урезания**. Заменить существующий clamp в `BookingSeatCount.kt:45-47`: при `available < wantedSeats` сохранить N, показать нехватку, заблокировать отправку и предложить «Уменьшить до K» либо поиск другой поездки. Только нажатие уменьшения изменяет N и итог; при 0 — только поиск. То же при смене участка/конкурентной брони; сервер остаётся авторитетным и возвращает нехватку без уменьшения группы за человека.

### Сайт (`webapp/`)
1. **W1 (А).** `api/discovery.ts`: `NearQuery.seats` → `seats=` при > 1; `NearRidesPage.hidden_by_seats`, `max_free_seats`, `count_at_max_free`. `api/rides.ts`: `RidesQuery.seats` (зеркало сервера). **`RidesScreen.tsx` (`/rides/feed`) места не применяет и не передаёт**: там нет чипа и строки, поездки пропадали бы молча.
2. **W2.** `filterPrefs.ts`: `seats` (1…8, по умолчанию 1) в JSON, чтение с проверкой диапазона; `write` и `saveVerifiedOnly` не теряют `seats`; строка в `FiltersScreen.tsx`.
3. **W3.** `nearbyFeed.ts`: `seats` в `NearbyFilters`, `nearbyQuery`, `nearbyContextKey`; состояние `"seats"` в `nearbyFeedState`; `seatsHiddenLabel(...)` использует `count_at_max_free` как M и `max_free_seats` как K, не `hidden_by_seats`; правило и фраза строго как A5. `NearbyFilters.tsx`: чип «Мест» + шторка; `HomeScreen.tsx`: состояние `seats` (старт — `loadFilters().seats`), карточка `NearbySeatsCard.tsx`, сброс в `resetFeedFilters`; чип меняет цвет CSS-переходом.
4. **W4.** `RideSheet.tsx`: `initialSeats` из ленты (иначе `loadFilters().seats`) — стартовое значение в `useState` и в сбросе `:85`, **без clamp** по `seats_left`. При нехватке после обновления/смены участка — сохранить N, отключить отправку, показать «Уменьшить до K» с новым итогом; только отдельное нажатие меняет N, как A6. Случай 0 — поиск другой поездки.
