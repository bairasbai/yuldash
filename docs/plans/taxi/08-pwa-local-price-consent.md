# PWA: локальная интеграция подтверждения начальной цены

Клиентский пакет непосредственно зависит от серверного `2ae7e0ec5c1329bde30cf5dfa8ed7a9c45159804` и [контракта v1](07-initial-price-consent-api.md). Это отдельное продолжение серверной ветки, а не независимый патч к main. TF09-A/TF09-B и другие клиентские ветки не включены. Из TF09-B переиспользован принцип отсчёта свежести с начала запроса, включая время вне вкладки.

## Отключён по умолчанию

Защищённый путь требует явного `VITE_TAXI_QUOTE_CONSENT_LOCAL=1` **и** loopback у настоящего UI и явного `VITE_API_BASE`: только localhost, 127.0.0.1 или ::1 по HTTP(S). Неверная запрошенная конфигурация блокирует подтверждение, не возвращает старый POST. Без флага прежний режим и предзаказы работают прежним путём. Флаг сборки не является сетевой изоляцией: браузерную проверку разрешено начинать только после проверки синтетического API/БД и запрета внешнего трафика.

Для пользователей режим включать нельзя: положительное чтение по ключу не доказывает отсутствие заказа и не даёт окончательно снять неизвестность. Backend, Android, тарифы, зависимости и lockfile этим пакетом не меняются.

## Сумма и запрос

Quote и create получают один набор входов: координаты начала/конца, упорядоченные остановки, класс, все поддерживаемые опции, обратный путь и ожидание обратно. Полное операционное тело передаётся только при подтверждении. Клиентская сумма серверу не отправляется. CTA, первое и повторное подтверждение используют `payable_kop`: 60000−15000=45000 → 450 ₽; без скидки 60000 → 600 ₽. Описание диалога показывает тот же итог и согласованную разбивку.

Истечение срока, в том числе в открытом диалоге, сначала запрашивает новую оценку. Обновление не создаёт заказ: нужно ещё одно явное нажатие. Поздняя оценка другого ввода/сеанса игнорируется. После `409 taxi_quote_price_pending` объясняем неизвестную стоимость подачи, предлагаем пересчёт, не отправляем ни старый, ни новый создающий POST. Уход водителя после полной оценки не означает отсутствие заказа: показываем фактический возвращённый статус и текущую `passenger_price_kop`, включая восстановленную карточку. Историческое начальное согласие не подменяет текущую terminal-сумму: промо при окончании поиска может освобождаться по серверному контракту. Эта карточка не обещает списание или вечную фиксацию цены.

## Неизвестный результат

Новые операции сохраняют до POST только маркер v2: ключ localStorage — существующий префикс и настоящий серверный `request_key`; значение — ровно `{v:2,g,e}` (случайное поколение текущего входа и loopback-окружение UI/API). Запись проверяется чтением до отправки. Нет `quote_id`, тела, цены, координат, адресов, контактов, комментариев, токенов или отпечатков. Существующий ключ не перезаписывается. Настройки/сохранённые места приложения этим пакетом не расширяются.

Старый маркер v1 содержит случайный **локальный** UUID. Он не соответствует серверному ключу: его нельзя передавать в lookup, преобразовывать в v2 или удалять как доказанный результат. Старые записи продолжают блокировать новое подтверждение. Чтение другой сессии или окружения ничего не удаляет. Штатная очистка при logout не меняется.

Исходное сериализованное тело, пара ключей и снимок хранятся только в памяти компонента. После неизвестного ответа явный повтор использует ровно эти байты и прежние ключи в том же живом входе и окружении **раньше проверки TTL**. Нет автоматического повтора POST при 401. Reload/Back с потерей памяти не реконструирует создание. Logout/новый вход, даже тем же пользователем, не возобновляет запрос.

Для маркера v2 после потери памяти доступно отдельное явное действие «Проверить результат заказа». Только авторизованный `POST /instant/orders/result/v1` с JSON `{request_key}`; ключ не попадает в URL или логи. `committed` разрешает следующий авторизованный GET деталей по точному `order_id` с привязкой к прежнему входу, окружению и всё ещё принадлежащему ему маркеру. Проверяются ID, роль пассажира и фактическая карточка. Только после этого удаляется собственный v2 и показывается текущий статус/сумма. Историческая `initial_payable_kop` не заменяет текущую `passenger_price_kop`. Ошибка удаления маркера не отменяет доказанную карточку, но сохраняет консервативный барьер.

`unknown`, 503/404, истечение срока, пустой список или исчезновение заказа между двумя чтениями не доказывают «не создан». Маркер остаётся; новый создающий POST запрещён. После `committed` с неудачным GET текст сообщает, что заказ был создан, а текущая карточка недоступна. Поздние ответы другого входа/окружения и после ухода с экрана игнорируются. Нет автоматического lookup по таймеру/фокусу, окончательного отрицания, outbox или гарантии восстановления подбора после серверного сбоя.

## Отдельная зависимость чтения результата

Этот follow-up имеет parent PWA `8af737d2599d2c0b060db9c44520320c66e8f31a`. Для интеграционных проверок нужен **внешний**, отдельно закреплённый API `3b865d0dd6e84bddf29e3bf2330cbab85c07cbaf` и его [контракт положительного результата](https://github.com/bairasbai/yuldash/blob/3b865d0dd6e84bddf29e3bf2330cbab85c07cbaf/docs/plans/taxi/08-price-consent-result-api.md). Оба — дочерние ветки `2ae7e0e`; серверная ветка здесь не слита и backend не скопирован. На исходном сервере PWA без result endpoint проверка оставляет безопасный барьер. Перед будущим merge требуется отдельная интеграция обеих веток с актуальным main и её проверка. Окончательное «не создан» и освобождение неизвестного исхода — следующая самостоятельная серверная задача.

## Проверка и границы

Штатный PWA gate: Node22, `npm ci`, `npm run check`, `npx tsc --noEmit`, `npm run build`. Отдельные unit проверяют строгий loopback/конфигурацию, копейки/разбивку, тождество ответа, свежесть и минимальное хранилище. Браузерный стенд использует реальную сборку, FastAPI/auth/SQL/fakeredis, управляемое тестовое время и синтетические данные; запрет внешней сети подтверждается до входа. Потеря ответа моделируется после настоящего commit. Подмена пустого списка — явно транспортная неисправность, не доказательство серверного отсутствия заказа.

Проверяются RU/BA × светлая/тёмная, 450/600, срок/фон, два таба, опции/маршрут, смена сеанса, точный повтор после commit/истечения без второго заказа и подбора, reload/logout, неизвестная подача/уход водителя и совместимость старого пути/предзаказа. Фактические коды выхода и исходные отказы хранятся в отдельном отчёте приёмки точного дерева. Это не общая E2E-приёмка такси, Android, скринридер, реальное устройство или разрешение выпуска. Перед будущим merge нужна интеграционная проверка с актуальным main и совместимым сервером.

Новые BA-строки — черновики, см. «Переводы на проверку» в tasks.md.

Проверка этого follow-up: настоящий API `3b865d0` в отдельной read-only копии, временная SQLite/fakeredis, Chromium в собственной внутренней сети без внешнего маршрута; 31 новый сценарий восстановления (29 + 2 актуального cancelled), 35 прежних, 2 opt-out, 2 scheduled и 3 независимых — exit0. Проверены RU/BA, обе темы, 320/390, отсутствие второго create/подбора, версия маркера до POST, actual current card после expiry/возврата скидки/отмены, precommit, удаление между чтениями, смена входа/API и отсутствие lookup для v1. Node22 check/typecheck/build и секрет-скан восьми путей — exit0. Это приёмка отдельного PWA parent с внешним API, не объединённого main; окончательное отрицание и включение пользователям не заявлены.
