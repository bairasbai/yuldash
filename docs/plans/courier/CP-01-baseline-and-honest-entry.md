## 1. Что получит человек

Человек не видит «курьер уже едет», если режим ещё закрыт, и не начинает неподдерживаемую услугу. Разработчик продолжает имеющуюся доставку, не строит вторую.

## 2. Что уже есть в коде

Courier/parcel flags default false: config.py:612/621. Раздельный DeliveryGate.kt:34–120; PWA ParcelsScreen:85–131. Есть старый план июля и сентябрьский dispatch ТЗ; PR211 содержит планы RS со статусом «не начато».

Это read-only сведения, не результат запуска. [Реестр источников](07-source-register.md) разделяет существующий код, старый план, исследование и предлагаемое изменение.

## 3. Что сделать

### Разница и решения

Снять новый baseline фактов после RS: реально merged механизмы, endpoints, schema, consumers, рабочие флаги (без доступа к секретам), открытые PR. Сделать карту reuse/delta/blocked и честную capability-витрину.

Инженерный договор ниже предлагается для реализации после review. Численные продуктовые параметры, договоры и production включение не утверждаются этим планом; открытые решения указаны в [gates](06-launch-gates.md).

### A Сервер

1. Инвентаризировать все входы создания/claim/paid/status, legacy и admin routes, workers/cleanup.
2. Матрица effective gates: глобальный courier, вид услуги, зона, транспорт, минимальная версия, provider/legal readiness. Серверный отказ обязателен даже при скрытой кнопке.
3. Disable закрывает новые заявки/назначения, но сохраняет завершение активных custody/поддержку/сверку.
4. Перенести только проверенные общие RS contracts; незавершённый predecessor остаётся blocked.

### B Android

Согласовать режимы Попутка/Курьер/Такси без удаления текущих вкладок; «Скоро»/«Пока нет курьеров»/«Услуга недоступна» не смешиваются. Проверить deep links, cold start и старую сохранённую вкладку.

### C PWA

Тот же capability DTO и причины недоступности. Не считать существующий экран feature enabled; прямой URL закрытого режима не обходит gate.

### API и события

GET /courier/v2/capabilities из C4. Ошибки FEATURE_DISABLED/COVERAGE_UNAVAILABLE; effective state читается из authoritative настроек, не только клиентского кеша.

Общий контракт [C1–C9](02-domain-api-contracts.md) обязателен: actor/phase allowlist, версии, денежные единицы, durable intent, replay и удаления. Новые DTO не расширяют права автоматически.

## 4. База данных

Нет новой миграции, если RS owner switches доступны. Добавление key с audit — только существующий реестр; неизвестная foundation блокирует код, не рождает второй AppSetting.

Проверки previous-main → target, synthetic legacy rows, SQLite + PostgreSQL, backfill/crash/resume, downgrade/up и runtime rollback выполняются по [D2](04-data-migrations-and-queue.md#d2-порядок-миграций). Новые персональные поля имеют purpose/retention/account deletion по D3; неизвестный срок блокирует production, не заменяется вечным хранением.

## 5. Надписи

«Курьер пока не доступен в этом районе». «Нет подходящего курьера на выбранное время». «Текущую доставку можно завершить, новые заказы временно не принимаем».

Все строки через appText(ru, ba)/соответствующий PWA словарь. Башкирский — черновик для носителя, не автоматический linguistic PASS. Денежные строки только через общий форматтер копеек; секреты не попадают в preview уведомлений.

## 6. Состояния экрана

Выключен/не запущен/временно закрыт/нет предложения/активная доставка при закрытии, неизвестный capabilities ответ, upgrade required.

Обязательны loading/empty/error/offline/retry, сохранённый ввод, длинный BA, light/dark, крупный шрифт,48 dp и контраст≥4.5:1. Состояния requested/pending/applied/unknown/conflict различимы; optimistic UI не доказывает завершение.

## 7. Тесты

Положительный: активный legacy заказ доступен после disable. Отрицательный: прямой POST/старый клиент/admin bypass не создаёт новый. Mutation: удалить серверную проверку flag — тест красный. Обновление capabilities в двух вкладках/после restart.

Все тесты из этого раздела NOT_EXECUTED. Исполнитель сохраняет точный SHA, команды/exit codes, платформу, expected/actual, первичные артефакты. Для затронутого сервера ruff/pytest и migration guards; Android unit/Compose/GuardTest + assembleDebug; PWA check/build и целевые тесты. PostgreSQL race, два физических телефона и реальный provider не подменяются SQLite/emulator/mock.

## 8. Приёмка

Есть pinned baseline и список неподтверждённых механизмов; каждый существующий route/worker классифицирован. Кнопки и API сообщают одинаковую возможность. Никаких цифр готовности или ложной приёмки RS.

Независимый принимающий сверяет код, права/контракты и первичные доказательства, не только список тестов. Принятие текста не принимает реализацию. Продуктовый статус «принято» только в существующем audit registry; [COURIER-E2E](../../audit-traceability/courier-scope.md) не сокращается.

### Мозг

После разрешённой реализации: architecture — изменённые экраны/модули/связи; decisions — реальные решения владельца и принятые договоры; tasks — прогресс и BA на проверку; lessons — воспроизводимые ошибки. Общие docs имеют одного писателя. Этот документационный пакет не проставляет runtime PASS.

## 9. Риски и запрещённые сокращения

Нельзя переименовать старый C1–C4 в «не существовало». Нельзя править AGENTS для расширения своих прав, включать courier по факту написанного ТЗ или использовать RS08 как разрешение банковских платежей courier.

Не выдавать default за production config, plan за реализацию, локальный callback за серверный commit, HTTP success за физическое вручение или платёж. Не запускать реальные заказы/платежи ради теста без отдельного разрешения. Новые зависимости/SDK/права не добавлять без обоснования по AGENTS.
