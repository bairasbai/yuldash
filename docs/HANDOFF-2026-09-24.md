## Последняя выполненная группа: QA-B02-003

**Одна подтверждённая причина, два воспроизведения.** В `BookingActiveTripScreen.kt`, функция ActiveTripScreen, начальная цепочка `getMessages → getBoardingCode → getBookingDetails` после смены A→B могла продолжить запросы старого экрана с токеном B. ApiClient защищал отдельный поздний ответ, возвращая ошибку смены сессии, но следующий вызов захватывал уже новый аккаунт.

Исправление: проверять исходный `tripSession` перед стартом и после каждого suspend-запроса, до изменения Compose-состояния и следующего вызова. При смене поколения входа завершать весь LaunchedEffect.

Новые тесты:

- `ActiveTripSessionChainTest.kt`: удержать messages либо boarding-code, переключить A→B, освободить ответ, проверить отсутствие следующих code/details с ключом B. До исправления оба теста падали именно на таких запросах. После исправления проходят. Наблюдение сети ограничено двумя секундами; это не доказательство отсутствия любых будущих callbacks.
- `ActiveTripLateTerminalTest.kt`: удержать успешный ответ кода до серверного done и удаления паспорта с диска; освободить ответ и дождаться следующего details как свидетельства обработки кода. Завершённая поездка не оживает, старый/поздний код не виден, паспорт отсутствует после переинициализации, другая бронь сохранна. Этот тест проходил уже до нового исправления, поэтому это подтверждение существующей защиты, а не новая исправленная ошибка.

Оба теста находятся в `android/app/src/test/java/com/yuldash/app/`.
Локальные Compose/Robolectric + MockWebServer, не настоящий сервер/телефон. Не утверждать, что доказана выдача чужих данных рабочим сервером: доказаны нежелательные запросы.

Проверка после исправления: **22/22 теста в 7 классах**, 0 ошибок/пропусков; `:app:assembleDebug` успешен; общий запуск 1м38с. Новых уникальных сценария 3, а не 22.

2. В новом управляемом тесте удержать ответ роли/статуса A, сменить вход на B, отпустить ответ; проверить позднее применение результата и следующий цикл опроса. Наличие ошибки пока не объявлено: нужно воспроизвести.
3. При подтверждении исправить привязку именно этой цепочки к исходной сессии. Проверить нормальный опрос без смены входа и сохранение терминального done/cancelled.
4. Затем отдельно проверить callbacks ChatSocket, загрузку истории при reconnect и последовательные запросы после flushOutbox. Не считать их закрытыми тестами начальной загрузки.
5. Записать результаты в QA-B02-003, сохранить журналы, обновить инвентаризацию. Не закрывать весь B02 по нескольким тестам.

Полезные файлы: `BookingActiveTripScreen.kt`, `data/ApiClient.kt`, `data/ChatSocket.kt`; прежние тесты `data/ApiClientLateMutationSessionTest.kt`, `ActiveTripDeletionTest.kt`. ApiClient.queueSessionGeneration меняется при входе/выходе. Ошибка устаревшей сессии возвращается как Result.failure, сама по себе не останавливает вызывающую цепочку.

Для вертикального скролла выбирать VerticalScrollAxisRange: общий hasScrollAction может найти также горизонтальную строку быстрых сообщений. Тесты не должны обращаться к рабочему серверу.
