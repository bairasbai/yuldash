# Офлайн-паспорт на экране брони — 20.09.2026

## Две воспроизведённые проблемы

1. Серверные детали подтверждённой брони загружены, но запись локального паспорта отклонена незавершённым переносом. Экран игнорировал результат save и не сообщал об отсутствии офлайн-копии. BookingOfflineSaveTest показал настоящего серверного водителя, проверил отсутствие паспорта новой брони, затем упал именно на отсутствии предупреждения. Источники: booking-offline-save-red-20260920.log/XML.
2. Отказ загрузки кода посадки превращался в пустую строку через getOrNull().orEmpty(). Успешная запись затем затирала ранее сохранённый код. Два отдельных UI-теста воспроизвели HTTP 503 и HTTP 200 с пустым code: ожидалось 4821, получена пустая строка. Источники: booking-offline-code-red-20260920.log/XML.

Это две причины, а не три независимые ошибки по числу красных тестов. Проверки используют настоящий BookingScreen, локальный MockWebServer и модель SharedPreferences с раздельными памятью и диском. Временные отказы записи моделируются; настоящее повреждение памяти телефона не создавалось.

## Сверка с main и исправление

В локальном main 527dbb0 сохранён тот же помощник saveTripPass, игнорирующий результат, и та же подмена недоступного кода пустой строкой. Но отказ save из-за незавершённого журнала относится к текущей рабочей ветке: в main ещё старая реализация хранилища Unit/apply. Правки выполнены в codex/push-routing-audit, без изменения main и без коммитов.

Экран отдельно показывает предупреждение о несохранённой офлайн-копии, сохраняя серверные детали и возможность открыть поездку. Кнопка «Сохранить ещё раз» повторяет получение кода и локальную запись, не создаёт бронь и не перезагружает её детали. Пока операция выполняется, виден индикатор и повторная кнопка скрыта. Карточка использует существующие Canon-компоненты и AnimatedVisibility; строки заданы через appText на двух языках. Башкирские переводы — черновики, добавлены в docs/tasks.md на проверку.

TripPassStore.save по явному запросу повторяет незавершённый перенос перед записью. Обычные вызовы не начинают повтор автоматически. Повтор не снимает карантин после неподтверждённого выхода. Перед записью проверяется поколение сессии: результат прежнего входа не должен сохраниться в новой сессии. Повтор переноса и запись находятся под общим монитором хранилища, работа с диском выполняется в Dispatchers.IO.

Отказ получения кода и пустой код теперь возвращают false до локальной записи. Старая полная копия остаётся на месте; повтор после восстановления сервера сохраняет новые данные. Это не проверка актуальности старого кода сервером: старый код просто больше не стирается неудачным запросом.
