# Карточка: `backend/app/routers/safety.py`

- Статус: verified
- Лист: leaf-3.1

## Назначение

Все серверные двери безопасности поездки: красная кнопка SOS (с контекстом «где» и «с кем»,
SMS доверенным, Telegram дежурному), её админ-лента и приём в работу, запрос обратного звонка,
жалобы §9 (анонимные, с правом «не заплатил» и требованием фото по «грязно»), чёрный список
(блокировка + приватность имён), список «на кого можно пожаловаться», зимний протокол
(«застрял на трассе» + авто-проверка «доехал?» для попутки/такси/доставки). Один файл на все
три сценария (попутка/такси/доставка) — логика `_roadside`/`_winter_run` общая, различаются
только «кого спрашивать» и «кому звонить».

**Правка по итогам независимого ревью (REQUEST_CHANGES → исправлено).** Первый проход листа
нашёл и починил только E1 (сырой текст исключения в логе, см. «Найденные ошибки»), но пропустил
8 находок серьёзнее (две — P1), часть из них карточка ошибочно отмечала как «ок». Все восемь
(N1–N8) исправлены в этой версии карточки — см. «Найденные ошибки».

## Связи

- Таблицы: `SosEvent`, `Report`, `Block`, `TrustedContact`, `TripShare` (только читает —
  создание/отзыв живёт в `routers/family.py`, ВНЕ зоны), `Booking`/`Ride`/`InstantOrder`/
  `ParcelDelivery`, `DriverProfile` (пауза такси — читает/пишет напрямую для N1).
- Зовёт `safety_logic.have_met` (приватность блок-листа), `safety_logic.trip_really_happened`
  (требование фото), `winter_escalate.escalate_now`/`ESCALATE_AFTER_MIN`/`_winter_identity_pattern`
  (🆕 для N3), `quality.*` (пауза/лестница/уведомления — ВНЕ зоны), `debt.*`/`carphoto.*`
  (побочные эффекты — ВНЕ зоны), `app.observability.scrub_exc`.
- Android: `SosScreen`, `RoadsideHelp.kt`, `WinterProtocol.kt`, `ActiveSharesList`,
  `BookingActiveTripScreen`/`InstantOrderScreen` (шторки «поделиться») — клиент вне зоны, не
  трогал.
- `sos_escalate.escalate_unhandled` читает `SosEvent.status`, который меняют
  `admin_sos_handle` (в т.ч. дубли, N4) и `_winter_ack` (зимняя тревога, N3) — после любого из
  них эскалация этот сигнал больше не видит.

## Остаток и ограничения

- **Честно про `with_for_update` в N8 (самопроверка после прогона поломок).** Первая версия
  этой правки заявляла мутацию M17 (снять `with_for_update` на resolve) и тест-гонку на
  PostgreSQL как доказательство, что без замка бывает двойной возврат комиссии. При прогоне
  M17 **SURVIVED**: тест прошёл ОДИНАКОВО что с замком, что без него. Разбираясь — поток-level
  `threading.Barrier` синхронизирует СТАРТ двух запросов, а не момент самого SQL-запроса к
  Postgres; в прогоне одно исполнение, видимо, успевало полностью завершиться (включая свой
  `COMMIT`) раньше, чем второе доходило до своего `SELECT`, и настоящего пересечения двух
  открытых транзакций форсировать не удалось. Вместо того чтобы это скрыть, убрал M17 из
  спецификации (была бы poломка без доказательства) и переписал докстринг теста честно: он
  проверяет КОНЕЧНЫЙ результат (не больше одной записи в `LedgerEntry`), которую реально
  обеспечивает идемпотентность по статусу (M18, подтверждено). Сам `with_for_update` оставил
  в коде как defense-in-depth без собственной мутации — у `debt.py::refund_commission_to_wallet`
  нет уникального ограничения на `ext_id` (подтверждено чтением модели: `UniqueConstraint` для
  `LedgerEntry` отсутствует), то есть при НАСТОЯЩЕМ пересечении двух транзакций двойной возврат
  теоретически всё ещё возможен — это открытая находка на границе с `debt.py` (вне зоны,
  согласовано с F3 leaf-1.1), а не доказанная защита с моей стороны.
- Разгадка нестабильности на PostgreSQL из предыдущей версии карточки — см. раздел 4
  независимого ревью, кратко изложено выше во врезке «Разгадка…».
- **ВНЕ ЗОНЫ — находка (не моя правка).** Системный паттерн «сырой `{e}` в лог» живёт ещё
  в ~38 файлах проекта (`debt.py`, `carphoto.py`, `services.py`, `db.py`, `taxi_worker.py:444`
  и далее — независимое ревью насчитало то же самое отдельно). Чинить целиком вне OWNS не стал.
- **ВНЕ ЗОНЫ (рекомендации независимого ревью, не блокируют).**
  - N9: `sos_escalate._есть_куда_слать` (чужой файл в этом же листе — см. его карточку)
    считает mock-SMS «настроенным каналом», хотя `services.sms_channel_live()` сказал бы
    честно. Из-за этого при реально ненастроенном Telegram громкого `log.error` не будет
    никогда — вместо него вечный тихий повтор. Код этой карточки не затрагивает.
  - N10: подсказка «дежурный уже видит его» при заглушённом/выключенном SMS ничем не
    проверяет, настроен ли вообще Telegram (`274–289` шлют и забывают результат).
  - N11: один общий потолок `SOS_SMS_PER_HOUR` на красный SOS, «застрял» и зимние тревоги —
    шумная зимняя ночь может исчерпать бюджет до настоящего SOS.
  - N12: пуш цели «Поступила жалоба» уходит и по жалобе без реальной встречи (отличие от
    авто-паузы, которая требует `trip_really_happened`) — 10 жалоб/час и 11 категорий
    превращают это в инструмент запугивания.
  - N13 (решение Александра, 152-ФЗ): `_car_of` отдаёт госномер по ЛЮБОЙ брони, где нажавший
    формально участник, включая `pending` (одна кнопка «Забронировать», без подтверждения
    водителем) — в отличие от карточки брони, где номер открывается только после
    подтверждения. Можно забронировать чужую поездку вторым номером и получить госномер
    незнакомого водителя через красную кнопку. Латентно (SMS = mock на проде), но это вопрос
    политики («в беде номер полезен» против утечки ПДн), не инженерная находка — **не решал
    сам, передаю Александру как есть**.
  - Порядок фоновых задач в `/sos`: SMS близким (до 10с/контакт) стоит ПЕРЕД Telegram
    дежурному — медленный SMS-шлюз задерживает уведомление дежурного. Рекомендация ревью:
    поставить Telegram первым. Не менял — порядок внутри `BackgroundTasks` не влияет на
    итоговую доставку (оба уходят), только на задержку конкретно дежурного относительно
    близких; выбор, что важнее first, — продуктовое решение, а не баг.
  - Лимит `/sos` по IP (`middleware.py`, 30/мин) считается ДО входа — за общим NAT/Wi-Fi
    соседи делят бюджет красной кнопки. Полностью вне зоны (общий лимитер).
  - Эскалация SOS и шаг зимнего протокола идут из `taxi_worker.run_once` под флагом
    `taxi_worker_enabled` — выключат такси-воркер, молча выключится и тревога. Вне зоны
    (воркер и его флаг не в OWNS).
  - Зимняя SMS близким (`winter_escalate.py:161`) — только по-русски (нарушение двуязычия),
    но сам файл вне зоны.
  - Android: `ApiClient.sos(...).map { }` выбрасывает честный ответ сервера
    (`contacts_notified`/подсказки) и всегда показывает одну и ту же осторожную фразу;
    координаты нажавшего кладутся в `note` на клиенте. Вне зоны (Android не в OWNS).
- `_report_counterparty` без привязки к поездке (голый `target_user_id`) по-прежнему не
  проверяет пересечение сторон — это СОЗНАТЕЛЬНАЯ политика (можно пожаловаться на
  постороннего, админ увидит), защищённая потолком/дедупом и отсутствием авто-наказания
  (`trip_really_happened`). Не менял.
- Двойное нажатие SOS по-прежнему пишет ДВА события на входе (намеренно, «жизнь дороже») —
  склейка происходит на ВЫХОДЕ, при «Принял» (N4). Это сознательный выбор архитектуры, не
  компромисс.
- Производительность: ни один обработчик файла не `async def` с синхронным HTTP внутри
  самого запроса; все HTTP-вызовы — в `BackgroundTasks` или в синхронных `def`-ручках
  (threadpool). Проверено явно (п. 4а брифа).
