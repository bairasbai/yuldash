# Карточки пофайлового обхода

Каждый файл из охвата обхода (список и отметки — [../audit-file-status.md](../audit-file-status.md)) получает
одну карточку: `docs/audit-files/<путь файла>.md`. Например, для `backend/app/ledger.py` —
`docs/audit-files/backend/app/ledger.py.md`.

Карточка — доказательство «что именно проверено». Отметку в реестр ставит только приёмка:
`python tools/audit_file_status.py apply --leaf <лист> --files <файлы>`. Инструмент проверяет структуру
карточки, существование каждого упомянутого теста и описание нарочных поломок, а потом записывает
отпечаток (SHA256) файла. Изменился файл — отметка устаревает (🔄) до новой проверки.

## Статусы

| Код | Значок | Когда ставить |
|---|---|---|
| `read` | 🟨 | Файл прочитан целиком, все функции разобраны, подозрения записаны, но тестов-защитников пока не хватает. |
| `verified` | 🟩 | Каждое важное правило файла защищено тестом, и хотя бы одна нарочная поломка (для денег и входа — на каждое правило) этим тестом поймана. |
| `bug` | 🟥 | Найдена подтверждённая ошибка, исправить её в этом листе нельзя (например, нужен чужой файл). |
| `blocked` | ⛔ | Проверка невозможна без внешнего доступа (настоящий телефон, реальная оплата, ключ подписи). Обязательна строка `Причина:`. |
| `inactive` | ⚪ | Файл нигде не исполняется (архив, артефакт отчёта). Обязательна строка `Причина:` с доказательством. |

## Что значит 🟩 для разных файлов

- **Код Kotlin/Python:** каждое важное правило файла закрыто тестом, который проверяет результат и
  побочные действия, а не «не упало». Минимум одна нарочная поломка на файл; для денег, входа и
  личных данных — на каждое правило.
- **Экраны Compose:** тест на компьютере (Robolectric) — загрузка, пусто, ошибка с повтором, успех,
  русский и башкирский текст, кнопки делают своё. Эмулятор — только если без него никак.
- **Миграции базы:** общий тест «применить всё на пустой PostgreSQL → откатить → применить снова» и
  сверка итоговой схемы с моделями. Поломка — например, убрать операцию из миграции.
- **Манифест, сборка, правила сжатия кода:** сборка плюс тест-сторож конкретного правила.
- **Скрипты сервера и CI:** проверка синтаксиса и запуск на тестовой копии. На боевом сервере — никогда.
- **Справочники данных:** тест формата (всё читается, нет дублей и битых координат).

## Формат карточки

Заголовки второго уровня и строки `- Статус:` и `- Лист:` проверяет инструмент — их не переименовывать.
Ссылка на тест: `путь::имя`. Для имён с пробелами (Kotlin) — `путь::"имя с пробелами"`.
Для pytest — `backend/tests/.../test_x.py::test_name` или `...::TestClass::test_name`.
Несколько тестов одного файла в одной ячейке: `путь::test_a, ::test_b` — голое `::имя` берёт путь предыдущей
ссылки в той же ячейке. Голое `::имя` без такого пути в ячейке — ошибка `check-cards`, а не молчаливый пропуск.

Ссылки читаются из таблицы «Важные правила и тесты». У 🟩 они обязательны; у 🟥 и 🟨 — по желанию, но каждая
указанная ссылка и каждая строка `| M… |` обязаны найтись, и `run-tests` прогоняет эти тесты вместе с тестами 🟩
(в выводе видно, какая карточка сколько дала). У ⚪/⛔ доказательство — строка `Причина:`, их тесты не читаются.

```markdown
# Карточка: `backend/app/ledger.py`

- Статус: verified
- Лист: leaf-1.1
- Проверял: Sonnet 5 (leaf-1.1); принимал: Opus 5.5
```
