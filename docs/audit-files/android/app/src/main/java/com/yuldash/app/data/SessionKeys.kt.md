## Назначение

Декларативный реестр «что происходит с каждым ключом настроек при выходе из аккаунта» — чистые
данные (`object` без логики), которые читает и `ApiClient.clearLocalSession`/
`clearAssociatedPersonalData` (стирает), и `AuthStorePolicy` (мигрирует/чистит), и сторож
`SessionKeysGuardTest` (требует решения у КАЖДОГО ключа, который приложение реально пишет на
диск). Главный сценарий защиты — телефон переходит из рук в руки (муж/жена, родитель/сын, продажа
б/у телефона): выход обязан унести чужие данные и фоновые идентификаторы (номер брони/посылок, по
которым фоновый GPS-сервис умеет «воскреснуть»), но оставить настройки САМОГО устройства (язык,
тема, звук).

## Связи

`ApiClient.clearLocalSession`/`clearAssociatedPersonalData` (обходят `CLEARED_BY_FILE`),
`AuthStorePolicy` (читает `CLEARED_ON_LOGOUT` при миграции/логауте — см. карточку
`AuthStorePolicy.kt.md`), `TripPassDeletion.KEY`/`OfflineMigration.JOURNAL` (ссылки в
`CLEARED_BY_STORE`). Используется тремя «дверями» конца сессии: кнопка «Выйти», удаление
аккаунта, «сессия истекла» (`YuldashApp.endSession`).
