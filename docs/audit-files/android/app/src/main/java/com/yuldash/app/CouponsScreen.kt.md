## Назначение

Купонный маркетплейс «Скидки по пути» — витрина скидок от местных заведений-партнёров для
пассажира. Две вкладки: «Скидки рядом» (публичный список `getCoupons`, фильтр-чипы по городу,
по умолчанию — родной город из профиля) и «Мои купоны» (активированные, `getMyCoupons`). Тап по
купону → детальная карточка → «Активировать скидку» (`activateCoupon`) → крупный одноразовый КОД
для показа в заведении. Скидку физически даёт заведение, не Юлдаш (честный дисклеймер на экране).
Жалоба «тут что-то не так» (`reportCoupon`) ставит купон перед глазами админа, но не снимает его.

Файл также хранит четыре переиспользуемых по всему приложению хелпера: `couponCategoryIcon`,
`couponCategoryLabel`, `kopToRub`, `shortDate` — их вызывают `PartnerCabinetScreen`,
`AdminPromoScreen`, `AdminParcelsScreen`, `CarPhotoScreen`, `DriverProfileScreen`,
`TaxiDocsScreens` и другие файлы вне зоны этого листа.

## Найденные ошибки

| ID | Что было (по-человечески) | Как воспроизвести | Исправление | Тест: до → после |
|---|---|---|---|---|
| B1 | Срок действия купона мог показываться на ДЕНЬ РАНЬШЕ настоящего. Сервер шлёт момент окончания скидки в UTC; старый код просто брал первые 10 символов строки вместо перевода в уфимское время. Если купон истекал, например, в 2 часа ночи по Уфе, пассажир видел дату на сутки раньше — и мог решить, что скидка уже кончилась, хотя она ещё действовала несколько часов | `shortDate("2026-07-05T21:00:00")` (сервер: конец скидки — 2 часа ночи 6 июля по Уфе) — старый код возвращал «05.07.2026» вместо «06.07.2026» | Переписал `shortDate`: для полного момента переводит UTC→Уфа через уже существующий в проекте `parseIsoUtcMillis` (тот же приём, что `formatDepart` в `MainActivity.kt`, разбор №2); чистую 10-символьную дату без времени (её мог обрезать сторонний вызывающий код) оставляет как есть | `ShortDateUfaTimezoneTest::crossesIntoNextUfaDay`: до фикса возвращал «05.07.2026» (неверно) → после фикса «06.07.2026» (верно). Подтверждено также мутацией M1 (откат фикса → тест падает) |

Проверено, но НЕ является ошибкой в рамках этого листа (относится к чужому файлу, см. отчёт
ведущему, раздел «ВНЕ ЗОНЫ»):

- Круговой путь «показ → правка → сохранение» срока купона в кабинете партнёра
  (`PartnerCabinetScreen.kt::CouponForm`, строка 573) режет `initial.validUntil` тем же способом,
  каким `shortDate` резал ДО фикса — без перевода часового пояса. Это опаснее: при сохранении без
  изменений резаная дата уходит на сервер как обычная правка, и при следующем открытии формы
  сдвигается ещё на день назад. Добавил сюда готовый хелпер `ufaIsoDate` для правильного чтения —
  владельцу файла остаётся одна строка замены, см. отчёт.

## Остаток и ограничения

- `kopToRub` не вызывается напрямую внутри этого файла для денежных расчётов (только
  переиспользуется другими экранами) — его собственные тесты (`MoneyFormatTest.kt`,
  `MoneySourceGuardTest.kt`) лежат вне зоны этого листа, новых не добавлял, чтобы не дублировать.
- Пустое состояние «Мои купоны» (кнопка «Посмотреть скидки» → переключает на вкладку «рядом»)
  прочитано и проверено чтением кода, но без отдельного UI-теста/мутации — сочтено менее
  рискованным, чем явные пункты фокуса листа (деньги, повтор запроса, часовой пояс, сеть); при
  нехватке времени приоритет отдан им.
- Жалоба на купон (`ReportCouponDialog`/`reportCoupon`) и дозвон по номеру заведения
  (`Intent.ACTION_DIAL`) проверены чтением кода (ограничение длины, непустой текст, двуязычность),
  без отдельного Robolectric-теста — тоже сознательный приоритет в пользу денежных/сетевых правил.
- Эмулятор не запускал (по правилам листа — дорого, достаточно Robolectric).
