# Карточка: `android/app/src/main/java/com/yuldash/app/SecureWindow.kt`

- Статус: verified
- Лист: leaf-2.2
- Проверял: Sonnet 5 (leaf-2.2); принимал: Opus 5.5

## Назначение

Точечная защита экрана от скриншота и от превью в списке недавних приложений: ставит
`WindowManager.LayoutParams.FLAG_SECURE` на `Activity.window`, пока открыт конкретный экран
(не всё приложение — обычный скриншот своей поездки «скинул мужу номер машины» остаётся рабочим).
Вешается на экраны, показывающие ЧУЖИЕ документы/лица (`AdminDriversScreen`, `AdminCourierScreen`,
`AdminTaxiScreen`, и везде, где грузится приватная картинка через `authedImageRequest` —
см. `SecureImageRequest.kt`).

## Связи

`WindowManager`/`Activity` (Android framework). Вызывается из экранов с приватными документами —
список подтверждён `SecureWindowGuardTest` (структурный поиск `authedImageRequest(` без
`SecureWindow()` рядом в том же файле).

## Остаток и ограничения

- R3 (счётчик реально защищает НИЖНИЙ экран при вложенности) не проверен ПОВЕДЕНЧЕСКИМ тестом
  (рендер `SecureWindow()` внутри `SecureWindow()` на Robolectric + `shadowOf(activity.window)` +
  снятие верхнего → флаг должен остаться). Существующий `SecureWindowGuardTest` проверяет только
  что слово `secureDepth` ЕСТЬ в файле — это слабее. Я НЕ стал добавлять свой тест под R3: сборка
  `ShadowWindow`/реального `FLAG_SECURE` в Robolectric требует `@Config(application=...)` с
  Activity-контроллером (`Robolectric.buildActivity`), и у меня не было времени поставить его
  надёжно без риска написать тест, который «зелёный» по случайности (см. п.4а брифа — поломка
  должна ловиться утверждением, а не довериться структурному совпадению). Честно оставляю это
  подозрением, а не закрытым правилом.
- M5 целится в структурную проверку (R2), а не в поведение счётчика (R3) — осознанный выбор:
  это правило реально ловится существующим тестом, в отличие от R3.
- Однопоточность: `secureDepth` — обычный `var`, не `@Volatile`. Compose composition (включая
  `DisposableEffect`) всегда выполняется на main thread, поэтому гонки потоков здесь нет (это
  НЕ находка — упоминаю, чтобы не подумали, что я упустил проверку потокобезопасности).
