Наличие элементов и обработчиков сверено с экранным кодом, исправлены только ожидаемые строки. Исходные доказательства: `test-results/local-device-first.log`, `test-results/local-device-first-xml/`.

Единственный пропуск — служебный `SeedAuthInstrumentedTest` без аргумента токена. Обе проверки `BilingualComposeTest` действительно выполнены. Локальные Android unit-тесты: **14 PushNotificationTest + 5 BilingualSourceGuardTest = 19 passed**, XML в `test-results/local-android-unit-xml/`. ## ЮKassa, S3 и Firebase

**110 passed, 0 skipped, 0 failed** за 11,15 с: `test-results/local-integrations-verified.xml` и `.log`. Это 76 существующих проверок провайдеров/уведомлений/хранилища, 24 проверок отказов и готовности интеграций и 10 новых тестов `backend/tests/test_local_provider_contracts.py`.

- ЮKassa: настоящий HTTPX с подменой транспорта. Проверены повтор одного ключа платежа, сериализация суммы и чека, ответы 401/429/500 и таймаут без ложного успеха.
- S3: настоящий boto3 со Stubber. Проверены параметры записи, чтения, удаления, отсутствие файла и запрет доступа как разные результаты.
- FCM: настоящие классы Firebase SDK 7.5.0, подменена отправка. Проверены обычное уведомление, фоновый оффер с высоким приоритетом, удаление только недействительного токена с сохранением временно недоступного и чужого устройства.

Firebase отсутствовал в исходном локальном окружении. Зависимости установлены только в `test-results/local-integrations-deps`, без изменения requirements и рабочей `.venv`. Промежуточные 109 passed / 1 failed (`local-integrations-final.log`) вызваны неполным импортом Redis в другом контексте прав; закреплённая версия Redis установлена в ту же изолированную папку, финальные 110 прошли. Обычный запуск нового файла без Firebase также проверен: **8 passed, 2 skipped** с явной причиной (`local-integrations-no-sdk.xml`), ошибки сбора тестов нет. Эти два пропуска не выдаются за проверку Firebase; сам Firebase проверен отдельным полным профилем со SDK.
