# Taxi address tail: отдельное исправление privacy

База cb21ef5, ветка fix/friday-taxi-address-tail-privacy-20261118. По отдельному поручению родителя после завершённого offermetadata. Подтверждённый старый дефект: street_only('ул. Гагарина, 5, кв. 9') возвращает 'ул. Гагарина, 5, кв.' и выдаёт дом в destination offer push/blurred payload. Pickup отдельно режет по первой цифре, портит числовые названия улиц; fallback исходного точного адреса при пустом префиксе небезопасен.

## Узкий план до кода

1. Общий внутренний sanitizer структурированного точного хвоста, существующие street_only/pickup_street_only остаются оболочками. Не менять роли/координаты/авторизацию/order_payload.from_text/денежные поля/push metadata/маршрутизацию.
2. Нормализовать NBSP и внешние разделители. Сначала отрезать явно обозначенный точный хвост: д./дом, корп./корпус/к., стр./строение — только с ожидаемым числовым идентификатором; кв./квартира, подъезд/под., этаж/эт., домофон/код — самостоятельные компоненты, не части слов. После отсечения убрать оставшийся номер дома в безопасном префиксе.
3. Дом без маркера после запятой: цельный числовой компонент (12,12а,5к2,5/2,5-2), вместе со всем последующим хвостом. Не считать домом компонент числового названия улицы с последующим словом: 8 Марта,50 лет Октября,1905 года,9 Января,40-летия Победы. Поддержать прежний terminal дом без запятой 'Пушкина 12' через anchored house-tail, не поиск первой цифры.
4. Если осталось только точное число/маркер или пустой префикс — вернуть пустую строку, НИКОГДА не исходный точный хвост. Push уже имеет существующие 'Точка А/Б' fallback; не добавлять новые односторонние UI строки. У точного payload пассажира/назначенного водителя исходные адреса сохраняются.
5. Не угадывать универсальную грамматику свободного текста. Не обещать обезличивание любого комментария/ориентира, не расширять на courier/геокодинг. Явно описать распознаваемые формы и неоднозначные названия вроде 'улица 8', '12 микрорайон'.
