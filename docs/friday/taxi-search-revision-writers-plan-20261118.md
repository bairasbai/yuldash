# Search revision writers: план до реализации

База `3e4fec6788e08aa1261eafb4d2bb1536ecece007`. Только backend такси; схема nullable BIGINT уже опубликована. Runtime пока неизменён.

1. Общие SQL expression `COALESCE(search_revision,0)+1` и guard NULL либо `0 <= revision < 2**63-1`. Start/advance/reassign increment в том же условном UPDATE, что переход; никогда из stale ORM. Снять присвоенный scalar до commit под блокировкой, после commit продолжать только собственную revision в searching. Сохранить прежние CAS условия.
2. Route: fresh row lock и stale-source check, включающий revision; SQL bump до присваивания ORM route/price. Invalidate offered/searching и сохранить UUID token guard. Route, revision, price, reclamp(commit=False) одним commit. Продолжение проверяет owner=(revision, token), не принимает чужую работу. Created/accepted маршруты не начинают новый поиск.
3. Fallback: вычислить новые классы и цену локально, bump до ORM изменений при фактической смене criteria/price. Searching получает нового владельца и продолжение даже без снижения цены. Offered без снижения цены сохраняет существующие recipient/token/TTL и не rematch: расширение допустимых классов не меняет показанное водителю. Offered с падением цены инвалидируется и продолжает. Duplicate no-op не вращает revision. Цена и reclamp атомарны, формулы неизменны.
4. Legacy NULL: try_offer_next проверяет searching; свежая блокировка/status/NULL recheck, conditional NULL→1, commit до lookup. Только выигравший initializer продолжает свою revision. Stale NULL caller, увидевший уже non-NULL, возвращает строку без принятия чужого поколения. После commit ещё ownership check.
5. Matcher captures scalar revision вместе с прежним tuple до lookup/commit; offered и expired UPDATE сравнивают revision плюс все прежние условия. Невалидная отрицательная revision fail-closed. MAX может завершить существующий поиск, но новый increment запрещён. Route/fallback overflow409 до изменения критериев, остальные writers без lookup/effects.
6. Регрессии: все writers, stale ORM, NULL initializers, одинаковое время/round/token (исходные два ABA XFAIL превратить в PASS только после исправления), overflow, rollback, проигравший CAS без Redis/push, no-op compatibility и успешные пути. Scoped, свежая независимая приёмка, согласованный FULL, отдельная ветка.

Границы: не трогать main/production/реальные БД и приостановленные пакеты. Scheduled pricing отдельного paused пакета не переписывать, activation использует start_matching. Mixed old writers, Redis lifecycle/distributed atomicity и postcommit delayed push не решены этим счётчиком. SQLite проверки не доказывают PostgreSQL row-lock concurrency; это отдельная граница доказательств.

Независимый read-only review плана: архитектурных блокеров нет. Обязательные уточнения приняты: ownership после commit проверяется до Redis tried и _notify_reassign; assigned revision снимается DB RETURNING либо свежим SELECT под UPDATE-lock, не из identity map. Дополнительные регрессии: потеря владельца после commit у всех entry writers, два NULL caller, MAX existing matcher, отрицательная revision, route/fallback overflow без изменения критериев. Реализация и итоговая приёмка ещё впереди.
