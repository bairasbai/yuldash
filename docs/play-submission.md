## 1. Анкета Data safety — что отвечать

### Собираем ли данные? — **Да**
### Передаём ли данные третьим лицам? — **Нет**

Данные не продаются и не передаются рекламодателям. Обработчики (Google, Яндекс, Sentry)
— это не «передача третьим лицам» в терминах анкеты, а инфраструктура; их указывать
в разделе sharing не нужно.

### Шифрование при передаче? — **Да**
Приложение ходит только по HTTPS. Незашифрованный трафик запрещён на уровне системы
(`network_security_config.xml`), исключение сделано лишь для локального адреса
разработчика — в релизной сборке оно недостижимо.

### Можно ли запросить удаление данных? — **Да**
И удалить аккаунт целиком — тоже да. Есть и кнопка в приложении, и веб-страница.

### Таблица данных

| Категория | Тип | Собираем | Обязательно | Зачем |
|---|---|---|---|---|
| Personal info | Name | да | да | попутчики видят, с кем едут |
| Personal info | Phone number | да | да | вход в аккаунт и связь между участниками поездки |
| Personal info | User IDs | да | да | идентификатор Telegram при входе через бота |
| Photos and videos | Photos | да | нет | фото профиля, документы водителя и курьера, фото вручения посылки, доказательства в споре |
| Audio | Voice or sound recordings | да | нет | голосовая заявка в простом режиме и голосовые в чате |
| Location | Approximate location | да | нет | подбор поездок рядом |
| Location | Precise location | да | нет | подача машины, показ машины на карте во время поездки |
| Messages | Other in-app messages | да | нет | чат между участниками поездки и доставки |
| App activity | App interactions | да | нет | продуктовая аналитика: создание заявки, бронь, отклик |
| Device or other IDs | Device or other IDs | да | да | защита от накрутки и мошенничества (один аккаунт — одно устройство) |

**Financial info — НЕ собираем.** Расчёты идут переводом по СБП напрямую между людьми,
данные карт в приложение не вводятся и на сервер не попадают.

### По каждому типу отмечать
- **Purpose:** App functionality; для App interactions дополнительно Analytics.
- **Is this data collected, shared, or both?** — Collected.
- **Is this data processed ephemerally?** — Нет (кроме точной геопозиции: она
  ретранслируется между участниками и живёт в кэше около двух минут, в базу не пишется —
  можно отметить как ephemeral, но безопаснее оставить «нет»).
- **Users can request data deletion?** — Да.

### Особо: точная геопозиция
В коде она нарочно доступна **только во время активной поездки**: канал закрывается,
если бронь не подтверждена или уже завершена, и координаты не сохраняются в базу.
Если модератор спросит — это проверяется тестами `test_location_privacy.py`.

## 2. Разрешения, к которым Google придирается

### `ACCESS_FINE_LOCATION` + `FOREGROUND_SERVICE_LOCATION` — **нужна декларация и видео**

Google требует объяснить, зачем геолокация работает в фоне, и **приложить видео**,
где это видно в приложении.

**Формулировка для декларации:**
> Приложение показывает участникам поездки положение друг друга в реальном времени, пока
> поездка идёт. Водителю нужно видеть, где пассажир, пассажиру — где машина. Это работает
> с погашенным экраном, поэтому используется foreground-сервис с типом location. Трансляция
> начинается при подтверждении поездки и прекращается при её завершении; вне поездки
> геолокация не собирается.

**Что снять на видео:** экран поездки с машиной на карте → погасить экран → в шторке видно
уведомление «Юлдаш — поездка идёт, показываем вашу позицию попутчику» → завершить поездку →
уведомление исчезает.

### `RECORD_AUDIO` — **объяснить в описании**

Используется в двух местах: голосовая заявка в простом режиме (для пожилых, кому тяжело
набирать текст) и голосовые сообщения в чате поездки. Разрешение запрашивается в момент
нажатия на микрофон, не при запуске.

### `USE_FULL_SCREEN_INTENT` — **декларация обязательна с Android 14**

С Android 14 это разрешение не даётся автоматически: приложение должно обосновать его
в Play Console, иначе полноэкранная карточка не покажется.

**Формулировка:**
> Водитель на линии получает предложение заказа, действующее около 20 секунд. Если карточка
> не покажется поверх погашенного экрана, заказ уйдёт другому, а пассажир будет ждать дольше.
> Это тот же сценарий, что входящий звонок: короткое окно на ответ.

Приложение уже умеет попросить включить разрешение вручную, если система его не дала
(`Permissions.kt`) — но без декларации в Play это будет происходить у каждого водителя.

## 3. Content rating (анкета IARC)

| Вопрос | Ответ |
|---|---|
| Насилие, кровь, страшные сцены | нет |
| Сексуальный контент | нет |
| Ненормативная лексика | нет (в приложении включён фильтр мата в объявлениях и чате) |
| Наркотики, алкоголь, табак | нет |
| Азартные игры и симуляция ставок | нет |
| **Пользователи могут общаться друг с другом** | **да** — чат между участниками поездки |
| **Пользователи могут делиться местоположением** | **да** — во время поездки |
| Покупки внутри приложения | нет (платежи идут переводом по СБП вне приложения) |

Ожидаемый рейтинг — 12+ или Teen из-за общения и обмена местоположением. Скрывать эти
два «да» нельзя: несоответствие анкеты и функций — основание для снятия с публикации.

## 6. Чего в приложении НЕТ — и это упрощает подачу

- Нет покупок внутри приложения → не нужна анкета по биллингу.
- Нет рекламных сетей → не нужен раздел про рекламные идентификаторы.
- Нет данных банковских карт → не нужна анкета по финансовым данным.
- Нет данных о здоровье, контактов телефонной книги, календаря, SMS.
