## Живой браузер

Изолированный стенд: `test-results/remaining-local-server.py`, отдельная SQLite, четыре синтетических аккаунта. Сервер допускает только локальную сеть; SMS и платежи заменены. Никаких действий в производственных аккаунтах.

Подготовленная поездка №2: гость открывает карточку ленты → подробности → вход по локальному SMS → возврат к той же поездке → «Забронировать место» → `/trip/2`, «Ждём подтверждения». Водитель входит отдельно, видит заявку и подтверждает. Пассажир входит снова → кабинет → та же поездка со статусом «Подтверждена» → экран с кодом посадки и договорённостью об оплате. Заказ №2 создан именно кнопкой интерфейса. Поездка подготовлена как тестовые данные; публикация этой записи формой не проверялась.

Первый диагностический сценарий с поездкой №1 включал прямой запрос API после ошибки браузера, поэтому он не используется как доказательство чистого интерфейсного создания брони. Обновление подтверждения проверено повторным входом; постоянная одновременная работа двух физических устройств этим не доказана.

После перезапуска сервера с исправлением WebSocket повторены открытие `/trip/2` и уход в профиль: прежняя ошибка двойного закрытия не появилась. В журнале отдельно есть Windows `asyncio` ConnectionResetError при разрыве сокета; это не тот же дефект. Полное отсутствие сетевых ошибок не заявляется.

Такси без доступной геопозиции: реальная форма показывает отдельные поля «Откуда»/«Куда». Последовательный ввод в «Откуда» открыл обе подготовленные сохранённые точки и действие определения геопозиции. Попытки выбрать точку через инструмент управления не дали подтверждённого изменения формы; в журнале нет записи её использования. Причина этого результата не установлена: автоматически объявлять его ошибкой приложения или успешным заказом нельзя. Расчёт/создание заказа в живом браузере в этом этапе НЕ закрыты; они проверены только тестом компонентов с заменёнными API. Сохранённые точки были подготовлены в тестовой БД, настоящий геокодер не выдавал их.
