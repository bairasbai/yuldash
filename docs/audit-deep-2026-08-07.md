## ⛔ Пять запретов (нарушение = ущерб, а не стиль)

1. **Ничего не создавать на проде.** Прод — `yulbash.ru`. Отладочная сборка берёт адрес из
   `YULDASH_DEBUG_API_BASE_URL` в `android/local.properties`. Нужны данные — локальный
   бэкенд на sqlite.
2. **Не трогать `mobile/`** — старый Flutter, заброшен.
3. **Ни ключей, ни секретов в git** — включая `docs/` и примеры в отчётах.
4. **ЮKassa и юрлицо не трогать.** Денежные флаги (`parcel_fee_enabled`, `payouts_enabled`,
   `tips_money_enabled`) выключены сознательно: оферта обещает «комиссия не берётся».
   Включишь — сделаешь оферту ложной.
5. **Один файл — один агент.** `MainActivity.kt` правит один агент в один момент.
   Параллельная сессия может работать над тем же репозиторием — не лезь в её зону.

## 📐 Что считается дырой (и что не считается)

**Дыра** — то, что при обычном использовании приводит к одному из:

| Класс | Пример |
|---|---|
| 🔓 **Доступ к чужому** | открыть чужой заказ/бронь/чат/посылку по номеру (IDOR); обычный юзер попадает в админку; водитель видит телефон, который видеть не должен |
| 💸 **Деньги врут** | двойное списание, комиссия обходится, долг не начисляется, возврат дважды, баланс расходится с журналом операций |
| 🧟 **Заказ зависает** | статус, из которого нет выхода; никто не может ни отменить, ни завершить; воркер не подбирает |
| ⚡ **Гонка** | два одновременных нажатия создают два объекта; двойное назначение исполнителя; овербукинг |
| 💥 **Падение / вечная загрузка** | необработанный `null`, `!!`, деление на ноль, спиннер без выхода, нет «Повторить» |
| 🕵️ **Утечка** | телефон или точные координаты в логах, в ответе API, в Sentry |
| 🔌 **Разрыв контракта** | приложение зовёт эндпоинт, которого нет; поле обязательное на сервере и необязательное в приложении |
| 🌐 **Одноязычие** | видимая надпись только по-русски или только по-башкирски |

**Не дыра** (не тратить время): стиль кода, «можно красивее», «стоило бы отрефакторить»,
отступ на 2dp, TODO в комментарии без последствий.

## 🗺 Карта проверки — что вообще есть в приложении

Собрано по коду 2026-08-07, не по докам.

| Слой | Размер | Где |
|---|---|---|
| Приложение | ~64 000 строк Kotlin, **89 экранов** | `android/app/src/main/java/com/yuldash/app/` |
| Слой данных приложения | 5 827 строк | `data/ApiClient.kt` |
| Сервер | ~29 000 строк Python, **345 эндпоинтов**, 40 роутеров | `backend/app/routers/` |
| База | **71 таблица** | `backend/app/models.py` |
| Тесты сервера | 183 файла | `backend/tests/` |

### Три режима

| Режим | Сущность в базе | Роутер | Экраны |
|---|---|---|---|
| 🚗 **Попутка** | `Ride` + `Booking` + `RideRequest` + `RequestResponse` | `rides.py`, `requests.py`, `bookings.py` | Карта, Создать поездку/заявку, Лента заявок, Отклики, Активная поездка |
| 🚕 **Такси** | `InstantOrder` + `Tariff` + `TaxiApplication` + `TaxiWorkDay` + `PreTripCheck` | `taxi.py`, `instant.py`, `pickup.py` | Быстрый заказ, Поездка водителя, Онбординг таксиста, Чек, Предзаказы |
| 📦 **Курьер** | `ParcelDelivery` + `CourierApplication` + `CourierProfile` | `courier.py`, `parcels.py` | Посылки, Режим курьера, Онбординг курьера, Заработок, Чат по посылке |

### Роли

В базе ролей три (`UserRole`: passenger / driver / admin), но **фактических ролей больше** —
они собираются из профилей и флагов. Проверять надо все:

| Роль | Чем определяется | Что не должна мочь |
|---|---|---|
| Пассажир | по умолчанию | видеть телефоны, чужие заказы, админку |
| Водитель попутки | `DriverProfile.verified` | брать такси-заказы без `TaxiApplication` |
| Таксист | `TaxiApplication.approved` + город в `TaxiCity` | работать без `PreTripCheck`, обходить комиссию |
| Курьер | `CourierProfile` + `CourierApplication.approved` | брать заказы вне зоны, сняться после закупки |
| Админ | `UserRole.admin` (по `ADMIN_PHONES` / `ADMIN_TELEGRAM_CHAT_ID`) | — но **никто другой** не должен попадать в его эндпоинты |
| Партнёр (бизнес) | `Partner` | видеть чужие купоны/погашения |
| Рекламодатель | `Ad.owner_id` | редактировать чужое объявление |

## 📋 План: пять волн, каждая — до упора

Порядок по риску: сперва то, что ломает деньги и приватность, потом бытовое.

### Волна 1 · Разведка (read-only, параллельно)

Восемь независимых проходов, каждый со своим срезом. Ничего не чинить — только находить
и **доказывать номером строки**.

| # | Срез | Что ищем |
|---|---|---|
| 1 | Права и доступ | IDOR по всем 345 эндпоинтам, админ-гейты, утечка телефонов |
| 2 | Такси end-to-end | жизненный цикл заказа, тупики статусов, гонки назначения, комиссия |
| 3 | Курьер + посылки | лайфцикл доставки, сбор, отказ курьера, зона, вручение |
| 4 | Попутка end-to-end | публикация → бронь → отклик → поездка → оценка; овербукинг, отмены |
| 5 | Деньги | `LedgerEntry`, `CommissionDebt`, `Payment`, кошелёк, купоны, промо, рефералы |
| 6 | База данных | `models.py` + миграции: связи, индексы, `nullable`, осиротевшие ссылки, рассинхрон enum |
| 7 | Контракт клиент↔сервер | `ApiClient.kt` против роутеров: несуществующие вызовы, разъехавшиеся поля |
| 8 | Экраны | мёртвые кнопки, отсутствующие состояния (загрузка/пусто/ошибка), одноязычные строки |

### Волна 2 · Проверка находок

Каждую находку волны 1 — **перепроверить независимо**. Опыт проекта: субагенты дают
30–50% ложных тревог («уже закрыто выше по стеку», «проверка есть, но в другом файле»).
Ложную тревогу — вычеркнуть с объяснением, почему соврала.

### Волна 3 · Починка

Правим подтверждённое, по убыванию тяжести. Каждая правка:
- минимальная (не рефакторинг заодно);
- **с тестом, который бы поймал этот баг** — иначе дыра вернётся;
- зелёный прогон тестов после.

### Волна 4 · Второй заход по тем же местам

Починка порождает новые дыры. Повторный проход по изменённым файлам + по срезам, где
волна 1 нашла больше всего.

### Волна 5 · Независимый аудитор

Отдельный агент, который **не верит отчёту**. Промт — ниже.

# 🔎 Промт для независимого аудитора

> Скопировать субагенту целиком.

```
Ты — независимый аудитор кода. Твоя работа — НЕ поверить предыдущему агенту на слово.

Контекст: в приложении Юлдаш (Kotlin/Compose в android/, FastAPI+PostgreSQL в backend/)
провели глубокий аудит: искали дыры в трёх режимах (попутка, такси, курьер), во всех
ролях, в базе данных и в контракте между приложением и сервером. Отчёт агента приложен.

ПРАВИЛА
1. Ничего не чинить. Твоя работа — найти и доказать, а не исправить.
2. Ничего не создавать на боевом сервере yulbash.ru.
3. «Выглядит правильно» — не доказательство. Нужен файл:строка или вывод команды.
4. Предыдущий агент мог ошибиться в обе стороны: объявить дырой то, что закрыто выше
   по стеку, и не заметить настоящую.

ЧТО ПРОВЕРИТЬ

A. Правда ли то, что заявлено
   - Прогони тесты сам. Совпадает ли число с отчётом?
   - Возьми пять случайных утверждений из отчёта и проверь построчно.
   - Проверь КАЖДУЮ заявленную починку: правда ли дыра закрыта, или закрыт только
     тот путь, который агент видел, а второй путь к той же функции остался открыт?

B. Чего в отчёте нет
   - Роутер, режим или роль, которых отчёт не касается?
   - Эндпоинт, который приложение зовёт, а сервера для него нет? И наоборот — эндпоинт,
     который не зовёт никто (мёртвый код)?
   - Статус в жизненном цикле заказа, из которого нет выхода?

C. Дыры, которые ищут в первую очередь
   - IDOR: возьми любой эндпоинт с {id} в пути и проверь, сверяется ли владелец.
   - Деньги: можно ли обойти комиссию, списать дважды, получить возврат дважды?
   - Гонки: что будет при двух одновременных запросах? Есть ли FOR UPDATE / идемпотентность?
   - Логи: попадают ли туда телефоны и точные координаты?
   - Права: доступен ли админ-эндпоинт обычному пользователю?

D. Двуязычие
   - Видимая надпись только на одном языке — это дефект. Ищи appText с пустой
     или скопированной башкирской стороной.

ФОРМАТ ОТВЕТА
1. ПОДТВЕРЖДЕНО — что проверил и что сошлось.
2. НЕ СОШЛОСЬ — что заявлено, но на деле иначе. С доказательством.
3. ПРОПУЩЕНО — чего в работе нет вовсе.
4. НАЙДЕНО НОВОЕ — дефекты, о которых никто не знал. С шагами воспроизведения.
5. ВЕРДИКТ — можно ли выпускать. Если нет — что именно блокирует.

Отвечай по-русски, простым языком. Ничего не приукрашивай: твоя ценность в том,
что ты находишь пропущенное.
```

## 📎 Грабли проекта — не наступать снова

| Грабли | Как проявились |
|---|---|
| Зелёная сборка ≠ работающее приложение | CI собирал APK, но не открывал его. Первый живой запуск — приложение не стартовало вообще |
| Субагент объявил блокер | Три «критичных» находки оказались уже закрытыми выше по стеку. Проверяй сам |
| Мигающий тест | Тот же код, другой результат = не регресс, а нехватка памяти |
| `pkill -f "port 8100"` | Убил собственную SSH-сессию. Правильно — `fuser -k -n tcp 8100` |
| Экран проверен по-русски | На башкирском текст обрезан: башкирский длиннее |
