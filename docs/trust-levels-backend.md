# Доверие «между своими» — БЭКЕНД (Фаза 4 / D5)

> Ветка `feat/trust-levels` (от `claude/feat-base`). Статус: ✅ код + тесты + миграция готовы, ⏳ **не задеплоено**, UI следом.
> Простыми словами: Юлдаш — попутки «между своими», поэтому доверие мы сделали **явным** — у каждого есть уровень, а самые доверенные могут звать своих и открывать поездки «только для круга».

## 1. Что сделано (вывод сверху)

- **Уровни доверия L0–L3** — считаются автоматически из данных пользователя + хранимый статус «свой».
- **Инвайт-коды** — проверенный участник зовёт своего в круг доверия; активация поднимает до L3.
- **«Только для своих»** — поездку/заявку можно пометить `only_trusted`: её видят и берут только L3.
- **Реестр согласий (152-ФЗ)** — фиксируем факт и время согласия на оферту / политику / геолокацию.
- pytest: **23 новых теста, все зелёные**; общий бэкенд — **204 passed, 1 skipped** (skip = тест гонки только на Postgres).

## 2. Уровни L0–L3 — что это и как считается

Уровень **не унижает**. L0 — полноправный пользователь, просто у него ещё меньше привилегий. Чем выше доверие — тем шире доступ к «кругу своих».

| Уровень | Название | Как получить | Что даёт |
|---|---|---|---|
| **L0** | Новичок | Подтвердил номер телефона (базовый вход) | Поиск и просмотр поездок |
| **L1** | Знакомый | Заполнил **имя и фото** профиля | Больше доверия при бронировании |
| **L2** | Проверен | Прошёл **проверку документов** (та же модерация водителя, `User.verified`) | Бейдж «Проверен», **может звать своих** |
| **L3** | Свой | Активировал **инвайт** от проверенного участника | Видит поездки «только для своих», сам зовёт своих |

- Логика в одном месте: `backend/app/trust_service.py`, функция `trust_level(session, user)`.
- Уровень L0–L2 **вычисляется** из уже имеющихся данных (телефон / имя+фото / `verified`) — ничего дополнительно не храним.
- Статус «свой» (L3) **хранится** в таблице `Trust` (получен по инвайту). Итог = `max(вычисленный, дарованный)`.
- L2 засчитывается по `verified` — **переиспользуем** уже существующую ручную/OCR-модерацию водителя, отдельной проверки не заводим.

**Эндпоинт:** `GET /me/trust` → мой уровень, его название и польза (двуязычно RU/BA) + что даёт следующий уровень и как его получить. Только про себя.

## 3. Инвайт-коды — «позови своего в круг»

- Модель `InviteCode(code, owner_id, uses_left, created_at)`.
- **Кто может создать:** только **L2+** (проверенный) — иначе доверие ничего не значит.
- **Анти-абьюз:**
  - запас кодов на пользователя ограничен — `MAX_INVITES_PER_USER = 5` (круг растёт органично, не лавиной);
  - код **не бесконечный** — `uses_left` (по умолчанию 1 активация), после исчерпания не сработает;
  - **нельзя активировать свой код**;
  - **нельзя стать «своим» дважды** (уже L3 → отказ);
  - активация под блокировкой строки (`with_for_update`) — два параллельных redeem не спишут одну активацию дважды.
- **Что происходит при активации** (`POST /invites/redeem {code}`): приглашённый становится **L3 «свой»**, в `Trust.invited_by` пишется, **кто** его позвал (цепочка приглашений — видно, из чьей «ветки» человек).
- Эндпоинты: `POST /invites` (создать), `GET /invites/mine` (мои коды — **только свои**, чужие не видны), `POST /invites/redeem` (активировать).

> Отдельно от реферала «позови соседа» (`referral.py`, бонусы за поднятия). Инвайт — про **круг доверия**, реферал — про виральность/бонусы. Разные таблицы, не смешиваем.

## 4. «Только для своих» (`only_trusted`)

- Флаг на поездке (`Ride.only_trusted`) и на заявке (`RideRequest.only_trusted`).
- Такие поездки/заявки **видят и берут только L3**. Для L0–L2 и анонимов их просто нет в выдаче.
- **Где фильтруем:** `/rides`, `/rides/near`, `/requests/feed`, `/requests/near`, `/match/rides`.
- Свою поездку водитель **видит всегда** (даже если сам ещё не L3).
- **IDOR-защита:** прямой вызов `POST /requests/{id}/respond` на «только для своих» заявку от не-L3 → 403 (фильтр не обходится по прямому id).
- Реализовано аккуратно поверх кеша ленты (per-user, как фильтр заблокированных `_hide_blocked`) — **текущую ленту не ломает**.

## 5. Согласия (152-ФЗ) — реестр

- Модель `Consent(user_id, kind, granted_at)`. Виды (`kind`): `offer` (оферта), `privacy` (политика конфиденциальности), `geo` (обработка геолокации).
- `POST /me/consents {kind}` — зафиксировать согласие с **таймстампом**. Идемпотентно: **время первого согласия не перезаписываем** (это юридическое доказательство).
- `GET /me/consents` — мои согласия (только свои).

### Политика хранения данных (152-ФЗ) — простыми словами

Мы храним **минимум** и удаляем, когда данные больше не нужны. По типам:

| Данные | Зачем | Сколько храним / когда удаляем |
|---|---|---|
| Телефон, имя, фото | Вход, узнаваемость «между своими» | Пока живёт аккаунт. Удаление аккаунта → стираем полностью. |
| Документы водителя (фото прав/авто) | Разовая проверка (модерация) | Пока водитель хочет статус «проверен». Удаление аккаунта → файлы стираем. |
| Точная геолокация | Только во время активной поездки (делёжка с попутчиком/близким) | Скрыта до подтверждения поездки; после поездки точную точку не храним. |
| Согласия (`Consent`) | Доказательство законности обработки (152-ФЗ) | Пока живёт аккаунт (нужно как доказательство). Удаление аккаунта → стираем. |
| Уровень доверия, инвайты (`Trust`, `InviteCode`) | Круг «своих» | Пока живёт аккаунт. Удаление → стираем; тех, кого юзер позвал, оставляем «своими», но ссылку на него (`invited_by`) обнуляем. |
| Чат, голосовые | Общение по поездке | Чистятся ретеншеном по возрасту (`cleanup.py`) + при удалении аккаунта. |

**Процедура удаления** уже есть: `POST /me/delete` → `app/account.py::delete_user_account` стирает **все** строки пользователя во всех таблицах в FK-безопасном порядке + best-effort медиа-файлы. Эта задача **дополнила** удаление: теперь стираются и `Trust`, `InviteCode`, `Consent`, а цепочка `invited_by` у приглашённых отвязывается (чужое не удаляем, лишь убираем ссылку). Удаление **необратимо**.
