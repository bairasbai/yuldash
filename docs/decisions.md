## 2026-06-28 (рефакторинг бэкенда, Opus, worktree)
- **Монолит `app/main.py` разрезан на домены.** Было: ~1400 строк, ~50 роутов в одном файле. Стало: `app/main.py` = тонкая фабрика `create_app()` (CORS, монтаж медиа, подключение роутеров, lifespan) + `app/routers/{health,auth,rides,requests,bookings,drivers,chat,discovery,family,safety}.py` + общий `app/services.py` (push/SMS/гео/доступ-к-броне/батч-витрина против N+1/seed/ConnectionManager) + `app/schemas.py` (`RideIn`/`RideOut`). Зачем: разные домены → разные файлы → параллелить агентами (§12), легче поддержка. Поведение 1:1 — проверено pytest 11/11 + smoke + security + паритет роутов.
- **API версионируется через алиас, не перенос.** Каждый роутер подключается ДВАЖДЫ: на корень (`/rides` — как у задеплоенной беты) и под `/api/v1` (`/api/v1/rides`). Зачем: живой клиент со старыми URL не ломается, новый префикс доступен сразу. Тест `test_api_v1_alias` стережёт паритет.
- **Энтрипоинт не меняли:** `app.main:app` (systemd `yuldash-api`). Deploy переключён с трёх отдельных `scp` на `scp -r app\` (после разрезки файлов стало много — копируем папку целиком, чтобы ничего не забыть).
- **Dockerfile + docker-compose добавлены как опция** (python:3.12-slim, non-root, healthcheck; compose: api+postgres). Прод пока на systemd — это путь к контейнеризации (Фаза 2), не замена. Не ломает текущий деплой.
- **Команда `/architect`** (`.claude/commands/architect.md`) — промт senior системного архитектора под Юлдаш (как `/debug`, `/perf`): проектирует целевое → реализует минимальный безопасный шаг, не ломая живую бету.
- **Прод-харднинг ДО релиза (пользователей ещё нет → ломать нечего, ломающие правки дёшевы).** `app/middleware.py`: rate-limit на IP (общий + строгий на `/auth`+`/sos` против перебора/спама), security-заголовки, access-лог (без тел/query — токены/телефоны не текут), единый обработчик ошибок (500 без стека наружу). `/health` пингует БД. Зачем сейчас: открыть публично без анти-абуза нельзя, а до запуска это бесплатно. Лимитер in-memory (на 1-2 воркера ок; Redis — позже).
- **Logout = серверная ревокация, не просто очистка токена.** `User.tokens_valid_from`: токены с `iat` раньше этой метки отбиваются (`current_user`). `POST /auth/logout` ставит метку = «выход со всех устройств». Зачем: при потере/смене телефона старый 30-дневный токен надо гасить. `iat` дробный (не целые секунды) — иначе гонка login→logout→login в пределах секунды ложно гасит новый токен. Refresh-ротацию НЕ делаем (больший передел auth, не нужен): access 30 дней + ревокация достаточно.
- **Пагинация — опциональная и обратносовместимая.** `limit/offset` на растущих списках; `limit=None` (дефолт) = прежнее поведение (все, прежний порядок). `order_by` для брони/заявок добавляется только при пагинации — чтобы не менять порядок дефолта. Потолок 200/страница. Android (массивы) не трогаем — load-more UI отложен (YAGNI на текущем объёме).
- **Alembic ВВЕДЁН в строй (чистый baseline).** Прежние 3 миграции падали на sqlite (ALTER CONSTRAINT) и на проде не запускались → заменены одним `0001_baseline` = `SQLModel.metadata.create_all/drop_all`: работает на sqlite+postgres, всегда совпадает с моделями (нет ручного DDL для рассинхрона). Прод (таблицы уже есть): разовый `alembic stamp head`. Рантайм по-прежнему `create_all` — Alembic это верифицируемый путь миграций, а не обязательная зависимость старта.
