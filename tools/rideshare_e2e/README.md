# Локальный стенд попутки: PWA-драйвер

## Установка из чистого checkout

Нужен Node.js **22.13.0+ в ветке 22 либо 24.0.0+**: общие помощники используют
встроенный [`node:sqlite`](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)
без дополнительного флага. Зависимости устанавливаются из
`package-lock.json`, как в `webapp/` и `web/`.

Из корня репозитория:

```sh
npm --prefix tools/rideshare_e2e ci
npm --prefix tools/rideshare_e2e run install:browser
npm --prefix tools/rideshare_e2e run check
npm --prefix tools/rideshare_e2e run smoke
```

`install:browser` использует закреплённый локальный Playwright и скачивает
совместимый Chromium. На чистом Linux могут понадобиться системные библиотеки;
для их установки предусмотрена команда локального Playwright
`node tools/rideshare_e2e/node_modules/playwright/cli.js install-deps chromium`
(может потребовать права администратора).

`check` проверяет импорт драйвера из чужой рабочей папки и настройку путей.
`smoke` действительно запускает Chromium на синтетической странице без сервера:
нажатие кнопки, сохранение профиля между открытиями, разделение двух профилей
и очистка одного профиля. Вход в приложение и платёжные сценарии он не проверяет.

## Пути и изоляция

| Настройка | Поведение |
|---|---|
| Без настроек | Данные стенда находятся в `<системный temp>/yuldash-e2e/<идентификатор checkout>`; разные checkout получают разные каталоги. |
| `RSACC_SCRATCH` | Отдельный каталог синтетических данных стенда; относительный путь считается от корня checkout. Профили браузера — в его подкаталоге `pw`. |
| `PLAYWRIGHT_BROWSERS_PATH` | Стандартное переопределение каталога браузеров Playwright; значение должно совпадать при установке браузера и запуске драйвера. |
| `RSACC_CHROMIUM_PATH` | Необязательный путь к собственному Chromium; относительный путь считается от корня checkout. По умолчанию используется браузер установленного Playwright. |
| `STAND_DB` | Существующее переопределение синтетической SQLite-базы для Node-помощников. |

Для `RSACC_SCRATCH` используй отдельную папку тестового стенда. Не направляй её
на каталоги личных браузеров. При `fresh: true` очищается только выбранный
подкаталог профиля. `fresh-stand.ps1` очищает все профили именно этого стенда.
Смена рабочего каталога процесса не меняет пути по умолчанию.

PowerShell-скрипты `start-server.ps1` и `fresh-stand.ps1` получают пути из
того же `lib/paths.mjs`, что и Node-драйвер. Чтобы продолжить старый локальный
стенд, явно укажи его `RSACC_SCRATCH`/`STAND_DB`; старые каталоги автоматически
не копируются и не удаляются. Сами PowerShell-скрипты и управление Android
по-прежнему требуют соответствующего Windows/Android окружения.

PWA ожидается на `http://127.0.0.1:4173`, API стенда — на loopback-портах из
существующих скриптов. Успешный smoke подтверждает запуск драйвера и браузера,
но не заменяет полный сценарий попутки с локальным сервером и Android.

Справка Playwright: [браузеры и их пути](https://playwright.dev/docs/browsers),
[использование библиотеки](https://playwright.dev/docs/library).
