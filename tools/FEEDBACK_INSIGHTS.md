# Обезличенные отзывы: Юлдаш и Тили-тили

Необязательный инструмент для владельца проекта. Он не подключён к аккаунтам, чатам, базам и пользовательским экранам. Оба проекта используют один формат экспорта; копировать серверный код между ними не нужно.

## Без сети и моделей

Достаточно Python 3.10+. Синтетический пример — `feedback-example.json`.

```powershell
python -B tools/feedback_insights.py validate tools/feedback-example.json
python -B tools/feedback_insights.py summarize tools/feedback-example.json
python -B tools/feedback_insights.py redact export.json --output cleaned.json
python -B tools/feedback_insights.py summarize cleaned.json --labels labels.json --output summary.json
python -B -m unittest discover -s tools -p test_feedback_insights.py -v
```

Формат: `{"schemaVersion":1,"records":[{"id":"anonymous-1","project":"yuldash","text":"Обезличенный отзыв"}]}`. Второй проект — `tili`. ID уникален во всём экспорте. До 1000 записей, до 4000 символов в каждой, файл до 4 МиБ. Неизвестные/повторные поля и ID отклоняются. Выходной файл создаётся только новым: существующий и исходный экспорт не перезаписываются.

`validate` показывает количество записей и виды возможных личных данных, без цитат и найденных значений. `redact` маскирует очевидные телефоны, почту, ссылки, координаты и некоторые ключи. **Это не полное обезличивание:** имена, адреса и узнаваемые описания нужно удалить вручную. `summarize` без меток честно показывает только количества. С метками считает категории и тональность отдельно по проектам и вместе; проценты = `количество / число записей × 100`, округление до одного знака. Модель итоговые числа не считает.

Метки — JSON-массив `[{"id":"anonymous-1","project":"yuldash","category":"bug","sentiment":"negative"}]`, ровно одна на каждую исходную запись. Категории: `bug`, `usability`, `feature`, `praise`, `other`; тональность: `negative`, `neutral`, `positive`. Подмена проекта/ID, дубли, пропуски и произвольные категории отклоняются. Отчёт — JSON без цитат и текста отзывов; HTML/CSV и автоматических решений нет.

## Необязательная обработка DocETL

Установи `requirements-feedback.txt` в отдельное Python-окружение. Секреты провайдера — только в переменных окружения этого процесса; `.env` не читается. Обычные команды выше не импортируют DocETL/LiteLLM и не обращаются к сети.

Классификация разрешается только с **обоими** флагами `--send-model --privacy-reviewed`, явными `--model`, `--allowed-host` и новым `--output`. Адрес — ровно HTTPS-хост выбранного провайдера; остальные хосты, прокси и частные/локальные адреса запрещены. Не передавай неочищенные сообщения. Флаги означают отдельное явное решение оператора отправить вручную проверенный экспорт и оплатить возможную обработку; при разработке такие вызовы не делались.

Ожидание ответа — до 120 секунд (`--timeout`), затем до 10 секунд на остановку; один поток обработки. Это **не гарантия денежного лимита**: провайдер может учесть запрос, даже если процесс остановлен. Результат проверяется до отчёта. Собственный временный кэш удаляется после завершения; общий пользовательский кэш не используется. Содержимое отзывов, ответы провайдера и ошибки с его текстом не выводятся в журналы. После закрытия кэшей выделенный worker явно завершает свой процесс, чтобы фоновые потоки SDK не удерживали его. Другие процессы не затрагиваются.

В worker до импорта заданы `PYTHON_DOTENV_DISABLED=1`, `LITELLM_LOCAL_MODEL_COST_MAP=True`, отдельные `DOCETL_HOME_DIR` и каталоги кэшей. Разрешён только `from_list(...).map(...).collect(max_threads=1)`, без оптимизации, агентов, загрузки URL и запасных моделей. Проверки с подменённым ответом SDK подтверждают обработку протокола; качество реальной классификации ими не доказывается.

## Источники

- DocETL 0.3.0, MIT: [релиз](https://pypi.org/project/docetl/), [код Frame выбранного выпуска](https://github.com/ucbepic/docetl/blob/953d0b3fe89794a7c745556480490ddb52435b65/docetl/frame.py), [лицензия](https://github.com/ucbepic/docetl/blob/953d0b3fe89794a7c745556480490ddb52435b65/LICENSE). Библиотека подключается зависимостью; её исходный код не копируется в продукты.
- В зависимости DocETL есть собственное кэширование и повторы запросов, поэтому одного `bypass_cache` недостаточно для отсутствия записи; изоляция и общий срок контролируются нашим процессом.

Проверочные данные — вымышленные. Реальные отзывы Юлдаша и Тили-тили этим изменением не собирались и не обрабатывались.
